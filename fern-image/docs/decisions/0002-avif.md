# 0002. Defer native AVIF pixel coding

**M8 decision, November 2026.** Defer the AVIF decoder and encoder. Keep the existing AV1 readers available for syntax inspection. Give JPEG and WebP qualification priority. Reconsider an AVIF decode-only prototype after M5 and M7 have reproducible pixel, resource and quality baselines. The format support table should list AVIF only after a Fern codec passes the pixel tests below.

## What the first image would require

| Layer | Candidate first implementation | Work outside that profile |
|---|---|---|
| Item container | Check the file brand and the primary item in `meta`. Resolve `pitm`, `iinf/infe`, `iloc` extents and `iprp/ipma` associations. Check offsets, counts and sums before reading. Require one local AV1 item with recognized essential properties. | External references, derived items and grids, auxiliary alpha, sequences, transformations and multiple images. Reject unknown essential properties. |
| Image description | Cross-check `ispe`, `pixi` where present, `av1C` and sequence-header dimensions, subsampling and bit depth. Start with 8-bit 4:2:0 still pictures, a declared supported color matrix, range and chroma location. | HDR, ICC transforms, gain maps, monochrome, higher precision and wider chroma profiles. Reject unsupported color interpretation before allocating RGB output. |
| AV1 reconstruction | Parse frame headers and tile groups, decode symbols and coefficients, reconstruct intra prediction and inverse transforms, then apply the enabled in-loop filters. Bound tile work and every scratch plane. | Inter prediction and animation. Even one still frame can require multiple tiles and filters. A restriction on coding tools needs an explicit admission check and fixture. |
| Output | Validate every tile, convert the supported YUV interpretation, then publish an owned image. Test coded-plane equality separately from color conversion. | Region and streaming APIs need independent peak-memory measurements. |
| Encoder | A later project would need mode search, quantization, entropy coding, filtering, rate control and compatible item metadata. | Defer lossy and lossless writing until decode conformance and a rate–distortion benchmark exist. |

The MP4 AV1 sample reader exposes track samples. An AVIF primary image uses an item directory. Reuse bounded integer reads, sequence headers and OBU ranges where their contracts match. Give item references their own parser and resource budget. In particular, cap nesting, item and extent counts, cumulative input bytes, dimensions, tile counts and total decode work. Validate references and reject cycles before traversal. A per-array limit alone allows several individually legal planes to exhaust the worker.

## Measured boundary

On Linux x86-64 (AMD EPYC 9V74, FFmpeg 7.1.5), libaom encoded one generated 512 × 512 YUV420P frame. Independent libdav1d and libaom decodes returned the same 393,216 sample bytes at each setting. PSNR below pools all coded Y, U and V samples against the original. Times are median elapsed milliseconds for three fresh FFmpeg processes with one codec thread. Peak RSS is the largest Linux child high-water mark among the three runs, including FFmpeg.

| libaom CRF | File bytes | PSNR, dB | Encode ms / KiB | dav1d decode ms / KiB | libaom decode ms / KiB |
|---|---:|---:|---:|---:|---:|
| 24 | 5,395 | 51.16 | 443 / 81,280 | 68 / 35,564 | 76 / 41,432 |
| 36 | 3,761 | 44.96 | 378 / 81,280 | 72 / 35,564 | 95 / 42,556 |

The x86-64 Fern reference driver read the extracted CRF-24 stream and reported temporal delimiter, sequence header and frame OBUs with payload sizes 0, 7 and 5,094 bytes. FFmpeg handled item selection and extraction. The Fern driver inspected coded bytes through the end of the frame. Only the reference decoders produced pixels.

Reproduce from the repository root with a compiler built from this tree. Repeat each timed invocation three times. Compare equal-length decoded files, then compute PSNR as 10 × log10(255² / mean squared sample error).

```sh
ffmpeg -v error -f lavfi -i testsrc2=size=512x512:rate=1 -frames:v 1 \
  -pix_fmt yuv420p -f rawvideo -y source.yuv
for q in 24 36; do
  ffmpeg -v error -f rawvideo -pixel_format yuv420p -video_size 512x512 \
    -i source.yuv -frames:v 1 -c:v libaom-av1 -still-picture 1 \
    -threads 1 -cpu-used 6 -crf "$q" -y "frame-$q.avif"
  for d in libdav1d libaom-av1; do
    ffmpeg -v error -threads 1 -c:v "$d" -i "frame-$q.avif" \
      -frames:v 1 -pix_fmt yuv420p -f rawvideo -y "$d.yuv"
  done
  cmp libdav1d.yuv libaom-av1.yuv || exit 1
done
ffmpeg -v error -i frame-24.avif -map 0:v -c copy -f obu -y extracted.obu
"$FERN" -target x86-64-linux -o obu scripts/video-reference/av1.fern
./obu extracted.obu
```

## Cost and decision gate

The reference encode handled roughly 0.6–0.7 megapixels per second including startup. One synthetic image cannot predict fleet throughput, photographic quality or savings against JPEG and WebP. The codec memory budget must include coded and reconstructed planes, filter scratch and output at the same time. At 3840 × 2160, one 8-bit 4:2:0 surface costs 11.9 MiB and one RGB8 output costs 23.7 MiB before padding or scratch. Measure the sum on each target before exposing an API.

A planning estimate for one engineer familiar with Fern and AV1 is weeks for a bounded item parser and its negative corpus, months for a scalar intra-only decoder with cross-decoder qualification, and a separate multi-month effort for an encoder and quality tuning. SIMD, cross-target conformance and ongoing malformed-input triage add cost. Re-estimate after a single complete frame. A container-only project can deliver metadata inspection earlier, but has no image-serving return by itself.

Using libavif with dav1d or libaom could shorten time to reference-quality pixels. A production dependency would require explicit approval, a replacement for the native-core requirement, build and ABI support on each target, vulnerability monitoring and downstream license review. Keep these tools as independent development oracles. Review the specifications, codec patent grants and applicable obligations, and the exact source licenses and notices for any proposed reuse before shipping. A reference executable in a test does not settle distribution rights. [AOM licensing](https://aomedia.org/license/) · [libavif](https://github.com/AOMediaCodec/libavif) · [dav1d](https://code.videolan.org/videolan/dav1d)

Reopen implementation planning when an owner can supply a representative corpus, a target CPU and memory budget, and a traffic estimate. Require exact decoded planes against independent decoders on the admitted profile, color and rejection fixtures, truncated and oversized input tests, and measured peak allocation on native and WASI. Require independent decoding of every encoder fixture before claiming write support. Compare JPEG, WebP and AVIF at matched visual quality and latency. Multiply bytes saved per delivery by expected deliveries and bandwidth price, then subtract encode, decode, cache and maintenance costs. Proceed only if that result funds the work within the agreed service budgets.
