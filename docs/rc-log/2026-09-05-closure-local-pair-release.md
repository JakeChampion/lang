# 2026-09-05 — a closure local handed to a callee releases its env (#8545)

`ElideClosurePair` collapses a closure slot to a bare `env_ptr` when every
reader is a canonical closure call. A closure LOCAL passed to a callee has a
reader that is not, so its slot keeps the `{fn, env, drop_fn, env}` pair — and
the pass then rewrote the exit sweep's `__closure_drop_<name>` (which reads
captures at `[env+offset]`) down to the generic `__fern_closure_drop`, which
frees the pair block and nothing else. Env and captures leaked, per closure,
per call.

The pair already carries what the release needs: `{drop_fn@2, env@3}` is a
callable sub-pair, and `__drop_closure_value` already dispatches through it
(`is_unique` gate, then `__fern_closure_drop` on the pair itself) for closures
reached through a container. The downgrade now routes there instead. The thunk
is unchanged — it is reached with the env, which is what it always wanted.

`__drop_closure_value` is generated by the drop-fn worklist in `Lower`, which
runs BEFORE `OptimizeProgram`, so the rewrite would have named a function
nothing generated. The worklist is seeded from `OpMakeClosure` — a pair
existing is the condition under which the rewrite can fire — and the
per-backend dead-function cull removes it again when it does not.

## Measured

x86-64 / arm64 / wasm, rc corpus leak gates, bytes live at exit:

| case | before | after |
|---|---|---|
| `closure_local_passed_to_callee_released` | 384 / 384 / 384 | 0 / 0 / 0 |
| `string_closure_capture_aliased` | 16 / 32 / 32 | 0 / 0 / 0 |

Conformance census (x86-64): `arrow_lambda_block_body` 3 → 0. That row is why
this was picked up — #2673 added three capturing lambdas to the fixture and its
pin stayed at 0, so `main` itself was red on the census lane.

Reduced, the shape is two blocks with no library in it:

```fern
function run(f: (i32) => void, v: i32): void { f(v); }
function main(): i32 {
    var sink: i32 = 0;
    var log = (x: i32) => { sink = sink + x * 2; };
    run(log, 4);
    return sink - 8;
}
```

`a` lines with no `f`: the env box `__fern_alloc_rc1` returns, and the `i32[]`
cell the mutable capture is boxed into. The arrow spelling is not the axis —
`function (x: i32): void { … }` measures the same two.

## The 2026-09-02 blocker is gone

`2026-09-02-persistent-collections-residual-leaks.md` recorded this exact
routing being tried and reverted: it cleared every native gate and then
use-after-freed the self-host compiler in `__drop_struct_checker__Scope`, on
the overwrite of the scope `build_func_scope` returns in `check_module`. "A
closure a `Scope` field still holds was released through that path first, so
some owner of it is uncounted" — and that owner was never identified.

It was identified elsewhere since, by #8267: `769cf97` retains an uncounted
field lift handed to an `own` position, and `a3f6c9c` moves that retain to the
bind so it covers the supersede. Both landed after the revert. With them in,
`TestSelfHostStdTestE2E` passes — including `iter_test.fern`,
`option_combinators_test.fern` and `result_combinators_test.fern`, the three
programs that died before.
