# arm64ssa: unwind data

**Date:** 2026-09-16

## Why

The arm64 half of the gap #9495 closes on x86-64. Neither SSA backend emitted
a single `.cfi_*` directive, where both stack-machine emitters do. A fib built
with `-target arm64-linux -backend ssa` had no CIE and no `PT_GNU_EH_FRAME`
segment at all, so a profiler, debugger or backtrace could not walk out of a
frame. Making SSA the default would have shipped that.

## Change

The frame this emitter builds is simpler to describe than x86's, because sp
does not move for the body's lifetime: a call-crossing register goes to the
reserved call-save area rather than to a push. So the one rule the prologue's
subtraction establishes covers every instruction up to a teardown, and the
callee-saved stores below it need no rules of their own.

x30 needs one as soon as the function calls. The CIE's initial state for
aarch64 is the CFA at sp+0 with NO rule for the return address — on entry it
is in x30 and not spilled — and the first call makes that false. Its rule is
the spill slot's offset from the entry sp.

The return moved into the teardown so the frame's rule can be bracketed with
`.cfi_remember_state` and `.cfi_restore_state`. Blocks are emitted in layout
order, so more body can follow a return, and a rule describing a released
frame would describe those instructions wrongly. Both teardown sites were
already `teardown(); w("\tret")`, so the marker now stands for both. A
function with no frame changes no rule, so it gets no bracket and pays
nothing.

`internal/native/cfi` already had the arm64 profile, so nothing below the
emitter changed.

## What it costs

The self-host driver (`examples/self_host/asm_run.fern`, built
`-target arm64-linux -backend ssa`) goes from 8,885,051 to 9,147,195 bytes:
262,144 bytes, 2.95%, which is 241,680 of `.eh_frame` and 38,468 of
`.eh_frame_hdr`. Decoding the rule programs back out of the image:

| | count |
| --- | --- |
| FDEs (functions) | 4,807 |
| of those, with a frame | 4,654 |
| return sites | 16,669 |

3.5 returns per function, the same shape x86-64 has. It costs half of what
x86-64's 6.5% does for the same rules because the aarch64 code alignment
factor is 4: a span of up to 63 INSTRUCTIONS encodes as a one-byte
`DW_CFA_advance_loc`, where on x86-64 the same factor is 1 and a span past 63
bytes needs `advance_loc1` or `advance_loc2`.

The structural fix is the stack-machine emitter's shape — route every return
through one epilogue per function, turning 16,669 teardowns into 4,807. That
pays back most of the `.eh_frame` and some `.text` too. It is a codegen
change on both backends, so it is its own slice.

## Tests

- `TestEveryFunctionCarriesBalancedCFI`: a function with two returns, so the
  layout puts a block after a teardown. Start and end proc balance, remember
  and restore balance, and the CFA offset returns to the CIE's initial 0 once
  per teardown.
- `TestPrologueCFIDescribesTheFrame`: the prologue's rules appear in the order
  the frame is built, and x30's rule names the slot it actually went to —
  computed from the frame size and the store's own displacement, so a rule
  that merely looks plausible fails.
- `TestFramelessFunctionCarriesNoFrameRules`: a function that neither spills
  nor calls carries an FDE and nothing else, which is what keeps the 153
  frameless functions in the driver free.
- By hand: a `-target arm64-linux -backend ssa` fib exits 34 under qemu and
  its image carries a CIE at 0x1a8 whose header is `01 7a 52 00 04 78 1e 01` —
  version 1, `zR`, code align 4, data align -8, return-address column 30, the
  aarch64 profile — with a `PT_GNU_EH_FRAME` search table of 2 rows. The same
  build before this change had neither.
