# Networking and HTTP research, 2026-09

Status: research survey (2026-09-20). Tracking issue: the networking plan issue
this document was written for (linked from the PR that adds it). Nothing here
is a build item; the plan in the issue is. This document records what the
field looks like, with sources, so the plan's choices can be checked against
evidence rather than recollection.

Method. Seven research passes ran in parallel, each over web search plus
fetches of primary sources, with a separate fact-check pass re-fetching the key
sources of three of them, and a five-lens adversarial review of the plan that
cites this document (repository fit, performance realism, ergonomics, factual
accuracy, completeness), whose confirmed findings were folded into the plan. The egress proxy blocked a number of primary hosts
(techempower.com, go.dev, docs.rs, ziglang.org, rustls.dev, RFC mirrors and
others); each section says which claims rest on a search snippet or memory
rather than a fetched page, and those are marked `[snippet]`, `[unverified]`
or `(unverified)` inline. Treat marked numbers as leads, not facts. Line counts
of TLS and QUIC implementations were taken from fresh clones on 2026-09-13 to
18, tests excluded.

The baseline measurement of Fern's own server (`hello.fern`, x86-64, 4-core
container, Go load generator opening one connection per request) is in the
tracking issue; it is repeated here because a research doc without a starting

## Reading the matrix for Fern

Three facts fall out.

1. **No mainstream stack ships deterministic simulation.** The column is empty
   for everything people deploy; the ones that have it (TigerBeetle, Eio's
   mock, Lean's mock transport) got it by making the I/O layer a value. Fern's
   `Platform` is that value already, and `internal/caps` plus E066 can forbid
   the side channels madsim had to patch back in at libc level.
2. **The performance leaders are all one shape.** Reactor per core, owned
   buffers, zero-copy parse (the HttpArena table below). Fern's share-nothing
   worker direction and Perceus ownership are that shape; nothing in the
   language has to change to reach it, only the stdlib and the reactor.
3. **Nobody has TLS both native and complete except Go and rustls.** Zig's
   client-only attempt is the cautionary tale. TLS is the largest single item
   in the plan and the one the plan defers behind a proxy-first stance.

The per-topic reports follow, lightly edited and with their source caveats
intact.

### 2. Techniques the leaders use

- **Prefork + SO_REUSEPORT [verified in source].** libreactor forks one child per CPU, pins it, enables `REUSEPORT_CBPF` and sequences forks with an eventfd so the CBPF index is deterministic ([libreactor.c](https://github.com/TechEmpower/FrameworkBenchmarks/blob/master/frameworks/C/libreactor/src/libreactor.c)). zeemo/zix/tokio-uring/Bun all do the same per-core split ([frameworks.json](https://raw.githubusercontent.com/MDA2AV/HttpArena/main/site/data/frameworks.json)). This model maps directly onto a single-threaded-per-process runtime.
- **Pipelined response batching [verified].** may_minihttp loops `request::decode` over a 32 KB request buffer, appends each response to a 32 KB `rsp_buf`, then one `write_all` ([http_server.rs](https://raw.githubusercontent.com/Xudong-Huang/may_minihttp/master/src/http_server.rs)); it also pipelines PostgreSQL queries and uses mimalloc ([TFB main.rs](https://github.com/TechEmpower/FrameworkBenchmarks/blob/master/frameworks/Rust/may-minihttp/src/main.rs)). ntex pre-serialises `Server: N` and content-type header values as static `HeaderValue`s and writes into a thread-local `BytesMut` ([utils.rs](https://raw.githubusercontent.com/TechEmpower/FrameworkBenchmarks/master/frameworks/Rust/ntex/src/utils.rs)); ntex ships `neon(io-uring)` variants ([benchmark_config](https://raw.githubusercontent.com/TechEmpower/FrameworkBenchmarks/master/frameworks/Rust/ntex/benchmark_config.json)), xitca a `compio` variant. Date-header caching is universal folklore but I did not find it in any fetched source; treat as unverified.
- **io_uring vs epoll, 2022–2026 numbers.** Streaming (one connection, IO depth 1) on kernel 6.0.7: epoll 1,565K vs io_uring 506K QPS at 64 B, 224K vs 183K at 16 KB, i.e. io_uring 2–3x slower; io_uring wins ping-pong ([liburing #536, verified](https://github.com/axboe/liburing/issues/536)). uWebSockets' maintainer measured <10%, often <5%, gain on 5.19+ and rated an io_uring backend "very, very low priority" (May 2023, [verified](https://github.com/uNetworking/uWebSockets/issues/1603)); uWS (hence Bun) still runs epoll/kqueue. Monoio's own doc (Xeon Gold 5118, 10 GbE, kernel 5.15): roughly equal to tokio at 1 core, ~2x at 4, ~3x at 16, with higher latency than tokio at 1 core/few connections; the gain is thread-per-core scaling, not the syscall API ([verified](https://github.com/monoio-rs/monoio/blob/master/docs/en/benchmark.md)). A VLDB 2026 paper (Jasny et al., arXiv 2512.04859) reports a naive epoll→io_uring swap gives 1.06–1.10x, engineered use (registered buffers, batching, zero-copy) up to 2.3x, zero-copy receive 2.5x [snippet]. Rust io_uring runtimes at 4 threads in 2026: tokio-uring 1.39M, monoio 1.36M, compio 1.27M, glommio 1.14M rps [snippet]. tokio-uring still calls itself "very young", kernel 5.11+ ([verified](https://raw.githubusercontent.com/tokio-rs/tokio-uring/master/README.md)).
- **Runtime adoption.** libuv uses io_uring for fs ops since 1.45 (2023-05) and "always use io_uring for epoll batching" since 1.50 (2025-01); SQPOLL off by default since 1.49; sockets stay epoll ([ChangeLog, verified](https://raw.githubusercontent.com/libuv/libuv/v1.x/ChangeLog)). Node keeps it opt-in on security grounds ([#52156, closed not-planned](https://github.com/nodejs/node/issues/52156)). .NET: Ben Adams' io_uring socket engine PR (2026-02-13, closed WIP): one ring per physical core, `SO_INCOMING_CPU` migration, SO_REUSEPORT shadow listeners, multishot accept/recv, provided buffer rings, `SEND_ZC`, kernel 6.1+, ~7 MB per engine, ~14.5K lines; no measurements in the PR ([verified](https://github.com/dotnet/runtime/pull/124374)); Phoronix quoted an expected 15–40% per-request CPU cut for plaintext [snippet].
- **Parsers.** picohttpparser is stateless and never allocates ([verified](https://github.com/h2o/picohttpparser)); httparse is push-based, no-alloc, no-copy ([verified](https://github.com/seanmonstar/httparse)) with SSE4.2/AVX2 runtime detection and ~1.6x slower than pico [snippet]; hparse (Zig `@Vector` SIMD + SWAR) claims 12.5% less wall time and 77% fewer instructions than pico in its own bench ([verified README](https://github.com/nikneym/hparse)).
- TCP_NODELAY/TCP_CORK(NOPUSH)/sendfile: standard nginx guidance is `sendfile on; tcp_nopush on; tcp_nodelay on` so full segments are sent and the tail is flushed without Nagle delay [snippet]. Not a differentiator among the leaders above.

### 3. Memory per idle connection

- **Go net/http [verified source]:** per connection a default `bufio.Reader` (4 KB) plus a 4 KB `bufio.Writer`, both `sync.Pool`-recycled ([server.go](https://raw.githubusercontent.com/golang/go/master/src/net/http/server.go)); goroutine `stackMin = 2048`, initial size adaptive to the observed average since 1.19 ([stack.go](https://raw.githubusercontent.com/golang/go/master/src/runtime/stack.go)). Order of 10–16 KB per live connection plus kernel socket buffers.
- **Rust hyper (HTTP/1):** 8 KB `INIT_BUFFER_SIZE` plus ~8 KB unbounded dispatch channel (32 blocks × ~250 B) ≈ 16 KB; issue still open, blocked on tokio ([#4057, verified](https://github.com/hyperium/hyper/issues/4057)). At 1M idle tasks tokio uses the least memory; Go ~12x the winner [snippet, pkolaczk].
- **Node:** ~10 KB heap per connection at 50K connections, halved by pointer compression [snippet, Platformatic].
- **nginx:** ~2.5 MB per 10,000 idle keep-alive connections (≈256 B) per the author's claim; 50K WebSocket connections under 1 GB [snippet].
- **Erlang/Bandit:** OTP issue opened 2026-09-04: 256–512 KiB `drv_binary` per idle HTTP/1.1 connection with Bandit 1.12.5 on OTP 28.5.0.5 (active-once, 9,216-byte buffer), ~7,000 connections per pod; unanswered ([verified](https://github.com/erlang/otp/issues/11585)). Bandit's own claim: up to 4x Cowboy throughput with as-good-or-better memory [snippet].
- **HttpArena incremental RSS at 32K held (not idle) connections, computed from the table:** Bun ~10 KiB, Bandit ~13 KiB, ntex ~20 KiB, fiber ~21 KiB, actix ~27 KiB, Kestrel ~36 KiB, axum ~39 KiB, ASP.NET minimal ~41 KiB. Includes allocator slack and per-process overhead across 64 workers; JVM/Node totals reflect heap sizing and are not per-connection.
- **Zig/h2o:** no published per-connection figures found. http.zig uses a fixed per-connection buffer plus a per-worker large-buffer pool ([verified](https://github.com/karlseguin/http.zig)); zeemo/zix/h2o total RSS at 4,096 connections is 70–195 MiB across 64 workers.

### 4. Zig std.http, Bun, Deno

- **Zig.** PR #25592 (merged 2025-10-29) introduced `std.Io`: `Io.Threaded` (production; has networking) and `Io.Evented` (io_uring/kqueue; experimental); `std.net` deleted in favour of `std.Io.net` ([verified](https://github.com/ziglang/zig/pull/25592)). 0.15.1 (Aug 2025) had already rewritten Reader/Writer and made `http.Server` operate on streams only [snippet, release notes]. 0.16.0 shipped April 2026 [snippet]. In current master `Evented` resolves to `IoUring.zig` on Linux x86_64/aarch64, `Kqueue.zig` on BSD/Darwin, `void` elsewhere ("context-switching code not implemented yet") ([Io.zig, verified](https://raw.githubusercontent.com/ziglang/zig/master/lib/std/Io.zig)); an open issue says Evented has no networking, so only Threaded can serve HTTP [snippet, codeberg #31723]. Third-party `zio` implements `std.Io` with stackful coroutines over io_uring (epoll fallback)/kqueue/IOCP and runs `std.http.Server` unchanged ([verified](https://github.com/lalinsky/zio)); reported 377.8K echo rps with 4 executors [snippet]. http.zig's author calls `std.http.Server` "very slow" and gets 140K rps on an M2 ([verified](https://github.com/karlseguin/http.zig)); Zap (facil.io wrapper) was archived 2026-09-06 ([verified](https://github.com/zigzap/zap)).
- **Bun.** `Bun.serve` runs on a uWebSockets fork, epoll/kqueue, one process per core sharing the port. v1.4.1 (2026-09-04) added experimental HTTP/2 to `Bun.serve` via ALPN (no WebSocket-over-h2, no push, no trailers) and the docs also expose an experimental `http3: true` (same port, TCP+UDP, `Alt-Svc`) ([docs, verified](https://raw.githubusercontent.com/oven-sh/bun/main/docs/runtime/http/server.mdx)). Bun's tweet for `node:http2`: 128,879 vs Node 52,785 rps [snippet]. HttpArena: 1.93M h1, 7.4M h2c.
- **Deno.** `Deno.serve` is hyper-based; Deno's own bench: Deno 2.9 85,600 vs Node v26 56,300 rps, p99 1.60 vs 3.10 ms, 100 connections, EPYC [snippet, deno.com/benchmarks]; 2.9.0 released 2026-06-25, startup 22→15 ms ([verified](https://github.com/denoland/deno/releases/tag/v2.9.0)). HttpArena: 1.68M h1, 2.55M pipelined (no batching).

### 5. HTTP/2 and HTTP/3

- **H2 vs H1 cost.** Per connection, H2 multiplexing raises server rps when the client keeps many streams open: h2o 16.1M rps at 256 h2 connections vs 3.64M h1; hyper 6.97M vs 3.00M; Kestrel h2c at 1,024 connections used 4.2 GiB vs ~0.4 GiB for h1 (HttpArena, verified). An old nghttp2 report of 40→50% CPU and 800 MB→2.5 GB RAM after enabling H2 was closed stale ([#1035, verified](https://github.com/nghttp2/nghttp2/issues/1035)). H2 is a framing/HPACK layer; the state-per-stream is the memory cost.
- **H3/QUIC libraries.** nginx h3 (quictls) reached 4.85M rps at 64 connections but static-h3 fell to 361K vs 802K static-h2 (HttpArena, verified). msquic dashboard: 6.61/7.13 Gbps single-connection up/down, 1,037K RPS, 10.48K handshakes/s [snippet]. Studies: quiche >2x quinn in several interop tests [snippet, ETH 2024]; msquic ≥50% ahead of quinn under loss/reordering [snippet, arXiv 2504.10054]; a KIT 2025 sustained-throughput paper puts quinn at up to 8.22 Gbit/s vs msquic 5.81 and notes HTTP/3 framing costs up to 27% goodput vs HTTP/0.9 [snippet, attributions conflict between sources]. quiche runs Cloudflare's edge, Android DoH3 and curl; tokio-quiche is in-tree ([verified](https://github.com/cloudflare/quiche)).
- **Stdlib or library?** Evidence favours library: Go's QUIC proposal (Feb 2023) is accepted but `x/net/quic` v0.59.0 (2026-09-08) is still "not ready for production", lacking 0-RTT, migration and PMTUD, with no HTTP/3 anywhere in std or x/net ([verified](https://pkg.go.dev/golang.org/x/net/quic), [#58547](https://github.com/golang/go/issues/58547)); Kestrel links native MsQuic and silently disables H3 when it is absent ([verified](https://github.com/dotnet/AspNetCore.Docs/blob/main/aspnetcore/fundamentals/servers/kestrel/http3.md)); Rust keeps `h3` generic over quinn/s2n-quic/msquic and has no HTTP in std; Zig std is HTTP/1.1 only; nginx uses quictls; only h2o writes its own (quicly) and still labels H3 experimental ([verified](https://github.com/h2o/h2o)). A QUIC stack is TLS 1.3 integration + loss recovery + congestion control + flow control + QPACK; even the sockets-only io_uring engine for .NET was 14.5K lines. For Fern: HTTP/1.1 (and probably H2 framing) in std with a per-core SO_REUSEPORT prefork model that already matches single-threaded-per-process; epoll/kqueue baseline with io_uring as an opt-in backend; HTTP/3 as a binding to msquic or quiche, not std.


## Report 2: Client and server API ergonomics

Method: web search (200-call budget, exhausted) plus fetches of GitHub-hosted sources. Several primary doc hosts (go.dev, docs.rs, hexdocs, ktor.io, hono.dev, bun.com, python-httpx.org, openjdk.org, curl.se, readthedocs) are blocked by the egress proxy; where a claim rests on memory or a secondary source I say so.

### 1. Server-side handler APIs

**Go net/http 1.22+.** Patterns are `"METHOD /path/{name}/{rest...}"`; `{$}` matches only the exact end; a wildcard's value is read with `r.PathValue("name")`; the most specific pattern wins and an unmatched method yields 405 automatically ([go.dev/blog/routing-enhancements](https://go.dev/blog/routing-enhancements) via [dev.to summary](https://dev.to/gabrielanhaia/go-122-servemux-method-and-wildcard-routing-without-a-framework-1f0l); go.dev itself was blocked). Handler remains `func(w http.ResponseWriter, r *http.Request)`; streaming is "write then `Flush`"; `Server.Shutdown(ctx)` closes listeners, closes idle conns, waits for active ones until `ctx` expires; `Server.BaseContext` seeds per-request contexts; `r.Context()` is cancelled on client disconnect ([golang/go#52805](https://github.com/golang/go/issues/52805), [victoriametrics guide](https://victoriametrics.com/blog/go-graceful-shutdown/)). What others copy: method-in-pattern, `{$}`, 405 for free, and the request-scoped `Context` as the cancellation carrier.

**Rust axum (0.8.x, 0.8.0 was the `{param}` syntax change).** Handlers are plain async fns whose parameters are *extractors* (`Path<(u32,)>`, `Query<T>`, `State<S>`, `Json<T>`); `State<S>` is checked at `Router::with_state` time; middleware is `tower::Layer`/`Service`, so timeout, trace, compression come "for free"; `axum::serve(...).with_graceful_shutdown(fut)`; `Body` implements `Stream` and `FromRequest`; SSE via `axum::response::sse`, WebSocket over HTTP/1 and HTTP/2 ([CHANGELOG](https://github.com/tokio-rs/axum/blob/main/axum/CHANGELOG.md), [README](https://github.com/tokio-rs/axum)). Note 0.8 dropped `#[async_trait]` on `FromRequestParts` (native async traits). The extractor-as-parameter shape is the most-copied idea in this survey (Hummingbird, Vapor 5 macros, Bun's `BunRequest<"/orgs/:orgId">` all move toward "the route string types the handler").

**Elixir Plug/Phoenix + Bandit.** Handler is `conn -> conn`; a "plug" is `init/1` + `call/2`, composed in a pipeline; `halt/1` stops the chain. Bandit (pure Elixir, HTTP/1.1 + HTTP/2 + WebSock) is Phoenix's default server since 1.7.11; Bandit 1.12.5 is dated 20 Aug 2026 ([bandit CHANGELOG](https://github.com/mtrudel/bandit/blob/main/CHANGELOG.md), [repo](https://github.com/mtrudel/bandit)). Graceful shutdown drains via the Plug/Thousand Island drainer (stop accepting, wait for in-flight) ([felt.com writeup](https://felt.com/blog/startup-and-shutdown-for-phoenix-applications)). Per-request cancellation is "the process dies", which is the BEAM's structural answer.

**Gleam wisp + mist.** Handler `fn(Request) -> Response`; middleware is any function taking a continuation, applied with `use <- wisp.log_request(req)`; routing is `case wisp.path_segments(req) { ["users", id] -> ... }` ([wisp README](https://github.com/gleam-wisp/wisp), [tutorial](https://blog.andreyfadeev.com/p/gleam-web-application-development-tutorial)). Gets right: middleware is *just a function with a callback argument*, and the language's `use` sugar makes it read linearly — no framework middleware type at all. Streaming/WebSocket live in mist, not wisp (not verified in detail).

**Roc basic-webserver (0.14.0-rc1).** The app provides three functions and no `main`:
```
init!     : () => Try({ config : Server.Config, context : Context }, [Exit(I64), ..])
respond!  : Server.Request, Context => Try(Server.Outcome, [ServerErr(Str), ..])
shutdown! : Server.ShutdownReason, Context => Try({}, [Exit(I64), ..])
```
Effects (Stdout, outbound Http, Sqlite, Cmd, TCP) are platform-provided modules called with `!`-suffixed effectful functions; the older `Task` API is gone ([README](https://github.com/roc-lang/basic-webserver/blob/main/README.md)). Hosting is Rust hyper/tokio. This is the closest existing analogue to Fern's "Platform bag handed to the handler": the platform owns the loop and lifecycle, the app is three typed functions.

**MoonBit.** Official `moonbitlang/async` ships `moonbitlang/async/http` (client + server, HTTPS, CONNECT proxy) with structured concurrency: every task is spawned inside `with_task_group`, failure cancels siblings, everything is cancellable by default, cancellation propagates like an error but is not `catch`-able, with `protect_from_cancel` for critical sections ([README](https://github.com/moonbitlang/async/blob/main/README.md)). JS backend got a fetch-based client in v0.8.3 (Mar 2026) ([release notes](https://www.moonbitlang.com/updates/2026/03/10/index)). A "file server" pearl exists ([moonbitlang.com](https://www.moonbitlang.com/pearls/2025/10/22/moonbit-http-server)). Server-side router ergonomics: could not verify beyond the README.

**Zig.** `http.zig` (httpz) is the de-facto base (Jetzig and Tokamak sit on it; zap wraps an unmaintained C lib): `httpz.Server(Handler).init(io, allocator, .{...}, handler)`, `router.get("/api/user/:id", getUser, .{})`, handler `fn(req: *httpz.Request, res: *httpz.Response) !void`, `req.param("id")`, `res.writer()` returns a `std.Io.Writer` for streaming, `server.stop()` finishes live requests, WebSocket via `httpz.upgradeWebsocket()`, 1 worker + 32-thread pool by default ([http.zig README](https://github.com/karlseguin/http.zig/blob/master/readme.md), [landscape overview](https://x.com/CodeToTheMoons/status/1879947592727163277)). Note the `init(init.io, …)` signature: Zig 0.16's `std.Io` (an explicit, passed-in I/O capability) has reached third-party servers — directly relevant to a Platform-bag design.

**Swift.** Hummingbird 2: `Router<Context>` is generic over a `RequestContext` protocol; handlers are `(Request, Context) async throws -> ResponseGenerator`; middleware is typed over the context so a library middleware can require `Context: AuthRequestContext` ([swiftonserver on contexts](https://swiftonserver.com/using-hummingbird-request-context/), [what's new in HB2](https://swiftonserver.com/whats-new-in-hummingbird-2/)). Vapor 5 (beta, 2026 per [vapor blog search hit](https://blog.vapor.codes/posts/vapor-5-beta/); the GitHub releases page fetch reported "Beta 2, 16 Sept" with an implausible 2024 year — treat the exact date as unverified) is a rewrite on the new Swift HTTP Server derived from Hummingbird's: fully structured-concurrency, bodies stream by default (`try await req.content.decode`), and experimental `@GET("users", UUID.self)` macros that type-check the handler parameter against the route ([releases](https://github.com/vapor/vapor/releases)).

**Kotlin Ktor 3.4–3.6.** `routing { get("/users/{id}") { call.parameters["id"] } }`, plugins `install(...)` globally or per-route; 3.4.0 (Jan 2026) added `HttpRequestLifecycle` with `cancelCallOnClose = true`: client disconnect cancels the handler coroutine and, by structured concurrency, everything it `launch`ed (Netty/CIO only) ([JetBrains blog](https://blog.jetbrains.com/kotlin/2026/01/ktor-3-4-0-is-now-available/), [3.6.0](https://blog.jetbrains.com/ktor/2026/09/18/ktor-3-6-0-is-now-available/)).

**JS runtimes.** Bun.serve `routes: { "/users/:id": { GET: (req: BunRequest<"/users/:id">) => Response } }` — params typed from the route literal, static `Response` values allowed as routes, `fetch` as fallback ([Bun routing docs](https://bun.com/docs/runtime/http/routing)). `Deno.serve((req, info) => Response, { signal, onListen })`; `info.remoteAddr`, `info.completed`; the server is stopped by an `AbortSignal` and awaited via the returned promise ([Deno docs](https://docs.deno.com/api/deno/~/Deno.serve)). Cloudflare Workers: `export default { async fetch(req, env, ctx) }` — `env` is the capability bag (KV, D1, R2, secrets), `ctx.waitUntil(p)` extends the lifetime past the response, allSettled semantics across calls ([Context docs](https://developers.cloudflare.com/workers/runtime-apis/context/), [Bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/)). Hono: `c.req.param('id')`, `c.set/c.var` with `createMiddleware<{ Variables: {...} }>()` giving typed downstream access, `c.executionCtx`, `streamSSE` ([middleware guide](https://hono.dev/docs/guides/middleware), [discussion #3257](https://github.com/orgs/honojs/discussions/3257)). WinterTC Minimum Common API (ECMA-429, first edition adopted Dec 2025) mandates on `globalThis`: `fetch`, `Request`, `Response`, `Headers`, `AbortController/Signal`, `ReadableStream/WritableStream/TransformStream`, `TextEncoder/Decoder`, `URL`, `URLPattern`, `crypto.subtle`, `structuredClone`, `queueMicrotask`; WebSocket is not in the list ([spec source](https://github.com/WinterTC55/proposal-minimum-common-api/blob/main/index.bs)).

**What gets copied (server).** (a) `(Request) -> Response` as the whole handler contract, with the platform owning the loop (Roc, Wisp, Workers, Deno, Bun). (b) Route string typed into the handler (axum extractors, Bun `BunRequest<...>`, Vapor macros). (c) A typed, extensible per-request context distinct from Request (Hummingbird `RequestContext`, Hono `Variables`, Workers `env`). (d) Middleware as a plain function taking the next handler (Wisp `use`, Hono `next`, Plug). (e) Disconnect = cancellation of the handler's whole subtree (Go `r.Context()`, Ktor 3.4, BEAM process exit). (f) Shutdown = stop accept, drain in-flight with a deadline (Go `Shutdown(ctx)`, Deno `signal`, httpz `stop()`).

Sources: [reqwest ClientBuilder](https://docs.rs/reqwest/latest/reqwest/struct.ClientBuilder.html) and [error.rs](https://github.com/seanmonstar/reqwest/blob/master/src/error.rs); [ureq error.rs](https://github.com/algesten/ureq/blob/main/src/error.rs), [ureq Config](https://docs.rs/ureq/latest/ureq/config/struct.Config.html); [Go transport.go](https://go.dev/src/net/http/transport.go), [bytesizego on DefaultClient](https://www.bytesizego.com/blog/the-default-go-http-client-will-hang-forever-here); [httpx timeouts](https://www.python-httpx.org/advanced/timeouts/), [httpx exceptions](https://www.python-httpx.org/exceptions/); [undici Client.md](https://github.com/nodejs/undici/blob/main/docs/docs/api/Client.md), [Dispatcher.md](https://github.com/nodejs/undici/blob/main/docs/docs/api/Dispatcher.md); [JDK HttpClient](https://docs.oracle.com/en/java/javase/21/docs/api/java.net.http/java/net/http/HttpClient.html); [Bun fetch](https://bun.com/docs/runtime/networking/fetch), [bun#16682](https://github.com/oven-sh/bun/issues/16682).

Other notes. undici's design is the cleanest separation: `Dispatcher` is the interface (Client, Pool, Agent, Proxy, Mock all implement it), `fetch` is a thin layer on it, and cross-cutting behaviour is `dispatcher.compose(retry(), redirect(), decompress(), cache(), dns(), deduplicate())` ([Interceptors](https://undici.nodejs.org/api/Interceptors)). libcurl: the connection pool lives on the *multi* handle so easy handles can be created/destroyed freely; idle connections older than 118 s are not reused (`CURLOPT_MAXAGE_CONN`); the multi interface exposes one timeout for all transfers ([multi overview](https://curl.se/libcurl/c/libcurl-multi.html), [connection reuse](https://everything.curl.dev/transfers/conn/reuse.html)); connect-timeout default 300 s and total timeout default infinite are from memory, not fetched. Swift AsyncHTTPClient: `HTTPClient.shared.execute(req, timeout: .seconds(30))`, deadline-based, pool with `getConnectionFromPoolTimeout` error ([swiftonserver](https://swiftonserver.com/async-http-client-by-example/)). Zig `std.http.Client` moved to buffer-supplied `std.Io.Writer` in 0.15 and takes explicit `allocator` + `Io` fields in 0.16; `fetch` had blocking bugs with large HTTPS bodies in 0.15 ([zig#25015](https://github.com/ziglang/zig/issues/25015), [#24967](https://github.com/ziglang/zig/issues/24967)). OCaml cohttp-eio 6.x is a multicore HTTP/1.1 client+server on Eio ([opam](https://ocaml.org/p/cohttp-eio/6.0.0)). Deno's `Deno.createHttpClient` (proxy, pool sizing) and its HTTP/2 default could not be fetched; MoonBit's `reqbest` claims native HTTP/1.1 with experimental H2/H3 ([repo](https://github.com/oboard/reqbest)).

Takeaways: nobody agrees on a default deadline (none / 5 s / 5 min); the libraries that were later regretted are the ones with *no* default (Go, reqwest total). Per-phase timeouts (ureq's `Timeout` enum, httpx's four-tuple, undici's headers/body split) are the mature shape; a single total deadline plus a per-phase "inactivity" timeout covers most needs. Redirect-following and status-as-error are the two defaults libraries flip most often (httpx and Java say no; ureq says yes to both).

### 3. Structured concurrency and cancellation

- **Trio**: `with trio.move_on_after(2): async with trio.open_nursery() as n: n.start_soon(fetch, a); n.start_soon(fetch, b)` — the cancel scope must enclose the nursery for children to be covered; level-triggered cancellation; Happy Eyeballs is the canonical demo (a nursery as the join point) ([trio reference](https://trio.readthedocs.io/en/stable/reference-core.html), [Happy Eyeballs thread](https://trio.discourse.group/t/happy-eyeballs-structured-concurrencys-hello-world/57)). API shape from memory; docs host blocked.
- **Kotlin**: `withTimeout(2.seconds) { val a = async { fetchA() }; val b = async { fetchB() }; a.await() to b.await() }`; a failing child cancels the scope; `select { a.onAwait…; onTimeout(…) }` for first-wins ([kotlinlang cancellation](https://kotlinlang.org/docs/cancellation-and-timeouts.html)). Ktor 3.4 ties request lifetime to this scope.
- **Swift**: `withThrowingTaskGroup` + `group.next()`; throwing from the body cancels remaining children and awaits them; timeout is user-written as a racing `Task.sleep` child ([hackingwithswift](https://www.hackingwithswift.com/quick-start/concurrency/how-to-cancel-a-task-group), [donnywals](https://www.donnywals.com/implementing-task-timeout-with-swift-concurrency/)).
- **Java**: JEP 505 (JDK 25) → JEP 525 (JDK 26, sixth preview): `try (var scope = StructuredTaskScope.open(Joiner.anySuccessfulOrThrow(), cf -> cf.withTimeout(Duration.ofSeconds(2)))) { scope.fork(...); scope.fork(...); return scope.join(); }`; JDK 26 renamed `anySuccessfulResultOrThrow`→`anySuccessfulOrThrow`, added `Joiner.onTimeout`, `allSuccessfulOrThrow` returns a list; finalisation expected JDK 27 ([JEP 525](https://openjdk.org/jeps/525), [JEP 505](https://openjdk.org/jeps/505)).
- **Go**: `ctx, cancel := context.WithTimeout(ctx, 2*time.Second); defer cancel()` + `errgroup`; cancellation is a value threaded by convention, not a scope.
- **OCaml Eio**: `Switch.run (fun sw -> …)`; `Fiber.both`, `Fiber.pair`, `Fiber.first` (returns first, cancels other — note both may already have completed under io_uring); exceptions cancel siblings; `Cancel.protect`; capabilities (`~net ~clock`) are passed as arguments, and `Eio_mock` supplies fakes ([eio README](https://github.com/ocaml-multicore/eio/blob/main/README.md), [discuss thread](https://discuss.ocaml.org/t/understanding-cancellation-in-eio/9369)).
- **MoonBit**: `with_task_group`, cancellation-by-default, `protect_from_cancel` ([README](https://github.com/moonbitlang/async/blob/main/README.md)).
- **Rust's problem**: cancellation is `drop`; `tokio::select!` drops losing futures, so any future owning partial state (a half-read frame) loses it; "cancel-safe" is a per-API doc promise, and tests with large in-memory duplex buffers never exercise it ([tokio select docs](https://docs.rs/tokio/latest/tokio/macro.select.html), [Oxide RFD 400](https://rfd.shared.oxide.computer/rfd/0400), [sunshowers](https://sunshowers.io/posts/cancelling-async-rust/), [Feb 2026 post](https://biriukov.dev/posts/async-rust-gocha-tokio-cancelation-select-future-then/)).

Most ergonomic expression of "A and B in parallel, 2 s deadline, cancel the loser": a deadline *scope* enclosing a *group*, where leaving the scope for any reason (deadline, error, first result) cancels and awaits children (Trio/Kotlin/Eio/MoonBit; Java is converging on it). For Fern's combinators that is `with_deadline(2s, || gather(a, b))` for both, and `with_deadline(2s, || race(a, b))` for first-wins; the design points the survey supports are (1) cancellation is a signal that unwinds `defer` but is not `catch`-able (MoonBit, Eio `Cancel.protect`), (2) the platform's HTTP primitives must honour it (Ktor 3.4, URLSession do; Rust must document it), (3) `race` must define what happens when both complete (Eio).

### 4. Testing without sockets

- Go `httptest.NewRecorder()` + `handler.ServeHTTP(rec, req)`, and `httptest.NewServer` for a real loopback listener ([golang doc, widely cited](https://github.com/golang/go/issues/52805)).
- Rust axum: `Router` is a `tower::Service`, so `app.oneshot(Request::builder()…).await` runs the full stack in-process; `MockConnectInfo` fakes peer info ([axum testing example](https://github.com/tokio-rs/axum/blob/main/examples/testing/src/main.rs)).
- Elixir `Plug.Test` builds a `conn` and calls the plug directly (standard; hexdocs blocked, not re-verified). Wisp has a `wisp/testing` module (from search summaries; not fetched).
- Undici `MockAgent` / `setGlobalDispatcher` swaps the dispatcher under `fetch` — dependency injection at the transport seam ([undici getting started](https://undici.nodejs.org/getting-started)).
- Eio: pass `Eio_mock` flows/nets instead of `env` ([eio README](https://github.com/ocaml-multicore/eio/blob/main/README.md)).
- Deterministic simulation: TigerBeetle VOPR stubs clock, network and disk behind one I/O interface, no threads, static allocation, seed + commit reproduces any failure ([vopr.md](https://github.com/tigerbeetle/tigerbeetle/blob/main/docs/internals/vopr.md), [protocol-aware DST, Aug 2026](https://tigerbeetle.com/blog/2026-08-20-protocol-aware-dst/)); FoundationDB is the ancestor. turmoil runs many hosts on one thread with simulated `TcpStream`/`TcpListener`, latency, partitions, crashes, torn writes, but cannot control time/entropy that dependencies (e.g. hyper) read from the OS ([turmoil](https://github.com/tokio-rs/turmoil), [S2 on mad-turmoil](https://s2.dev/blog/dst)); madsim replaces tokio wholesale under `--cfg madsim` and shims tonic/etcd/kafka/S3 ([madsim](https://github.com/madsim-rs/madsim)).

What a language can offer natively: the recurring obstacle is *ambient* time, randomness and sockets. If every effect goes through the Platform value the handler receives (Roc, Eio, Zig 0.16 `Io`, Workers `env`), a simulated Platform is an ordinary value, and a seeded deterministic run is the default test mode rather than a fork of the runtime. That is the VOPR/madsim outcome without the libc-override hack.

### 5. Error models

- reqwest: opaque `Error` with `Kind {Builder, Request, Redirect, Status, Body, Decode, Upgrade}` and predicates `is_timeout/is_connect/is_dns/is_status/…`; timeout is found by walking the source chain — informative but not exhaustive to match on ([error.rs](https://github.com/seanmonstar/reqwest/blob/master/src/error.rs)).
- ureq 3: a flat public enum — `StatusCode(u16)`, `Timeout(Timeout)`, `HostNotFound`, `ConnectionFailed`, `Protocol`, `Io`, `TooManyRedirects`, `RedirectFailed`, `BodyExceedsLimit`, `Tls`, … — with `Timeout` itself an enum of the phase that expired; `http_status_as_error` (default true) decides whether 4xx/5xx is `Err` ([error.rs](https://github.com/algesten/ureq/blob/main/src/error.rs)). Best typed design surveyed: phase-of-failure is data, not a string.
- httpx: a class hierarchy — `TransportError > TimeoutException > {ConnectTimeout, ReadTimeout, WriteTimeout, PoolTimeout}`, `NetworkError > {ConnectError, ReadError, …}`, `ProtocolError`, `TooManyRedirects`, and `HTTPStatusError` only from `raise_for_status()` ([exceptions](https://www.python-httpx.org/exceptions/)).
- undici: error codes `UND_ERR_CONNECT_TIMEOUT`, `UND_ERR_HEADERS_TIMEOUT`, `UND_ERR_BODY_TIMEOUT`, `RequestAbortedError`; statuses are never errors unless the `responseError` interceptor is composed ([Dispatcher.md](https://github.com/nodejs/undici/blob/main/docs/docs/api/Dispatcher.md)).
- Java: `HttpConnectTimeoutException extends HttpTimeoutException extends IOException`; statuses are data ([JDK-8209075](https://bugs.openjdk.org/browse/JDK-8209075)).
- Go: `*url.Error` wrapping `net.Error` with `Timeout()`; `context.DeadlineExceeded` for deadlines; status is data.
- Elixir/Erlang: process crash + supervisor; Bandit closes WebSockets with 1000 on shutdown.

Recommended synthesis for a Result-typed language: a small closed sum over *phase* — `Dns | Connect | Tls | Timeout(phase) | Protocol | Io | Redirect | BodyLimit | Cancelled` — with HTTP status kept on the `Ok` side and an explicit `ok_or_status()` helper, as ureq and httpx both converged on; `Cancelled` as its own variant is what MoonBit and Eio add and Rust lacks.


## Report 3: The lower stack: TLS, DNS, sockets, QUIC, WebSocket, buffers

Method: web search plus direct fetch of primary sources (GitHub READMEs/source, pkg.go.dev, kernel docs mirrored on GitHub), and fresh shallow clones of the QUIC/TLS repos for line counts (`find … | wc -l`, tests/examples/fuzz/bench excluded, HEAD of 2026-09-13..18). The egress proxy blocked rustls.dev, memorysafety.org, phoronix, go.dev, lwn.net, docs.kernel.org, rfc-editor/ietf/datatracker, wasi.dev, ziglang.org, bearssl.org, security.googleblog.com and web.archive.org; claims that rest only on search snippets from those domains are marked **[snippet]**, and things I could not confirm are marked **[unverified]**.

### 1. TLS

**Size of a native TLS 1.3 client+server.** Go `crypto/tls` is 14,092 lines excl. tests plus 7,728 for `crypto/x509` (Go 1.24.7 tree, my count). rustls `rustls/src` is 41,099 lines excl. tests (0.24.0-dev; crypto lives in the pluggable provider, `aws-lc-rs` default or `ring`; TLS 1.2+1.3, client+server; https://github.com/rustls/rustls). s2n-tls (C99, SSLv3–TLS 1.3, libcrypto from AWS-LC/OpenSSL/LibreSSL/BoringSSL, kTLS on POSIX) is ~60k lines across `tls/ utils/ stuffer/ crypto/` (https://github.com/aws/s2n-tls). Zig's `std.crypto.tls` is ~4,000 lines total (tls.zig 757, tls/Client.zig 1,613, Certificate.zig 1,270, Certificate/Bundle.zig 344) but is **client-only**: `std.crypto.tls.Server` (https://github.com/ziglang/zig/issues/14171) is open since Jan 2023 with no PR; the client does not handle HelloRetryRequest (comment in Client.zig), cannot answer client-certificate requests (https://github.com/ziglang/zig/issues/17446, open, milestone "urgent"), and has no ALPN (https://github.com/ziglang/zig/issues/18963). Its cipher/curve list is otherwise modern: AES-128/256-GCM, ChaCha20-Poly1305, AEGIS, X25519, **X25519MLKEM768**, P-256, P-384; ECDSA/RSA-PKCS1/RSA-PSS/Ed25519 signatures (https://github.com/ziglang/zig/blob/master/lib/std/crypto/tls/Client.zig). Nim has no native TLS; `std/net` wraps OpenSSL behind `-d:ssl` (https://github.com/nim-lang/Nim/blob/devel/lib/pure/net.nim). wolfSSL claims 20–100 kB footprint, TLS/DTLS 1.3, native ML-KEM + ML-DSA, release 5.9.2 on 2026-06-23 (https://github.com/wolfSSL/wolfssl). Mbed TLS 4.0 split crypto into TF-PSA-Crypto (three libraries) (https://github.com/Mbed-TLS/mbedtls). BoringSSL: "no guarantees of API or ABI stability", Chrome/Android only (https://github.com/google/boringssl). BearSSL size numbers: **[unverified]** (site blocked).

**Minimum interop set (2026).** Go's TLS 1.3 suites are fixed and not configurable: `TLS_AES_128_GCM_SHA256`, `TLS_AES_256_GCM_SHA384`, `TLS_CHACHA20_POLY1305_SHA256` (https://pkg.go.dev/crypto/tls). Key exchange: X25519MLKEM768 is default when `CurvePreferences` is nil since Go 1.24 (`GODEBUG=tlsmlkem=0` to disable); Go 1.26 added `SecP256r1MLKEM768`/`SecP384r1MLKEM1024`; Go 1.27 (Aug 2026) added opt-in `MLKEM1024`, ML-DSA-44/65/87 TLS 1.3 signature schemes, and `SystemCertPool` honouring `SSL_CERT_FILE`/`SSL_CERT_DIR` on Windows and Darwin (https://github.com/golang/website/blob/master/_content/doc/go1.27.md, go1.26.md). One user report on Go 1.25.1 saw plain X25519 negotiated with defaults; closed "not planned" (https://github.com/golang/go/issues/75453) — treat the default as version-dependent. Browser side **[snippet]**: Chrome 131 (Nov 2024) and Firefox 132 send X25519MLKEM768 by default, Apple OS 26 in fall 2025; Akamai made PQ the edge default 2026-01-31; the hybrid key share is 1,124 bytes vs 36 for X25519 (https://www.postquantumsecurity.org/publications/X25519+MLKEM768.html, https://scrapfly.io/blog/posts/post-quantum-tls-bot-detection). rustls's July 2025 benchmark also states OpenSSL and rustls now default to X25519MLKEM768 (https://rustls.dev/perf/2025-07-31-report/ **[snippet]**). Practical minimum: TLS 1.3 only, AES-128-GCM + ChaCha20-Poly1305 (+AES-256-GCM), X25519 + X25519MLKEM768 + P-256, verify ECDSA-P256/Ed25519/RSA-PSS certs. So for Fern: AES-GCM (with `aes`/`pmull` on arm64, AES-NI/PCLMUL on x86-64-v3), ChaCha20-Poly1305, X25519, ML-KEM-768, P-256, Ed25519, RSA verify, HKDF are the missing primitives.

**Root stores.** Go on Linux reads the first hit of `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/ca-bundle.pem`, `/etc/pki/tls/cacert.pem`, `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, `/etc/ssl/cert.pem` plus dirs `/etc/ssl/certs`, `/etc/pki/tls/certs` (https://github.com/golang/go/blob/master/src/crypto/x509/root_linux.go). On Darwin it does not bundle roots: it calls `SecTrustCreateWithCertificates`/`SecTrustEvaluateWithError` via `crypto/x509/internal/macos` without cgo (https://github.com/golang/go/blob/master/src/crypto/x509/root_darwin.go) — relevant for a no-libc language: that package dlopens Security.framework, so a static Darwin binary still needs a dynamic-library hook. rustls: `webpki-roots` is generated from Mozilla's CCADB and its README says embedded lists go stale, recommending `rustls-platform-verifier`, which on Linux = `rustls-native-certs` + `openssl-probe` + webpki, on macOS = Security.framework, Windows = CryptoAPI, Android = Trust Manager via JNI (https://github.com/rustls/webpki-roots, https://github.com/rustls/rustls-platform-verifier). rustls's CT crate `sct.rs` is archived (https://github.com/orgs/rustls/repositories); neither stack fetches OCSP itself **[unverified beyond org listing]**.

**kTLS.** Enabled per socket with `setsockopt(TCP_ULP,"tls")` then `TLS_TX`/`TLS_RX`; TLS 1.3 KeyUpdate pauses RX with `EKEYEXPIRED` until userspace supplies the new key; rekey counters (`TlsTxRekeyOk`…) appear in the v6.14 doc and not in v6.13, so TLS 1.3 rekey is kernel ≥6.14 (https://github.com/torvalds/linux/blob/v6.14/Documentation/networking/tls.rst). OpenSSL added kTLS in 3.0.0 (Sep 2021) and TLS 1.3 RX offload + zerocopy `sendfile` in 3.2.0 (Nov 2023) (https://raw.githubusercontent.com/openssl/openssl/master/CHANGES.md); rustls has the `ktls` crate under its org; Go has none (issue https://github.com/golang/go/issues/31908 is the runtime io_uring one; no kTLS issue located).

**Throughput/handshake numbers.** Nov 2023 (rustls #1626): with `ring`, rustls did ~2× OpenSSL 3.1.4 on TLS 1.3 client handshakes (3,868 vs 1,958/s) and 1.9× on TLS 1.2 resumption, but only 0.34–0.55× on bulk AES-GCM (2,235 vs 6,569 MB/s send); switching to aws-lc-rs recovered 26–62% (https://github.com/rustls/rustls/issues/1626). The 2025-07-31 report (rustls 0.23.31 vs OpenSSL 3.5.15 vs BoringSSL, x86_64, PQ on, BoringSSL with AVX-512 AES-GCM) and the Q1 2026 update say rustls still wins most handshake benchmarks and that neither OpenSSL nor BoringSSL moved since; exact tables **[snippet]** (https://rustls.dev/perf/2025-07-31-report/, https://www.memorysafety.org/blog/26q1-rustls-performance/, https://rustls.dev/perf/2024-10-31-arm64/).

### 2. DNS

Go's pure resolver (~3,300 lines: `dnsclient*.go`, `dnsconfig*.go`, `hosts.go`, `conf.go`, `nss.go`, `lookup*.go`) is the Unix default; it falls back to cgo `getaddrinfo` on macOS, when `LOCALDOMAIN`/`RES_OPTIONS`/`HOSTALIASES` are set, when `/etc/resolv.conf` or `nsswitch.conf` use unsupported features, or for `.local`/mDNS names; `netgo`/`netcgo` tags and `GODEBUG=netdns=` override (https://pkg.go.dev/net). A static no-libc binary therefore must accept: no NSS plugins (mDNS, LDAP, systemd-resolved beyond its stub at 127.0.0.53), and it must read `/etc/hosts`, `/etc/resolv.conf` (`nameserver`, `search`, `ndots`, `timeout`, `attempts`, `rotate`) itself. Happy Eyeballs in Go is `Dialer.FallbackDelay` = 300 ms (RFC 6555), racing the primary family against the other (https://github.com/golang/go/blob/master/src/net/dial.go). hickory-resolver defaults: strategy `Ipv6AndIpv4` (parallel A+AAAA), EDNS0 on, ndots 1, timeout 5 s, attempts 2, `try_tcp_on_error` false, DoT (RFC 7858) and DoH (RFC 8484) behind features; 0.26.2 fixed RUSTSEC-2026-0119/0120 and it ships on Pixel phones (https://github.com/hickory-dns/hickory-dns/blob/main/crates/resolver/src/config.rs, https://github.com/hickory-dns/hickory-dns/releases). c-ares (C89 stub resolver) covers EDNS0, AAAA, 0x20 randomisation, DNS cookies, TCP fallback + TCP Fast Open, RFC 6724 sorting (https://github.com/c-ares/c-ares). Zig 0.16's `std/Io/net/HostName.zig` (431 lines) parses resolv.conf (ndots ≤15, attempts ≤10, timeout ≤60), A/AAAA/CNAME, and has `connectMany` racing all addresses; no TCP fallback or EDNS0 is visible in the file (https://github.com/ziglang/zig/blob/master/lib/std/Io/net/HostName.zig). A stdlib stub therefore needs: RFC 1035 wire codec, UDP with TC-bit → TCP retry, EDNS0 (4096-byte UDP), hosts file, resolv.conf, search-list/ndots, parallel A/AAAA, RFC 6724 sort, and a Happy Eyeballs dialer; DoH/DoT are optional layers over the same codec.

### 3. Sockets and event loops

**io_uring availability.** Docker's default seccomp allowlist contains `io_setup`/`io_submit` but not `io_uring_setup/enter/register` (https://github.com/moby/profiles/blob/main/seccomp/default.json); moby#47532 asking to allow them was closed "not planned" (https://github.com/moby/moby/issues/47532). Docker Desktop 4.42.0 (2025-06-10) additionally "blocks io_uring syscalls in containers" and users report EPERM even with `--privileged --security-opt seccomp=unconfined` (https://github.com/docker/for-mac/issues/7707). Google's 2023 statement that 60% of kCTF submissions were io_uring exploits and its disabling on Android/ChromeOS/servers is widely quoted **[snippet; blog blocked]**. Consequence: io_uring can only be an opt-in fast path with an epoll fallback.

**Who uses what.** libuv 1.45 moved some file ops to io_uring; 1.49 reverted to the threadpool by default (opt-in `UV_LOOP_USE_IO_URING_SQPOLL`), sockets stayed on epoll (https://github.com/libuv/libuv/blob/v1.x/docs/src/fs.rst; Node re-enable request closed: https://github.com/nodejs/node/issues/52156). Bun's uSockets loop calls `epoll_pwait2` (syscall 441, ≥5.11) with `epoll_pwait` fallback and `kevent64` on macOS; no io_uring (https://github.com/oven-sh/bun/blob/main/packages/bun-usockets/src/eventing/epoll_kqueue.c). Deno/tokio use mio: epoll, kqueue, IOCP, no io_uring (https://github.com/tokio-rs/mio). Go's netpoller is epoll/kqueue; io_uring issue #31908 is "Unplanned" since 2019. tokio-uring is "still very young", owned-buffer API, needs ≥~5.11 (https://github.com/tokio-rs/tokio-uring). monoio (io_uring with epoll/kqueue fallback, thread-per-core, owned buffers) reported ~2× tokio at 4 cores and ~3× at 16 on a 10 GbE X710, kernel 5.15, Dec 2021 (https://github.com/bytedance/monoio/blob/master/docs/en/benchmark.md). glommio is io_uring-only, kernel ≥5.8, needs 512 KiB locked memory (https://github.com/DataDog/glommio). Zig 0.16's `std.Io` has `Threaded` (all platforms) and `Evented` (io_uring on Linux x86_64/aarch64, kqueue on BSD/macOS), the latter experimental with a known perf regression under investigation (https://github.com/ziglang/zig/blob/master/lib/std/Io.zig; https://ubos.tech/news/zig-0-12-0-introduces-experimental-io_uring-and-gcd-std-io-implementations-february-2026-devlog-highlights/ **[snippet]**). Jens Axboe's own write-ups give no epoll-vs-io_uring percentages; the one number is that send-zerocopy beats copying above ~3,000-byte packets in 6.10 (https://github.com/axboe/liburing/wiki, "What's new in 6.10"). Feature floor: multishot accept 5.19, provided buffer rings 5.19, multishot recv 6.0, `DEFER_TASKRUN`+`SINGLE_ISSUER` 6.1 (https://github.com/axboe/liburing/wiki/io_uring-and-networking-in-2023).

**Defaults.** Go sets `TCP_NODELAY` on in `newTCPConn` and keepalive idle/interval 15 s, count 9 (https://github.com/golang/go/blob/master/src/net/tcpsock.go); Node `setNoDelay` default `true` (https://nodejs.org/api/net.html). `SO_REUSEPORT`/`TCP_FASTOPEN` in Go stdlib: only via raw `ListenConfig.Control` **[unverified this pass]**.

**WASI.** 0.2 sockets are `start-*/finish-*` pairs plus a `pollable`, with `input-stream`/`output-stream`; no TLS, Unix sockets, raw sockets or interface enumeration (https://github.com/WebAssembly/wasi-sockets). The 0.3 draft (`@since 0.3.0-rc-2025-09-16`) is native async: `connect: async func`, `listen -> stream<tcp-socket>`, `send: async func(data: stream<u8>)`, `receive -> tuple<stream<u8>, future<result>>`, UDP `send`/`receive: async func` with `list<u8>` (https://raw.githubusercontent.com/WebAssembly/wasi-sockets/main/wit-0.3.0-draft/types.wit). Wasmtime 37 (2025-09-20) shipped the first WASIp3 behind `-Sp3 -Wcomponent-model-async`; Wasmtime 46 (2026-06-22) "supports WASI 0.3.0 by default" with `component-model-async` on; 48 (2026-08-20) unified p2/p3 wasi-http host traits (https://github.com/bytecodealliance/wasmtime/releases/tag/v37.0.0, /v46.0.0, /v48.0.0).

### 4. QUIC / HTTP/3

Line counts (my clones, excl. tests): Cloudflare quiche 61.7k Rust incl. h3+qpack, requires BoringSSL, sans-IO, used by Cloudflare edge, Android DoH3 and curl, v0.30.0 (https://github.com/cloudflare/quiche); quinn-proto 26.0k + quinn/quinn-udp 8.1k Rust, rustls, GSO/GRO/ECN, 0.12 (https://github.com/quinn-rs/quinn); ngtcp2 48.8k C + 9.6k crypto shims for quictls/BoringSSL/aws-lc/picotls/wolfSSL/GnuTLS/LibreSSL/OpenSSL≥3.5 (https://github.com/ngtcp2/ngtcp2); msquic 62.1k core + 46.1k platform C, Schannel or OpenSSL, RSS, XDP, UDP coalescing (https://github.com/microsoft/msquic); s2n-quic 144.7k Rust total (core 79k, transport 35k), s2n-tls or rustls, GSO on kernel ≥5.0, 1.88 (https://github.com/aws/s2n-quic); quic-go 37.2k Go + 5.9k http3, RFC 9000/9001/9002/9114/9221/8899/9369, GSO on Linux ≥4.18 with `QUIC_GO_DISABLE_GSO`, users Caddy/cloudflared/Syncthing (https://github.com/quic-go/quic-go, https://github.com/quic-go/docs/blob/master/content/docs/quic/optimizations.md). Go stdlib: **no HTTP/3** in Go 1.27; `golang.org/x/net/quic` v0.59.0 (2026-09-08) and `x/net/internal/http3` both say "not ready for production usage" (https://pkg.go.dev/golang.org/x/net/quic, https://pkg.go.dev/golang.org/x/net/internal/http3; https://github.com/golang/go/issues/32204 still "Unplanned"). No Zig QUIC in std. Verdict: a QUIC transport is 25–60k lines *on top of* TLS 1.3 with the QUIC-TLS key-schedule hooks (Go exposes these as `crypto/tls.QUICConn`, which quic-go consumes); HTTP/3+QPACK is another ~6k. Keep QUIC/HTTP/3 out of the stdlib; design the TLS core with a QUIC-style handshake-message/secret interface so a library can build on it.

### 5. WebSocket

RFC 6455 is small: coder/websocket claims zero-alloc reads/writes with full permessage-deflate including context takeover, whereas gorilla only supports no-context-takeover and `x/net/websocket` is deprecated (https://github.com/coder/websocket). uWebSockets' documented reasons for speed: corking ("by far the single most important performance trick") so all writes in a callback batch into one syscall; per-socket `maxBackpressure` with `send()` returning SUCCESS/BACKPRESSURE/DROPPED and a `drain` event; user data stored inline in the socket; compression modes `DISABLED`, `SHARED_COMPRESSOR` (no per-socket memory, per-message reset) or `DEDICATED_COMPRESSOR` (4 kB–256 kB per socket sliding window), with the note that compression leaves "20–30% remaining I/O performance"; claims >100k active TLS 1.3 sockets on a Pi 4 and 12× Node's HTTP req/s (https://github.com/uNetworking/uWebSockets/blob/master/misc/READMORE.md). RFC 7692 window/no-context-takeover details and RFC 8441 (extended CONNECT, `:protocol = websocket`, `SETTINGS_ENABLE_CONNECT_PROTOCOL`) text and current browser support: **[unverified; all RFC mirrors blocked]** — from memory, Firefox and Chrome support 8441 and Chrome also RFC 9220 over H3.

### 6. Zero-copy and buffers

`MSG_ZEROCOPY` only pays above ~10 kB writes, completions come back via `MSG_ERRQUEUE`, buffers must stay untouched until then, and loopback always copies (https://github.com/torvalds/linux/blob/master/Documentation/networking/msg_zerocopy.rst). io_uring `SEND_ZC` crossover is ~3 kB (6.10). io_uring zero-copy RX landed in 6.15 (doc present at v6.15, absent at v6.14) and needs NIC header/data split plus flow steering into a dedicated queue, `SINGLE_ISSUER`+`DEFER_TASKRUN`, and a registered area split into fixed-size chunks (https://github.com/torvalds/linux/blob/v6.15/Documentation/networking/iou-zcrx.rst); large-RX-buffer follow-up claims up to 30% CPU saving **[snippet]** (https://www.phoronix.com/news/IO-uring-zcrx-Large-RX). kTLS + `sendfile` zerocopy is `SSL_OP_ENABLE_KTLS_TX_ZEROCOPY_SENDFILE` in OpenSSL 3.2 (https://github.com/openssl/openssl/blob/master/doc/man3/SSL_CTX_set_options.pod). The completion-based runtimes (tokio-uring, monoio) all converge on the same rule: the buffer is *moved* to the kernel and handed back on completion, which is exactly the shape Perceus ownership gives for free. Recommendation for Fern: (a) a per-thread ring of provided buffers (kernel picks the buffer for multishot recv, the CQE tells you which one) as the io_uring path, with an epoll path that reuses the same owned-buffer type; (b) a unique-owned, refcount-1 byte buffer that recv returns and the parser slices without copying (the `bytes::Bytes` pattern is just refcounted slices, i.e. Fern's default); (c) a per-connection arena for parser state and headers, dropped with the connection; (d) write via `writev`/corking of immutable slices rather than assembling a contiguous frame; (e) treat `MSG_ZEROCOPY`/`SEND_ZC` as an opt-in for ≥~4–10 kB sends only.

### Bottom line for the plan
TLS 1.3 client+server with the minimum set above is a ~15–20k-line job plus the missing primitives (AES-GCM, ChaCha20-Poly1305, X25519, ML-KEM-768, P-256, Ed25519, RSA-verify, HKDF); Zig shows what shipping client-only costs in interop bugs. A stub resolver plus Happy Eyeballs is ~3–4k lines and mandatory in a no-libc binary. Event loop: epoll/kqueue primary, io_uring opt-in with owned-buffer semantics, WASI 0.3 streams map onto the same owned-buffer API. QUIC/HTTP/3 and WebSocket-over-H2 are library territory; RFC 6455 with shared-compressor deflate is a stdlib-sized item.

Method: web search + primary-source fetches. Several blogs were egress-blocked (ponylang.io, kristoff.it, andrewkelley.me, ziglang.org, tigerbeetle.com, polarsignals.com, s2.dev, inko-lang.org, harelang.org, moonbitlang.com, antithesis.com, fuchsia.googlesource.com); for those I relied on GitHub sources or search snippets and flag it. ### 1. Erlang/OTP + Elixir

**Socket API shapes** ([gen_tcp.erl docs](https://github.com/erlang/otp/blob/master/lib/kernel/src/gen_tcp.erl)):
- `{active, true | false | once | N}`: active delivers `{tcp, Sock, Data}` / `{tcp_closed, Sock}` / `{tcp_error, Sock, R}` to the owner; `{active, N}` counts down and sends `{tcp_passive, Sock}` at 0 — flow control built into the delivery mode, not bolted on.
- `{packet, 0|1|2|4|line|http|http_bin|...}` plus `packet_size`: the kernel-side driver frames messages before they reach user code. `http_bin` parses request lines/headers in C.
- `controlling_process/2`: exactly one owner receives messages; non-owner calls return `{error, not_owner}`. The classic trap: you must set `{active,false}` before handing off or messages race to the old owner.
- **Two backends, two semantics** (`inet_backend = inet` (inet_drv) vs `socket` NIF): the driver *buffers* oversized sends unboundedly and returns `ok`; the socket backend blocks the caller until `send_timeout`; `shutdown` is deferred on inet, immediate on socket. That is a semantic fork inside one API — a mistake to avoid.

**Binaries** ([efficiency guide](https://github.com/erlang/otp/blob/master/system/doc/efficiency_guide/binaryhandling.md)): heap binaries ≤64 bytes; larger are refc binaries (off-heap, shared across per-process heaps via ProcBin). `<<H, T/binary>>` uses a *match context* — a pointer+position — so protocol parsing never copies; the compiler elides sub-binary creation when the context is immediately re-matched. Cost: a small sub-binary pins the whole refc binary (hence `binary:copy/1`), and append-then-send "shrinks" the writable binary so the next append copies.

**Acceptor pools** ([Thousand Island](https://github.com/mtrudel/thousand_island)): `Listener` + `AcceptorPoolSupervisor` → 100 `AcceptorSupervisor`s by default, each = one `Acceptor` + one `DynamicSupervisor` for its connections, so subtrees are "nearly autonomous". Handler behaviour: `handle_data(data, socket, state) -> {:continue, state}` (+ `handle_connection/close/timeout/error/shutdown`). Draining: close the listener, handlers trap exits, force-kill after `shutdown_timeout` (15 000 ms). [Ranch 2.3](https://github.com/ninenines/ranch) is the older equivalent: `ranch:handshake` transfers socket ownership to the protocol process; `max_connections` gives backpressure at accept.

**HTTP** ([Bandit 1.8.x](https://github.com/mtrudel/bandit)): pure Elixir, no NIFs; HTTP/1.x (RFC 9112), HTTP/2 (RFC 9113, one process per *stream*, full flow control), WebSocket (RFC 6455) via WebSock; default in Phoenix ≥1.7.11; claims up to 4× Cowboy on HTTP/1 and 1.5× on HTTP/2; no HTTP/3. [Cowboy 2.19](https://github.com/ninenines/cowboy) covers HTTP/1.1, /2, /3, WebSocket over Ranch.

**Steal:** `{active, N}` credit-based delivery; kernel/driver-side framing (`{packet, N}`) as a socket option; explicit single owner; refc-binary + match-context parsing (Fern's Perceus buffers can do the same with a slice-of-shared-buffer type, but design the "sub-slice pins parent" cost in from day one). **Avoid:** two backends with different blocking/buffering semantics.

### 2. Pony, Inko

**Pony**: `TCPConnection` is an actor; you supply a notify object. [RFC 0017](https://github.com/ponylang/rfcs/blob/main/text/0017-tcp-backpressure.md) added write backpressure — `fun ref throttled(conn: TCPConnection ref, status: Bool)` fires when a write can't complete and data is queued — and read backpressure — `be mute()` / `be unmute()` stop reading so TCP pushes back on the peer. Documented trap: a muted connection cannot observe peer close (close is learned on read), so it never exits unless unmuted. Runtime-level backpressure (deprioritising senders to overloaded actors, [PR #2264](https://github.com/ponylang/ponyc/pull/2264)) produced a real deadlock ([#3382](https://github.com/ponylang/ponyc/issues/3382)). A rewrite landed in 2026 ("[Pony Networking, Take Two](https://www.ponylang.io/blog/2026/03/pony-networking-take-two/)", March 2026 — blocked, unread). The [current source](https://github.com/ponylang/ponyc/blob/main/packages/net/tcp_connection.pony) shows the new shape: `TCPConnection` is a *class* owned by a `TCPConnectionActor`, with typed lifecycle receivers (`_on_connected`, `_on_sent`/`_on_send_failed`, `_on_tls_ready`, `_on_idle_timeout`), `send()` returning a `SendResult` with an immediate `_on_send_accepted` and later `_on_sent` once data reaches the OS, Happy-Eyeballs in-flight tracking, and `close()` while muted hard-closing and dropping undelivered data. **Steal:** split "accepted into queue" from "handed to OS"; explicit throttled/unthrottled; idle timeout as a first-class event. **Avoid:** implicit runtime backpressure that can deadlock.

**Inko** (0.18–0.20): sockets are non-blocking; a blocked process is suspended and a "network poller" thread (epoll/kqueue, `INKO_NETPOLL_THREADS`) reschedules it — async I/O baked into the process model, no colouring ([release notes](https://inko-lang.org/news/inko-0-18-1-is-released/)). API returns `Result`: `TcpServer.new(IpAddress.v4(0,0,0,0), port: 9999)`, `server.accept`, `TcpClient.new([ips], port:)` (RFC 8305 Happy Eyeballs, 5 s default timeout since 0.18.1, `with_timeout` override) ([sockets tutorial](https://github.com/inko-lang/inko/blob/main/docs/source/getting-started/sockets.md)). Its author argues against async I/O as a language feature in "[Asynchronous IO: the next billion-dollar mistake?](https://yorickpeterse.com/articles/asynchronous-io-the-next-billion-dollar-mistake/)" (blocked; content unverified).

### 3. Roc

**Purity inference** (basic-cli [0.18.0](https://github.com/roc-lang/basic-cli/releases/tag/0.18.0), 28 Dec 2024): `Task` deleted. `!` is now part of the *name* of an effectful function, `=>` marks an effectful function type, `Task.ok/err` → `Ok/Err`, `Task.await` → `try`. The compiler infers effectfulness; pure functions cannot call effectful ones; all platform functions are effectful. **Steal:** this is the closest existing design to Fern's "Platform bag": effects are ordinary functions the platform hands in, purity is inferred and visible in the type.

**basic-webserver** ([README](https://github.com/roc-lang/basic-webserver/blob/main/README.md), pinned to nightly 2026-09-18): the app exports three functions — `init!` (returns `Server.Config` + app context), `respond!` (per request, concurrent), `shutdown!`. Host is Rust hyper+tokio; does HTTP/1.1 and cleartext h2, response compression (zstd/br/gzip), SSE, pooled outbound HTTP(S), pooled SQLite, bounded `Cmd`. Explicit limits: 32 concurrent handlers / 64 queued, 1 MiB default body, 30 s graceful shutdown, **no TLS** ("put a reverse proxy in front"), **no WebSocket**, no request decompression. Stated stance: "Durable mutable state belongs in SQLite or an external service." **Steal:** init/respond/shutdown triple with bounded concurrency and bodies as *platform config*; refuse to own TLS at first. **Got wrong:** no WebSocket/streaming request bodies leaves a hole for edge-style workloads.

### 4. Other languages

- **Koka**: no networking. `std/os` has dir/env/file/flags/path/process/readline/task only ([source](https://github.com/koka-lang/koka/tree/master/lib/std/os)).
- **Lean 4**: `Std.Http` now in core ([Transport.lean](https://github.com/leanprover/lean4/blob/master/src/Std/Http/Transport.lean)): a typeclass `recv : α → UInt64 → Async (Option ByteArray)`, `sendAll : α → Array ByteArray → Async Unit`, `recvSelector`, `close : α → IO Unit`, with `Socket.Client` and an in-memory `Mock` pair for tests. [`Server.serve (addr) (handler) (config := {}) (backlog := 1024) : Async Server`](https://github.com/leanprover/lean4/blob/master/src/Std/Http/Server.lean), HTTP/1.1 only, `CancellationContext` shutdown, `maxConnections`. Underlying I/O is libuv promises. **Steal:** transport-as-typeclass with a mock instance shipped in the stdlib.
- **Austral**: stdlib "a few basic data structures and capability-based filesystem access" — no net ([repo](https://github.com/austral/austral)). **Vale, Carbon, Jai:** no networking story I could verify (Jai is closed beta) — **unverified**.
- **Odin `core:net`** ([doc.odin](https://github.com/odin-lang/Odin/blob/master/core/net/doc.odin)): blocking only ("Nonblocking IO" planned), Windows/Linux/macOS; init panics unless the temp allocator has ≥4 MiB scratch. Not a model.

- **C3**: `std::net` has tcp/udp/socket/url/inetaddr ([source](https://github.com/c3lang/c3c/tree/master/lib/std/net)); plain sockets.
- **Zig 0.16 (Apr 2026)** — the most relevant design. `std.Io` is a `{userdata, vtable}` value passed like an `Allocator` ([Io.zig](https://github.com/ziglang/zig/blob/master/lib/std/Io.zig)). One vtable covers `async/concurrent/await/cancel/select/group*`, mutex/condition, all file ops, `now/sleep`, and net: `netListenIp, netAccept, netBindIp, netConnectIp, netListenUnix, netSend, netReceive, netRead, netWrite, netClose, netLookup`. `Io.Threaded.init(gpa)` is a thread pool that interrupts blocking syscalls via `SIGIO` for cancellation; in `single_threaded` builds `Io.concurrent` returns `error.ConcurrencyUnavailable` ([Threaded.zig](https://github.com/ziglang/zig/blob/master/lib/std/Io/Threaded.zig)). `Io.Evented` (io_uring/kqueue) exists but was reported as incomplete/not compiling in May 2026 ([Lalinsky](https://lalinsky.com/2026/05/11/async-io-in-zig-016-today.html), blocked; from search snippet). `std.http.Client` holds an `io: Io` field ([Client.zig](https://github.com/ziglang/zig/blob/master/lib/std/http/Client.zig)). **Steal:** the *shape* — one caller-supplied interface that is simultaneously the concurrency primitive, the clock, and the socket layer, so a test/simulated Io is just another implementation. **Watch:** shipping with only the threaded backend shows how large the vtable is to implement.
- **Nim**: [mummy](https://github.com/guzba/mummy) — one epoll/kqueue I/O thread, handlers on a worker pool, "blocking the thread is totally fine"; needs `--threads:on --mm:orc|arc`; ~9.5k req/s vs httpbeast 9.9k in its own benchmark. [chronos](https://github.com/status-im/nim-chronos) — single-threaded async/await with `{.async: (raises: []).}` exception tracking; multithreaded servers still TODO. [httpbeast](https://github.com/dom96/httpbeast) — selectors-based, parallel when threaded, "not hardened against common HTTP exploits". **Steal from mummy:** threads-not-async is viable for a share-nothing-worker design.
- **Crystal**: `HTTP::Server` = one fiber per connection, handler chain, HTTP/1.1 only, `reuse_port` for multi-process ([server.cr](https://github.com/crystal-lang/crystal/blob/master/src/http/server.cr)). 1.20.0 (17 Apr 2026) added an io_uring event loop and `Fiber::ExecutionContext::ThreadPool`; 1.21.0 (16 Jul 2026) released Execution Contexts (breaking) ([releases](https://github.com/crystal-lang/crystal/releases)).
- **V veb**: picoev loop, handlers run *on* the loop (must `spawn` to avoid blocking), `nr_workers` extra loops Linux-only, `ctx.takeover_conn()`, per-request arenas with `-prealloc`, HTTP/1.1 ([source](https://github.com/vlang/v/tree/master/vlib/veb)).
- **D vibe.d**: fibers over `eventcore`, blocking-style API ([repo](https://github.com/vibe-d/vibe.d)).
- **OCaml 5 Eio** (≥1.x, OCaml ≥5.2) ([README](https://github.com/ocaml-multicore/eio/blob/main/README.md)): direct style via effects; `Switch.run (fun sw -> Fiber.fork ~sw ...)` structured concurrency; every fiber has a cancellation context and sibling failure cancels the branch; **capabilities passed as `env#net` / `env#fs` / `env#cwd`** — no net capability, no network; `Eio.Net.listen net ~sw addr`, `Eio.Net.run_server`, `Eio.Net.connect ~sw net addr`; backends `eio_linux` (io_uring), `eio_posix`, `eio_windows` (incomplete); `Eio_mock` flows/net with automatic deadlock detection. **Steal:** capability object = Fern's Platform bag, plus a mock backend in the stdlib. **Got wrong (self-reported):** Conditions are error-prone; io_uring completion ordering surprises.
- **Haskell warp**: HTTP/1.x + HTTP/2 over WAI ([repo](https://github.com/yesodweb/wai/tree/master/warp)); green-thread-per-connection over the GHC IO manager with a single timeout-manager thread — from the POSA chapter, which I could not fetch (**partly unverified**).
- **Scala Kyo** ([repo](https://github.com/getkyo/kyo)): effects as `A < S` intersection rows; `kyo-http` (HTTP/1.1 client+server on JVM/JS/Native/WASM), `kyo-net` (TCP/Unix/TLS over io_uring/epoll/kqueue/NIO); `Scope` for structured resource lifetime. **Unison**: abilities (site blocked; **unverified** detail).
- **Gleam 1.18.1** (Aug 2026): [glisten](https://github.com/rawhat/glisten) = supervisor over gen_tcp acceptors, handler `fn(state, msg, conn) -> state`; [mist](https://github.com/rawhat/mist) = HTTP/1.1, WebSocket, chunked/streaming, `send_file`; BEAM-only, no JS-target server. [wisp](https://github.com/gleam-wisp/wisp) = middleware-as-functions via `use`.
- **Grain**: wasi stdlib is file/process/random/time — no sockets ([source](https://github.com/grain-lang/grain/tree/main/stdlib/wasi)).
- **MoonBit** ([async 0.22.1](https://github.com/moonbitlang/async), [docs](https://github.com/moonbitlang/moonbit-docs/blob/main/next/language/async-experimental.md)): `async fn` colouring but calls look normal; async fns implicitly raise; **everything cancellable by default**, cancellation raised at the last block point, `defer/errdefer` run, not `catch`-able; `async fn[X] with_task_group(async (TaskGroup[X]) -> X) -> X` guarantees children finish. Single-threaded cooperative runtime with epoll/kqueue/IOCP; packages socket/http/tls/websocket/fs/process; JS target has no IO in browsers; wasm1 experimental and only runs under `moonrun`. **Steal:** cancel-by-default + task-group scoping; **note:** their wasm story is a private runtime, not WASI.
- **Bend/HVM**: none.

### 5. Systems level

- **MirageOS** [mirage-tcpip](https://github.com/mirage/mirage-tcpip): functorised over a `NETIF` device; ships a *direct* stack (unikernel) and a *socket* stack (`src/stack-unix`, wraps OS sockets) behind the same signature — the same app runs on either.
- **smoltcp** ([repo](https://github.com/smoltcp-rs/smoltcp), Rust ≥1.91): `no_std`, no heap; `phy::Device` with `RxToken/TxToken`; **`Interface::poll(timestamp, device, sockets)`** — the stack is a pure state machine the caller drives with time; `poll_at/poll_delay` hand timers back; sockets use caller-supplied ring buffers; no SACK, no VLAN. Used by Hubris and (until archived 28 Apr 2026) [Redox netstack](https://github.com/redox-os/netstack).
- **Hubris** [net task](https://github.com/oxidecomputer/hubris/tree/master/task/net): UDP/IPv6-only smoltcp; **sockets declared statically in `app.toml` (`config.net`) with owner task and buffer sizes**; clients call `send_packet`/`recv_packet` IPC with leased buffers; the stack posts notification bits; three copies (DMA → socket buffer → task) accepted so a slow task cannot starve DMA; one smoltcp instance per VLAN.
- **Unikraft** [lib-lwip](https://github.com/unikraft/lib-lwip): lwIP glued to `uknetdev` plus a POSIX socket shim. **seL4 sDDF** ([repo](https://github.com/au-ts/sddf)): driver/mux/copier/client components over shared-memory queues; "network device class mostly mature" (design PDF not fetched). **Fuchsia netstack3**: core/bindings split — **unverified** (blocked).
- **TigerBeetle**: `pub const IO = switch (builtin.target.os.tag) { .linux => IO_Linux, .windows => IO_Windows, .macos… => IO_Darwin }` ([io.zig](https://github.com/tigerbeetle/tigerbeetle/blob/main/src/io.zig)) — completion-based callbacks, kqueue emulated as completion; single-threaded loop; all memory allocated at startup; time injected by the primary into the state machine, never read ambiently ([ARCHITECTURE](https://github.com/tigerbeetle/tigerbeetle/blob/main/docs/ARCHITECTURE.md)). New blog "[Protocol-Aware DST](https://tigerbeetle.com/blog/2026-08-20-protocol-aware-dst/)" (20 Aug 2026, blocked).

**Day-one lesson:** the stack (smoltcp, Hubris, TigerBeetle) is a state machine that *receives* time and buffers; the OS-facing edge (Zig `Io`, MirageOS NETIF, Lean `Transport`) is a swappable interface. Fern should make the Platform bag *be* that interface — sockets, clock, sleep, random, spawn — so bare-metal and simulation are just other implementations.

### 6. Deterministic simulation testing

- **FoundationDB** ([testing.rst](https://github.com/apple/foundationdb/blob/main/documentation/sphinx/source/testing.rst), [flow](https://github.com/apple/foundationdb/blob/main/flow/README.md)): Flow's `Promise/Future` coroutines on one thread; simulation models network, disk (incl. fill-up), machine/DC failure, "swizzle-clogging"; ~10:1 sim/real; ~1 trillion CPU-hours run.
- **TigerBeetle VOPR** ([vopr.md](https://github.com/tigerbeetle/tigerbeetle/blob/main/docs/internals/vopr.md), [packet_simulator.zig](https://github.com/tigerbeetle/tigerbeetle/blob/main/src/testing/packet_simulator.zig)): seed + commit reproduces; `PacketSimulatorOptions` = `one_way_delay_mean/min`, `packet_loss_probability`, `packet_replay_probability`, `partition_mode {uniform_size, uniform_partition, isolate_single}`, `partition/unpartition_probability`, `path_maximum_capacity`, `path_clog_probability/duration_mean`; the message bus contract is deliberately weak (drop/dup/reorder/corrupt allowed).
- **turmoil** ([repo](https://github.com/tokio-rs/turmoil)): hosts as tasks on one thread, `turmoil::net::TcpStream` drop-ins, `turmoil-fs`, `turmoil-io-uring`; does not control time in non-turmoil code.
- **madsim** ([repo](https://github.com/madsim-rs/madsim)): `cfg(madsim)` swaps tokio; **libc hooks on `getrandom`/`clock_gettime`**; mocked tonic/etcd/rdkafka/S3; needs patches for crates like `quanta`. S2's [mad-turmoil](https://github.com/s2-streamstore/mad-turmoil) fuses the two because transitive crates read time/entropy out of band — "deterministic needs a libc-level seam, not just a runtime-level one".
- **Shuttle** ([repo](https://github.com/awslabs/shuttle)): replaces `std::thread/sync`, random/PCT schedulers, replayable seed; unsound but scales (vs loom's exhaustive). **Polar Signals** (2025, [blog](https://www.polarsignals.com/blog/posts/2025/07/08/dst-rust) blocked): rewrote as state machines owning concurrency, time, randomness, fault injection after "mostly-DST" in Go via WASM proved leaky. **Antithesis**: hypervisor-level (blocked; **unverified**).

**The seam Fern needs:** every non-determinism source — sockets, clock/monotonic time, sleep/timers, random, worker spawn, file I/O — reachable *only* through the Platform value, with no ambient global (that is what madsim had to patch back in); a single-threaded deterministic scheduler mode for share-nothing workers; and a packet-simulator-grade fake network in the stdlib (Eio_mock / Lean `Mock` / turmoil all ship one). Because Fern has no exceptions and immutable values, a `Platform` with a seeded simulated implementation is cheap to make; the hard part is forbidding side channels (`clock_gettime` via FFI) at the capability-classification layer Fern already has.


## Report 5: Security, robustness and conformance

Sources verified by fetch are cited inline. Where the primary host was unreachable from this sandbox (portswigger.net, rfc-editor.org, ietf.org, httpwg.org, kb.cert.org, nginx.org, rustsec.org, blog.cloudflare.com, curl.se, nvd.nist.gov, cve.org, seclists.org, openwall.com) the claim rests on a mirror or a secondary write-up and is marked *(secondary)*; anything I could not confirm at all is marked **unverified** or (unverified).

### 1. Attack classes to design against

#### 1a. Request smuggling / desync (HTTP/1.1)
RFC 9112 §6.3 is the framing law (numbered §6.4 in the current httpwg bis draft; §6.1 is Transfer-Encoding in both), and every 2019-2025 desync is a violation of one of its rules. Verbatim from the httpwg source mirror ([raw](https://raw.githubusercontent.com/httpwg/http-core/main/draft-ietf-httpbis-messaging-latest.xml)): Transfer-Encoding "overrides the Content-Length. Such a message might indicate an attempt to perform request smuggling"; chunked not the final coding in a request → "MUST respond with the 400 (Bad Request) status code and then close the connection"; an invalid or non-identical multi-valued Content-Length → 400 and close (proxy: 502); a request with neither → body length 0. §6.1: a server "MAY reject a request that contains both Content-Length and Transfer-Encoding ... Regardless, the server MUST close the connection after responding"; an HTTP/1.0 message carrying Transfer-Encoding "MUST [be treated] as if the framing is faulty"; unknown coding → SHOULD 501. §5.1: whitespace before the colon → MUST 400. §5.2: obs-fold → MUST 400 or replace with SP. §2.2: bare CR → MUST reject or replace with SP; "a recipient MAY recognize a single LF as a line terminator". §7.1: "recipients MUST anticipate potentially large hexadecimal numerals and prevent parsing errors due to integer conversion overflows"; unrecognized chunk extensions MUST be ignored but total extension length ought to be capped.

The named variants: CL.TE / TE.CL / TE.TE (2019), H2.CL / H2.TE downgrade smuggling (PortSwigger 2021: AWS ALB forwarded TE in h2 requests; Netty CVE-2021-21295; Netlify cache poisoning) ([research index](https://portswigger.net/research/http2), *secondary*), TE.0 against Google Cloud's HTTP(S) load balancer (backend treated a chunked body as length 0; fixed May 2024, $8,500 bounty) ([Bugcrowd](https://www.bugcrowd.com/blog/unveiling-te-0-http-request-smuggling-discovering-a-critical-vulnerability-in-thousands-of-google-cloud-websites/), *secondary*), and Kettle's Black Hat 2025 "HTTP/1.1 must die": 0.CL (front end and back end disagree on `Content-Length: 0`), Expect-based desyncs (vanilla and obfuscated `Expect: 100-continue` made parsers leak memory and skip header stripping), "early-response gadgets" that make 0.CL exploitable (unverified), and double desync for response-queue poisoning, subverting Akamai, Cloudflare and Netlify (24M+ sites); >$350k in bounties ([PortSwigger](https://portswigger.net/research/http1-must-die), [Black Hat whitepaper](https://i.blackhat.com/BH-USA-25/Presentations/US-25-Kettle-HTTP1-Must-Die-The-Desync-Endgame-wp.pdf), [tool reimplementation](https://github.com/perplext/echteeteepee), *secondary*). Akamai's own CVE-2025-66373 (fixed 2025-11-17) forwarded chunk data whose declared size did not match the actual chunk ([GHSA](https://github.com/advisories/ghsa-xxgg-h2vh-mc43)).

**Recurring root causes** across the 2024-2026 CVE record: lenient line terminators (Go CVE-2025-22871: bare LF accepted in chunk-size line, fixed 1.23.8/1.24.2 ([GO-2025-3563](https://pkg.go.dev/vuln/GO-2025-3563))); malformed header termination (Node CVE-2025-23167, `\r\n\rX`, fixed by llhttp 9 ([Node May 2025](https://nodejs.org/en/blog/vulnerability/may-2025-security-releases))); whitespace before the colon (Node CVE-2024-27982 ([Node Apr 2024](https://nodejs.org/en/blog/vulnerability/april-2024-security-releases))); header-count truncation where headers past `maxHeadersCount` were hidden from the app but still used for framing (Node CVE-2026-58044, llhttp 9.4.3 ([Node July 2026](https://nodejs.org/en/blog/vulnerability/july-2026-security-releases))); non-RFC Content-Length digits (hyper RUSTSEC-2021-0078, CVE-2021-32715) and chunk-size integer overflow (RUSTSEC-2021-0079, CVE-2021-32714) ([advisory-db](https://raw.githubusercontent.com/rustsec/advisory-db/main/crates/hyper/RUSTSEC-2021-0079.md)). llhttp documents every relaxation it offers (`lenient_headers`, `lenient_chunked_length`, `lenient_optional_lf_after_cr`, `lenient_optional_cr_before_lf`, `lenient_optional_crlf_after_chunk`, `lenient_spaces_after_chunk_size`, `lenient_header_value_relaxed`, ...) as exposing you to "request smuggling attacks" and "cache poisoning attacks" — "USE WITH CAUTION!" ([llhttp](https://github.com/nodejs/llhttp)). Design rule: no lenient mode, ever; reject and close.

#### 1b. HTTP/2 resource attacks
- **Rapid Reset, CVE-2023-44487** (disclosed 2023-10-10; 398M rps at Google): HEADERS+RST_STREAM loops bypass MAX_CONCURRENT_STREAMS because cancelled streams stop counting ([Qualys](https://blog.qualys.com/vulnerabilities-threat-research/2023/10/10/cve-2023-44487-http-2-rapid-reset-attack), *secondary*). Go's fix (CVE-2023-39325, Go 1.20.10/1.21.3, x/net 0.17.0) bounds the number of simultaneously executing handler goroutines to the stream concurrency limit (MaxConcurrentStreams, default 250) and queues new streams ([GHSA](https://github.com/advisories/GHSA-4374-p667-p6c8), [GO-2023-2102](https://pkg.go.dev/vuln/GO-2023-2102)); h2 capped remote resets (RUSTSEC-2023-0034, h2 0.3.17) ([advisory](https://raw.githubusercontent.com/rustsec/advisory-db/main/crates/h2/RUSTSEC-2023-0034.md)).
- **Reset-flood variant**: invalid frames force the server to *emit* resets that queue unboundedly when the client closes its window (h2 RUSTSEC-2024-0003, fixed 0.3.24/0.4.2) ([advisory](https://raw.githubusercontent.com/rustsec/advisory-db/main/crates/h2/RUSTSEC-2024-0003.md)).
- **CONTINUATION flood** (2024-04-03; Nowotarski): HPACK state forces you to decode header fragments even for a request you will reject. Go CVE-2023-45288 (1.21.9/1.22.2, x/net 0.23.0; "sets a limit on the amount of excess header frames we will process before closing a connection") ([GHSA](https://github.com/advisories/GHSA-4v7x-pqxf-cx7m)); Node CVE-2024-27983 (CONTINUATION frames + abrupt close crash the Http2Session destructor) ([Node Apr 2024](https://nodejs.org/en/blog/vulnerability/april-2024-security-releases)); ATS CVE-2024-31309, amphp; h2 RUSTSEC-2024-0332 (0.3.26/0.4.4) ([advisory](https://raw.githubusercontent.com/rustsec/advisory-db/main/crates/h2/RUSTSEC-2024-0332.md)); nghttp2 CVE-2024-28182, httpd CVE-2024-27316, Tomcat CVE-2024-24549 ([Phoenix](https://phoenix.security/http2cve-2024-27316/), *secondary*). Fix: cap total header bytes (incl. Huffman-decoded) per stream and close the connection, not the stream, when exceeded.
- **MadeYouReset, CVE-2025-8671** (2025-08-13; CERT VU#767506, *secondary*): malformed WINDOW_UPDATE/PRIORITY/DATA frames provoke *server-side* RST_STREAM, and "when a stream is reset, it is immediately considered not active, and thus unaccounted for in the active streams counter" ([Netty GHSA-prj3-ccx8-p6x4](https://github.com/advisories/GHSA-prj3-ccx8-p6x4)); Netty CVE-2025-55163, Jetty CVE-2025-5115, Undertow CVE-2025-9784, F5 CVE-2025-54500, swift-nio-http2, Pingora, amphp ([GHSA list](https://github.com/advisories?query=MadeYouReset)). Fix: budget *all* resets per connection regardless of who sent them.
- **HTTP/2 Bomb, CVE-2026-49975** (2026-06-08; CWE-789 excessive allocation / CWE-409 data amplification): HPACK expansion plus a Slowloris-style hold; httpd 2.4.17-2.4.67 affected ([GHSA](https://github.com/advisories/GHSA-262v-g5h9-6mc6)), fixed 2.4.68 / mod_http2 2.0.41; nginx < 1.29.8, IIS, Envoy 1.37.2 and Cloudflare Pingora also affected, nginx 1.29.8 adding `max_headers` ([PoC/README](https://github.com/mrx-arafat/CVE-2026-49975-POC), [3CX](https://www.3cx.com/blog/news/http2-vulnerability-mitigation/), *secondary*). Fix: bound per-connection decoded-header memory *including per-entry overhead* — the attack's 1-byte indexed references evade plain decoded-size limits, which is why nginx's fix is a header-count cap (`max_headers`, default 1000) ([nginx docs source](https://raw.githubusercontent.com/nginx/nginx.org/main/xml/en/docs/http/ngx_http_core_module.xml)) — not frame count.
- **Small stuff that still crashes**: empty DATA frame queueing (h2 RUSTSEC-2026-0258, fixed 0.4.16, 2026-08-17) ([advisory](https://raw.githubusercontent.com/rustsec/advisory-db/main/crates/h2/RUSTSEC-2026-0258.md)); `SETTINGS_MAX_FRAME_SIZE=0` infinite loop in Go's client (CVE-2026-33814, Go 1.25.10/1.26.3, May 2026) ([Red Hat bug](https://bugzilla.redhat.com/show_bug.cgi?id=2467815)); unknown frame types 0x0a-0x0f panicking Go servers (CVE-2026-27141); h2c preface peek ignoring ReadHeaderTimeout (Go CVE-2026-56853) ([KrakenD](https://www.krakend.io/security-advisories/cve-2026-56853/)); Node HTTP/2 ORIGIN-frame OOM CVE-2026-48619, retained headers evading `maxSessionMemory` CVE-2026-56846, data accepted after GOAWAY CVE-2026-48937, nghttp2 re-entrancy UAF CVE-2026-56848 ([Node June 2026](https://nodejs.org/en/blog/vulnerability/june-2026-security-releases), [July 2026](https://nodejs.org/en/blog/vulnerability/july-2026-security-releases)). **Unverified**: "CVE-2026-2219 Go HTTP/2 header smuggling" appears only on one low-quality site with an implausible description; treat as noise until Go's tracker lists it.

#### 1c. Slowloris / slow body, limits
Go's `Server` has no timeouts by default (`ReadTimeout`/`ReadHeaderTimeout`/`WriteTimeout`/`IdleTimeout` zero = none; `DefaultMaxHeaderBytes` = 1 << 20) ([net/http](https://pkg.go.dev/net/http)); nginx defaults are `client_header_timeout`/`client_body_timeout`/`send_timeout` 60s, `keepalive_timeout` 75s, `keepalive_requests` 1000, `large_client_header_buffers 4 8k`, `client_max_body_size 1m`, `max_headers 1000` (since 1.29.8), `lingering_close on` ([nginx docs source](https://raw.githubusercontent.com/nginx/nginx.org/main/xml/en/docs/http/ngx_http_core_module.xml)); hyper caps 100 headers and ~400 KiB of header bytes by default ([hyper Builder](https://docs.rs/hyper/latest/hyper/server/conn/http1/struct.Builder.html)). Fern's 8 KiB/1 MiB caps are in range; what is missing is a header *timeout*, a body *rate* floor, per-IP connection caps and a hard header-count cap.

#### 1d. Decompression bombs
undici's fetch had an unbounded Content-Encoding chain (CVE-2026-22036, fixed 6.23.0/7.18.2; layer cap only) ([GHSA](https://github.com/advisories/GHSA-g9mf-h72j-4rw9)) and then unbounded *output* (CVE-2026-84890, 2026-09-04, fixed 7.29.1/8.10.2; now capped at 5 layers and a 64 MiB default `maxSize`) ([undici GHSA](https://github.com/nodejs/undici/security/advisories/GHSA-3xpg-4rpp-hhhm)). Go's Transport transparently gunzips with no limit (`DisableCompression` is the only knob) ([net/http](https://pkg.go.dev/net/http)). RFC 9659 (Sept 2024) makes the 8 MiB zstd window a requirement for Content-Encoding ([RFC 9659](https://www.rfc-editor.org/info/rfc9659/), *secondary*). Design: cap chain depth, output bytes and ratio; never decompress request bodies by default.

#### 1e. Hop-by-hop, Host, path
`Connection: close, X-Forwarded-For` makes compliant proxies strip a header they did not add (Davison 2019) ([HackTricks mirror](https://raw.githubusercontent.com/b4rdia/HackTricks/master/pentesting-web/abusing-hop-by-hop-headers.md)); RFC 9110 §7.6.1 requires intermediaries to remove listed fields, so a server must never treat presence/absence of forwarded headers as trust. Host: 9112 §3.2 mandates 400 for missing, duplicate or invalid Host, and absolute-form authority overrides Host; applications must never build URLs from Host (password-reset poisoning) ([PortSwigger Academy](https://portswigger.net/web-security/host-header), *secondary*). Path: httpd CVE-2021-41773/42013 came from an `ap_normalize_path` rewrite that mishandled `%2e` and double encoding ([Qualys](https://blog.qualys.com/vulnerabilities-threat-research/2021/10/27/apache-http-server-path-traversal-remote-code-execution-cve-2021-41773-cve-2021-42013)): decode once, remove dot segments (RFC 3986 §5.2.4), reject NUL and encoded `/`, then check the prefix on the *resolved* filesystem path.

#### 1f. Vendor patterns 2024-2026
nginx: 7 HTTP/3 memory-safety bugs in 2024-2026 plus a 2026 "HTTP/2 request injection in proxy module" (CVE-2026-42926) ([advisories source](https://raw.githubusercontent.com/nginx/nginx.org/main/xml/en/security_advisories.xml)). Go: proxy bypass via IPv6 zone IDs in NO_PROXY (CVE-2025-22870, x/net 0.36.0, Go 1.23.7/1.24.1) ([issue](https://github.com/golang/go/issues/71984), [GO-2025-3503](https://pkg.go.dev/vuln/GO-2025-3503)) and Proxy-Authorization/Proxy-Authenticate surviving cross-origin redirects (CVE-2025-4673) ([issue](https://github.com/golang/go/issues/73816)). ### 2. Minimal-but-correct HTTP/1.1 (RFC 9110/9112)
- Framing: implement §6.3 exactly (above); chunked with extensions ignored, trailers parsed, chunk-size overflow rejected; "chunked" applied at most once; trailers allowed only for fields the sender declared safe.
- Persistence (§9.3): HTTP/1.1 persists unless `Connection: close`; honour HTTP/1.0 `keep-alive` only as origin, never as proxy; pipelined responses "MUST [be sent] in the same order that the requests were received"; tear-down via half-close then drain (§9.6) — this is what fixes today's Connection: close RST data loss.
- Expect (9110 §10.1.1): send 100 only to HTTP/1.1, 417 for unknown expectations, and treat the request identically whether or not 100 was sent (the 2025 desyncs live here).
- No-body rules: HEAD, 1xx, 204, 304 end at the blank line; MUST NOT send Transfer-Encoding on 1xx/204 or 2xx-to-CONNECT; MUST NOT send TE to an HTTP/1.0 request (§6.1).
- Date: origin with a clock MUST send it; MAY on 1xx/5xx (9110 §6.6.1) — TechEmpower verifies it and permits re-rendering once per second ([TFB wiki](https://github.com/TechEmpower/FrameworkBenchmarks/wiki/Project-Information-Framework-Tests-Overview)).
- Targets: MUST accept absolute-form and prefer its authority; 414 for over-long targets, 431 for headers, 8000-octet request-line minimum (§3.3); reject whitespace between start-line and first field.
- HTTP/1.0 clients: no chunked, no 1xx, Connection: close unless keep-alive honoured.
- Case: field names case-insensitive; method and header *values* not.
- Range (9110 §14): MAY ignore; MAY reject >2 overlapping or many small unordered ranges; 416 with Content-Range.
- Upgrade (9110 §7.8): ignore in HTTP/1.0; 101 must carry Upgrade + Connection: upgrade; h2c Upgrade is deprecated by RFC 9113 §3.1 — only prior-knowledge cleartext h2 (§3.3) is worth implementing ([Go deprecation issue](https://github.com/golang/go/issues/72039)). WebSocket: client MUST mask, server MUST close on unmasked frames, server MUST NOT mask (RFC 6455 §5.1) ([rfc-editor](https://www.rfc-editor.org/rfc/rfc6455.html), *secondary*).
- Via/Forwarded: proxies MUST add Via (9110 §7.6.3); `Forwarded` (RFC 7239) and X-Forwarded-* are only trustworthy from a configured proxy list.

### 4. Client-side security
- **TLS**: verify by default; Node's 2026 record (session-reuse skipping hostname checks, Unicode-dot wildcards, SNI case) says hostname verification must be re-run on every reused session and on the *normalised* ASCII host.
- **Redirects**: RFC 9110 §15.4 says the agent SHOULD resend after removing implementation-generated and proxy-specific fields (Proxy-Authorization), origin-specific fields (Host), cache validators, and resource-specific fields "including Referer, Origin, Authorization, and Cookie" *(secondary)*; Fetch dropped Authorization on cross-origin redirect (merged 2022-11-25) ([whatwg PR](https://github.com/whatwg/fetch/pull/1544)); Go forwards Authorization/WWW-Authenticate/Cookie only to the same domain or a subdomain and caps at 10 hops ([net/http](https://pkg.go.dev/net/http)); Go still leaked Proxy-Authorization until CVE-2025-4673. Same-origin means scheme+host+port; drop on 303 body rewrite as well.
- **Cookies** (draft-ietf-httpbis-rfc6265bis): name+value ≤ 4096 B, attribute ≤ 1024 B, lifetime ≤ 400 days, ≥50/domain and ≥3000 total storage, `__Host-` needs Secure + Path=/ + no Domain, `__Secure-` needs Secure, unknown SameSite → Lax, reject Domain on public suffixes, longer path then earlier creation ordering, reject control/non-ASCII ([httpwg source](https://raw.githubusercontent.com/httpwg/http-extensions/main/draft-ietf-httpbis-rfc6265bis.md)).
- **SSRF**: block loopback, RFC 1918/4193, link-local incl. 169.254.169.254 and AWS `fd00:ec2::254`, IPv4-mapped IPv6 and decimal/octal forms, and check the *dialled* IP (post-DNS) to defeat rebinding — exactly the check Deno missed (GHSA-cpgj-f7g3-2pp2) ([ssrf lib](https://github.com/cplieger/ssrf), [SANS](https://www.sans.org/blog/cloud-instance-metadata-services-imds-)). Keep the block list as a Platform capability so handlers cannot opt out silently.
- **Proxy env**: curl reads only lowercase `http_proxy` — uppercase `HTTP_PROXY` is ignored since 7.19.4 (2009) (unverified — the version/date could not be confirmed; curl's docs give only the reason) because CGI maps a `Proxy:` request header to it (httpoxy, 2016) ([everything-curl source](https://raw.githubusercontent.com/curl/everything-curl/master/usingcurl/proxies/env.md), [curl manpage source](https://raw.githubusercontent.com/curl/curl/master/docs/cmdline-opts/_ENVIRONMENT.md), [httpoxy](https://httpoxy.org/), *secondary*); Go prefers lowercase, errors on HTTP_PROXY when `REQUEST_METHOD` is set (CGI), never proxies localhost/loopback, parses NO_PROXY as domains/leading-dot/CIDR/port/`*` ([httpproxy](https://pkg.go.dev/golang.org/x/net/http/httpproxy)) — and still had the IPv6-zone bypass (CVE-2025-22870, x/net 0.36.0).
- **Compression**: browsers send `gzip, deflate, br, zstd` over HTTPS only (Chrome 123, Firefox 126, 2024) ([Chrome status](https://chromestatus.com/feature/6186023867908096)); a client should advertise only what it bounds, enforce the 8 MiB zstd window, and cap depth/output as in §1d.

### 1. Timeouts and limits taxonomy

| Stack | Header read | Body / whole request | Response write | Keep-alive idle | Header cap | Body cap |
|---|---|---|---|---|---|---|
| Go `net/http` go1.27 ([pkg.go.dev](https://pkg.go.dev/net/http#Server)) | `ReadHeaderTimeout` 0 → falls back to `ReadTimeout` | `ReadTimeout` 0 | `WriteTimeout` 0 | `IdleTimeout` 0 → `ReadTimeout` → **none** | `MaxHeaderBytes` 1 MiB | none |
| hyper 1.x http1 ([source](https://github.com/hyperium/hyper/blob/master/src/server/conn/http1.rs)) | `header_read_timeout` 30 s, **only if a `Timer` is set; panics if configured without one** | – | – | keep-alive on, no idle timeout | `max_headers` 100, `max_buf_size` ~400 KB | – |
| nginx ([core module](https://raw.githubusercontent.com/nginx/nginx.org/main/xml/en/docs/http/ngx_http_core_module.xml)) | `client_header_timeout` 60 s | `client_body_timeout` 60 s (between reads) | `send_timeout` 60 s (between writes) | `keepalive_timeout` 75 s, `keepalive_requests` 1000, `keepalive_time` 1 h | `client_header_buffer_size` 1k, `large_client_header_buffers` 4 8k | `client_max_body_size` 1m |
| Bun.serve ([docs](https://github.com/oven-sh/bun/blob/main/docs/runtime/http/server.mdx)) | `idleTimeout` 10 s (max 255, 0 disables) — one knob for everything | same | same | same | ? | `maxRequestBodySize` 128 MB ([ref](https://bun.com/reference/bun/Serve/HostnamePortServeOptions/maxRequestBodySize)) |
| Kestrel ([source](https://github.com/dotnet/aspnetcore/blob/main/src/Servers/Kestrel/Core/src/KestrelServerLimits.cs)) | `RequestHeadersTimeout` 30 s | `MinRequestBodyDataRate` 240 B/s after 5 s grace | `MinResponseDataRate` 240 B/s after 5 s grace | `KeepAliveTimeout` 130 s | 32 KB total, 100 headers, 8 KB request line | 30,000,000 B |
| Node.js v26 ([http.md](https://raw.githubusercontent.com/nodejs/node/main/doc/api/http.md)) | `headersTimeout` = min(`requestTimeout`, 60 s) | `requestTimeout` 300 s | – | `keepAliveTimeout` 65 s | `maxHeadersCount` 1000 | none |

Which are best considered, and why:

- **Kestrel's set is the most complete taxonomy**: header phase bounded by time, body and response phases bounded by *minimum data rate* (defeats slowloris without capping upload duration), keep-alive bounded separately, and independent caps on line, header total, header count and body. That is the shape to copy.
- **Go's all-zero defaults are the canonical anti-pattern**: with nothing set, keep-alive connections never expire, because `IdleTimeout` falls back to `ReadTimeout` which is 0 ([pkg.go.dev](https://pkg.go.dev/net/http#Server)). `ReadTimeout` also covers body reads inside the handler, so it is the wrong tool for streaming uploads; the community consensus is a small `ReadHeaderTimeout` plus `IdleTimeout` and no `ReadTimeout`.
- **hyper's default is a trap**: the 30 s exists but is inert until a timer is installed; hyper-util's auto builder says "do not depend on that" ([hyper-util source](https://github.com/hyperium/hyper-util/blob/master/src/server/conn/auto/mod.rs)); linkerd and others shipped proxies with no head-read timeout as a result ([linkerd#14147](https://github.com/linkerd/linkerd2/issues/14147)).
- **Bun's single 10 s `idleTimeout` breaks SSE/streaming by default** ([bun#13712](https://github.com/oven-sh/bun/issues/13712), [bun#27479](https://github.com/oven-sh/bun/issues/27479)); `server.timeout(req, 0)` is the per-request escape hatch.
- **nginx's separation of between-operation timeouts** (header/body/send) rather than whole-request budgets is why 60 s defaults work for large transfers; `lingering_close on` (30 s / 5 s) and `reset_timedout_connection off` are the sane close-side defaults.
- **The upstream-proxy rule**: the server's keep-alive idle timeout must be *longer* than every proxy in front of it, or the proxy reuses a connection the server is closing → 502 ([AWS re:Post](https://repost.aws/knowledge-center/elb-alb-troubleshoot-502-errors)). Node raised `keepAliveTimeout` from 5 s to 65 s (ALB default 60 s); Kestrel's 130 s and nginx's 75 s clear the same bar.
- **Cloudflare's numbers** ([connection-limits](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/fundamentals/reference/connection-limits.mdx)): proxy read timeout 125 s (error 524; older docs and blogs say 100 s *(unverified)*), proxy write 30 s, proxy idle 900 s, client keep-alive/HTTP2 idle 400 s, request/response headers 128 KB, URL 16 KB. Guidance ([error-524](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524.mdx)): poll for long work, move it to an unproxied subdomain, Enterprise can raise to 6,000 s.
- Connection limiting: nginx `limit_conn_zone $binary_remote_addr` + `limit_conn` returns 503 by default ([limit_conn](https://github.com/nginx/nginx.org/blob/main/xml/en/docs/http/ngx_http_limit_conn_module.xml)); Kestrel `MaxConcurrentConnections` null = unlimited.

### 2. Graceful shutdown and drain

- **Go `Shutdown(ctx)`**: closes listeners, closes idle connections, polls until active ones go idle or ctx expires; hijacked/WebSocket connections are not tracked; `Serve` returns `ErrServerClosed` ([pkg.go.dev](https://pkg.go.dev/net/http#Server.Shutdown)). `SetKeepAlivesEnabled(false)` makes connections close after their current request.
- **hyper 1.x**: `hyper_util::server::graceful::GracefulShutdown` watches each connection; the guide selects over accept-loop and signal, drops the listener, calls `shutdown()` and races it against a 10 s sleep, then exits ([guide source](https://github.com/hyperium/hyperium.github.io/blob/master/_stable/server/graceful-shutdown.md)).
- **Kestrel**: `StopAsync` closes port bindings, sends HTTP/2/3 GOAWAY, lets HTTP/1.1 loops finish their request, waits `HostOptions.ShutdownTimeout` (30 s) then aborts ([dotnet/docs#34879](https://github.com/dotnet/docs/issues/34879)).
- **Envoy**: `--drain-time-s` 600 s default with `gradual` strategy (percentage of requests "encouraged" to drain rises to 100%), `--parent-shutdown-time-s` 900 s ([cli.rst](https://github.com/envoyproxy/envoy/blob/main/docs/root/operations/cli.rst)). Drain = HTTP/1 gets `Connection: close`, HTTP/2 gets GOAWAY, `/healthcheck/fail` flips health checks first ([draining.rst](https://github.com/envoyproxy/envoy/blob/main/docs/root/intro/arch_overview/operations/draining.rst)). Hot restart passes SO_REUSEPORT sockets by worker index over a Unix socket; existing connections are never transferred, only drained ([hot_restart.rst](https://github.com/envoyproxy/envoy/blob/main/docs/root/intro/arch_overview/operations/hot_restart.rst)).
- **nginx binary upgrade**: USR2 forks a new master (old pid → `.oldbin`), both serve, WINCH drains old workers, QUIT retires old master; rollback is HUP old + QUIT new ([control.xml](https://raw.githubusercontent.com/nginx/nginx.org/main/xml/en/docs/control.xml)).
- **SO_REUSEPORT trap**: closing one listener in a reuseport group *resets* connections still in its accept queue (the kernel docs say in-flight handshakes and accept-queue sockets are "aborted") unless `net.ipv4.tcp_migrate_req=1` (Linux 5.14) ([LWN](https://lwn.net/Articles/853637/), [ip-sysctl.rst](https://github.com/torvalds/linux/blob/master/Documentation/networking/ip-sysctl.rst)). fd inheritance (Cloudflare's [tableflip](https://github.com/cloudflare/tableflip): SIGHUP, child calls `Ready()`, one upgrade at a time) avoids this.
- **systemd socket activation**: fds arrive at fd 3+ with `LISTEN_PID`/`LISTEN_FDS`/`LISTEN_FDNAMES`; `sd_listen_fds` sets CLOEXEC; the fd store (`FDSTORE=1`) keeps sockets across service restarts ([sd_listen_fds.xml](https://github.com/systemd/systemd/blob/main/man/sd_listen_fds.xml)).
- **Kubernetes**: `terminationGracePeriodSeconds` 30 s; endpoint removal and the preStop hook run *in parallel*, so SIGTERM can arrive before load balancers stop sending; SIGKILL when grace expires (preStop gets a 2 s extension); terminating endpoints report `ready: false` ([pod-lifecycle.md](https://github.com/kubernetes/website/blob/main/content/en/docs/concepts/workloads/pods/pod-lifecycle.md)). The native `sleep` preStop action went GA in 1.34 ([KEP-3960](https://github.com/kubernetes/enhancements/blob/master/keps/sig-node/3960-pod-lifecycle-sleep-action/README.md)).

**Minimal correct behaviour for a static-binary server**: (1) handle SIGTERM/SIGINT; (2) keep accepting for a short configurable delay (or document `preStop: sleep`) because routing converges after SIGTERM; (3) fail the readiness/health endpoint immediately; (4) close the listener; (5) stop keep-alive (send `Connection: close` on next response; GOAWAY if ever h2); (6) wait for in-flight requests up to a bounded deadline (10–30 s is the industry range), then exit non-zero if any were aborted; (7) accept inherited fds (`LISTEN_FDS`) so systemd/tableflip-style restarts need no reuseport dance.

### 3. Observability

- **OTel HTTP metrics** ([http-metrics.md](https://github.com/open-telemetry/semantic-conventions/blob/main/docs/http/http-metrics.md)): `http.server.request.duration` is *stable*, a histogram in **seconds**, buckets `[0.005 … 10]`; required `http.request.method`, `url.scheme`; conditionally `http.response.status_code`, `http.route`, `error.type`, `network.protocol.name`; `network.protocol.version` recommended; `server.address/port` opt-in to avoid Host-header cardinality. `http.server.active_requests`, `request.body.size`, `response.body.size` are still *development*. ### 4. Framework ergonomics people copy

- **Routing**: Go 1.22 `ServeMux` patterns `[METHOD ][HOST]/[PATH]` with `{name}`, `{name...}`, `{$}`; most-specific wins, ambiguous registrations panic, GET also matches HEAD, `r.PathValue` ([pkg.go.dev](https://pkg.go.dev/net/http#ServeMux)). matchit is a radix trie with `{id}`, `{*rest}`, `{{`/`}}` escapes, ~2.4 µs over 130 routes ([repo](https://github.com/ibraheemdev/matchit)); axum 0.8 (2025-01-01) adopted that syntax and panics on the old `:id` ([release](https://github.com/tokio-rs/axum/releases/tag/axum-v0.8.0)). - **Middleware**: Tower `Service { poll_ready, call }` + `Layer::layer(inner) -> Service` — middleware is a function from Service to Service, with backpressure ([tokio blog](https://github.com/tokio-rs/website/blob/master/content/blog/2021-05-14-inventing-the-service-trait.md)). Koa/Hono onion: code before `await next()` runs inbound, after it outbound ([Koa guide](https://github.com/koajs/koa/blob/master/docs/guide.md), [Hono](https://github.com/honojs/website/blob/main/docs/guides/middleware.md)).
- **Typed extraction**: axum splits `FromRequestParts` (any position) from `FromRequest` (consumes body, must be last); `Json` rejections map to 400/415/422 ([extract.md](https://github.com/tokio-rs/axum/blob/main/axum/src/docs/extract.md)). - **SSE/streaming**: axum `Sse` sets `text/event-stream` + `cache-control: no-cache`, keep-alive comment every 15 s when enabled ([sse.rs](https://github.com/tokio-rs/axum/blob/main/axum/src/response/sse.rs)); Go uses `http.ResponseController.Flush` (1.20) through middleware wrappers; Hono `streamSSE` ([sse.ts](https://github.com/honojs/hono/blob/main/src/helper/streaming/sse.ts)). - **Compression defaults, 2026**: nginx `gzip off` (level 1, `text/html` only, min 20 B when on) ([gzip module](https://raw.githubusercontent.com/nginx/nginx.org/main/xml/en/docs/http/ngx_http_gzip_module.xml)); Caddy compresses only with an `encode` directive, which defaults to zstd (preferred) + gzip, min 512 B ([encode.md](https://github.com/caddyserver/website/blob/master/src/docs/markdown/caddyfile/directives/encode.md)); tower-http is opt-in, skipping <32 B, gRPC, non-SVG images and `text/event-stream` ([predicate.rs](https://github.com/tower-rs/tower-http/blob/main/tower-http/src/compression/predicate.rs)); Cloudflare defaults by plan — Free: Zstandard, Pro/Business: Brotli, Enterprise: gzip ([compression.mdx](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/speed/optimization/content/compression.mdx)). zstd is accepted by Chrome 123+, Firefox 126+, Safari 26 ([caniuse](https://caniuse.com/zstd)). ### 2. Cold start and instantiation

- **wasmtime:** the fast-instantiation levers are precompile, `InstancePre`, pooling allocator, copy-on-write heap images, Wizer ([doc](https://raw.githubusercontent.com/bytecodealliance/wasmtime/main/docs/examples-fast-instantiation.md)). The memfd/CoW pooling PR (Jan–Feb 2022) measured ~24 µs per instantiate-and-call single-threaded, ~773 ns raw instance creation for SpiderMonkey.wasm ([PR #3697](https://github.com/bytecodealliance/wasmtime/pull/3697)); the Wasmtime 1.0 post quotes 2 ms → 5 µs (400×) **(unverified)** ([article](https://bytecodealliance.org/articles/wasmtime-10-performance)). Wizer: 1.35–6× faster init ([wizer](https://github.com/bytecodealliance/wizer)).
- **Fastly:** ~35 µs cold start marketing figure; Lucet (2019) <50 µs with a few KB overhead vs V8 ~5 ms/tens of MB **(unverified; blocked)** ([Fastly](https://www.fastly.com/blog/how-compute-edge-is-tackling-the-most-frustrating-aspects-of-serverless), [Lucet](https://www.fastly.com/blog/lucet-performance-and-lifecycle)).
- **Cloudflare:** 5 ms isolate start hidden behind the TLS ClientHello (2020); "shard and conquer" (Sept 2025) took enterprise warm rate 99.9% → 99.99% and cut replicated-Worker memory >99% **(unverified)** ([2020](https://blog.cloudflare.com/eliminating-cold-starts-with-cloudflare-workers/), [InfoQ](https://www.infoq.com/news/2025/10/workers-shard-conquer-cold-start)).
- **Lambda:** Firecracker spec: ≤125 ms from InstanceStart to guest `/sbin/init`, ≤5 MiB VMM overhead ([SPECIFICATION.md](https://raw.githubusercontent.com/firecracker-microvm/firecracker/main/SPECIFICATION.md)). Minimal Rust on `provided.al2023`: 12–22 ms p50/p99 **(unverified)** ([rustify](https://rustify.rs/articles/rust-aws-lambda-serverless-guide-2026)); daily data at [lambda-perf](https://github.com/maxday/lambda-perf). Custom runtime = a `bootstrap` binary polling `AWS_LAMBDA_RUNTIME_API` ([rust runtime](https://github.com/aws/aws-lambda-rust-runtime)). SnapStart: Java 11+, Python 3.12+, .NET 8+, restore ~100–200 ms, **not** OS-only runtimes **(unverified)** ([docs](https://docs.aws.amazon.com/lambda/latest/dg/snapstart.html)). Lambda Web Adapter v1.1.0 is an extension that polls `127.0.0.1:8080` every 10 ms until 100–499, then forwards events as HTTP; supports response streaming, SIGTERM, SnapStart hooks and Managed Instances multi-concurrency ([LWA](https://github.com/aws/aws-lambda-web-adapter), [design](https://github.com/aws/aws-lambda-web-adapter/blob/main/docs/design.md)). Managed Instances (re:Invent Dec 2025) send up to 64 concurrent requests per vCPU to one environment ([re:Post](https://repost.aws/articles/AR6dW5ie4oSFmpkrIoKcI3cg/re-invent-2025-lambda-managed-instances-ec2-power-with-serverless-simplicity)).
- **Fly.io:** Firecracker Machines "boot in milliseconds"; suspend/resume "hundreds of milliseconds" vs seconds for stop/start **(unverified)** ([docs](https://fly.io/docs/reference/suspend-resume/)).
- **Unikraft:** guest boot tens–hundreds of µs, <1 ms on Firecracker; Unikraft Cloud ~4 ms first VM, ~14 ms at the 5,000th; Alpine on Firecracker ~330 ms **(unverified)** ([perf](https://unikraft.org/docs/concepts/performance), [blog](https://unikraft.cloud/blog/death-to-cold-starts/)).
- **Native process:** Linux `posix_spawn` ≈170 µs regardless of binary (EdgeOS paper) **(unverified)** ([arXiv 1901.01222](https://arxiv.org/pdf/1901.01222)). A static no-libc Fern binary sits at the floor of this: exec + page faults, tens to a few hundred µs.

### 3. WinterTC

WinterCG became Ecma TC55 (Jan 2025); the Minimum Common Web API is ECMA-429 (adopted Dec 2025 **(unverified)**) covering `fetch`, `Request`, `Response`, `Headers`, `URL`, `URLPattern`, `crypto.subtle`, the streams trio, encoders and timers ([WinterTC55](https://github.com/WinterTC55), [w3c](https://www.w3.org/blog/2025/collaborating-across-w3c-and-ecma-for-web-interoperable-server-runtimes-through-wintertc/)). The `export default { fetch(req, env, ctx) }` shape is convention, not spec; a separate fetch-workstream repo discusses server-side Fetch needs. Hono needs only `(Request) => Response` and runs on Workers, Deno, Bun, Fastly, Lambda, Node (adapter) and wasi:http ([web-standard.md](https://raw.githubusercontent.com/honojs/website/main/docs/concepts/web-standard.md)). For a non-JS language, matching the API buys nothing at link level (Hono cannot call Fern); what matters is matching the *semantics* hosts assume: streaming bodies both ways, case-insensitive header multimap, an abort/deadline signal, `waitUntil`, and a `(request, env, ctx) -> response` handler. Own typed API is fine; keep those five semantics.

### 4. Proxies

- **nginx 1.29.7 (March 2026):** upstream default became HTTP/1.1 with keepalive on (previously 1.0 + `Connection: close`) ([release](https://github.com/nginx/nginx/releases/tag/release-1.29.7)). nginx still proxies upstream over HTTP/1.x only (grpc_pass aside).
- **Caddy:** transport `versions` default `1.1 2` (or `h2c 2` for `h2c://`); keepalive 2 m, 32 idle conns/host; "connection reset by peer" → 502 for non-idempotent requests if the upstream's keepalive timeout is shorter than Caddy's; sets `X-Forwarded-For/Proto/Host`, ignores incoming ones unless `trusted_proxies`; active health `health_interval` 30 s ([reverse_proxy.md](https://raw.githubusercontent.com/caddyserver/website/master/src/docs/markdown/caddyfile/directives/reverse_proxy.md)).
- **Envoy:** HTTP health checks expect 200 over persistent connections; `x-envoy-immediate-health-check-fail` ejects a host ([health_checking.rst](https://raw.githubusercontent.com/envoyproxy/envoy/main/docs/root/intro/arch_overview/upstream/health_checking.rst)); drain = `Connection: close` on H1, GOAWAY on H2 ([draining.rst](https://raw.githubusercontent.com/envoyproxy/envoy/main/docs/root/intro/arch_overview/operations/draining.rst)); XFF/XFP/x-request-id handling, no RFC 7239 `Forwarded` ([headers.rst](https://raw.githubusercontent.com/envoyproxy/envoy/main/docs/root/configuration/http/http_conn_man/headers.rst)); PROXY v1/v2 listener filter with TLV metadata and an upstream PROXY transport socket ([listener](https://raw.githubusercontent.com/envoyproxy/envoy/main/docs/root/configuration/listeners/listener_filters/proxy_protocol.rst), [upstream](https://raw.githubusercontent.com/envoyproxy/envoy/main/api/envoy/extensions/transport_sockets/proxy_protocol/v3/upstream_proxy_protocol.proto)); ext_proc is a bidirectional gRPC stream, so an ext_proc server must speak h2 ([ext_proc](https://raw.githubusercontent.com/envoyproxy/envoy/main/docs/root/configuration/http/http_filters/ext_proc_filter.rst)).
- **HAProxy:** `http-reuse never|safe(default)|aggressive|always`, `check-reuse-pool`, `send-proxy-v2`, admin-socket `state drain` **(unverified)** ([blog](https://www.haproxy.com/blog/http-keep-alive-pipelining-multiplexing-and-connection-pooling)). PROXY spec rev 2026/04/27; v2 = 12-byte signature, AF_INET/INET6/UNIX, TLVs incl. `PP2_TYPE_SSL` 0x20, `PP2_TYPE_UNIQUE_ID` 0x05 ([proxy-protocol.txt](https://raw.githubusercontent.com/haproxy/haproxy/master/doc/proxy-protocol.txt)).
- **Pingora/Oxy:** Pingora pools upstream connections keyed by peer (ip:port, scheme, SNI, cert settings); errors invalidate; `idle_timeout=0` disables ([pooling.md](https://github.com/cloudflare/pingora/blob/main/docs/user_guide/pooling.md)); Cloudflare reports reuse 87.1% → 99.92% (160× fewer origin connections) and 70% CPU / 67% memory savings **(unverified)** ([blog](https://blog.cloudflare.com/how-we-built-pingora-the-proxy-that-connects-cloudflare-to-the-internet/)); Oxy is internal, L3–L7 ([Oxy](https://blog.cloudflare.com/introducing-oxy/)).

**What an upstream must do:** HTTP/1.1 keep-alive with an idle timeout longer than the proxy's (Caddy 2 m); correct `Content-Length` or chunked framing; a 200 health endpoint; graceful drain on SIGTERM (fail health, finish in-flight, close idle); honour `X-Forwarded-For/Proto` only from trusted proxies; optionally PROXY v2 and h2c. **TLS is not required** behind any of these; **HTTP/2 is only required for gRPC/ext_proc**. Fern's current `Connection: close` on every response defeats every pool above.

### 5. Bindings beyond request/response

- **Workers:** `env` bindings (KV, D1, R2, Queues, DO, secrets); extra entrypoints `scheduled`, `queue`; `ctx.waitUntil` runs ≤30 s after the response, shared per request; cron/DO/queue handlers 15 min ([context](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/workers/runtime-apis/context.mdx), [limits](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/workers/platform/limits.mdx)). DO WebSocket hibernation: `acceptWebSocket`, `webSocketMessage/Close` callbacks, `getWebSockets`, `serializeAttachment` (≤16,384 bytes per docs), auto-pong, no GB-s while evicted ([websockets.mdx](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/durable-objects/best-practices/websockets.mdx)).
- **Spin:** triggers HTTP/Redis/cron (plugin) ([triggers.md](https://raw.githubusercontent.com/spinframework/spin-docs/main/content/v3/triggers.md)); KV granted per component via `key_value_stores = ["default"]` ([kv](https://raw.githubusercontent.com/spinframework/spin-docs/main/content/v3/kv-store-api-guide.md)); variables/secrets via `get(name)` with env/Vault/Azure Key Vault providers ([variables.md](https://raw.githubusercontent.com/spinframework/spin-docs/main/content/v3/variables.md)); SIP-016 inbound WebSockets uses tokens and fresh instances per frame batch ([SIP-016](https://raw.githubusercontent.com/spinframework/spin/main/docs/content/sips/016-inbound-websockets.md)). wasmCloud ships wasi:keyvalue/blobstore/config/logging plus async `wasmcloud:messaging` 0.3.0; wasi-keyvalue is Phase 2 ([wasi-keyvalue](https://github.com/WebAssembly/wasi-keyvalue)).
- **Roc basic-webserver:** app exports `init!`/`respond!`/`shutdown!`; host owns timers, backpressure, cancellation, compression and HTTP/1.1+2 framing; bodies stream in bounded, responses are whole values; pooled outbound HTTP and SQLite; no blocking I/O in user code ([README](https://github.com/roc-lang/basic-webserver/blob/main/README.md)).
- **Lambda:** env (`_HANDLER`, `AWS_LAMBDA_RUNTIME_API`), Runtime API next/response loop, Extensions API for INVOKE/SHUTDOWN, secrets via Secrets Manager/Parameter Store extensions ([runtimes-api](https://docs.aws.amazon.com/lambda/latest/dg/runtimes-api.html)).

**Seam vs library for Fern:** language/Platform-bag seams: deadline+cancel (maps to `with_deadline`, AbortSignal, `Lambda-Runtime-Deadline-Ms`), background work (`waitUntil`), outbound HTTP (capability-gated like `allowed_outbound_hosts`), config/secrets `get`, KV/blobstore as host interfaces, WebSocket accept/hibernate (host-owned state). Libraries: routers, cron/queue handlers (just additional exported entrypoints), DO-style actors (over KV + host single-writer guarantee). TLS and HTTP/2 termination: leave to the proxy.
