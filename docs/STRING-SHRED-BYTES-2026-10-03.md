# Raw overwrite buffers for shred

`shred` keeps random-source chunks, generated bytes, repeating patterns and
partial writes in byte arrays. Short source reads accumulate in a builder;
pattern construction doubles byte ranges. Random and constant-byte passes
use GNU's 65,536-byte boundary, preserving exactly what is written before
source exhaustion. Three-byte patterns retain their aligned 61,440-byte block.

The reproduced builder compiler passes 71 utility cases on Darwin,
including source exhaustion and multiple files. Successful runs and the
tested source-exhaustion exits have balanced allocation censuses. Tests
compile the actual private pattern functions and verify their bytes on
Darwin, core WebAssembly, component WebAssembly and the interpreter. Native
and core executions require balanced censuses; component execution checks
behavior because its entrypoint does not report a census. The full utility
requires chmod capabilities unavailable on WASI. Compiler reproduction is
recorded in [the builder report](STRING-BYTE-BUILDER-MAPS-2026-10-03.md).

Built with the same compiler, code falls from 112,408 to 112,392 bytes.
Unwind data grows from 15,260 to 15,524 bytes; static data remains 8,888
bytes and the file remains 149,489 bytes. The changed reader, builder and
write paths account for the code and unwind changes. No size baseline changes.

Linux raw-byte checks, primary target and pattern checks, the existing GNU
corpus, primary parity, the full unit suite and all lint checks pass. The
Darwin raw-byte and pattern checks pass. Its existing corpus has the same
six terminal-device failures as the unchanged parent: terminal, sized,
exact, zero-pass, quiet and terminal-then-file. The existing Darwin exception
list is unchanged; this change does not claim full Darwin terminal parity.

Native arm64 Darwin measurements use GNU 9.12 and uutils 0.12.0.
The 8,192-byte pilot precedes the same workloads at 8,388,608 bytes.
Only input size changes. Each run operates on a dedicated temporary
target; all implementations must match GNU status, stdout, stderr and
final file bytes. Two warmups precede seven alternating samples. RSS is
measured separately, with other compiler and container jobs idle.

Raw-source copying improves from 5.312 to 4.905 ms with disjoint ranges.
The other timing ranges overlap. Raw-source peak RSS falls, but the
other three workloads use more sampled memory with byte pattern
builders. The migration preserves byte semantics without claiming
universal speed or memory improvements. GNU and uutils match at both
scales in every workload.
