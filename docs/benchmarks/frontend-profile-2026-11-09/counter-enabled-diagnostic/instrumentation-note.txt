The native frontend harness uses __heap_alloc_count and __heap_bump_bytes. These enable allocation-statistics code and can disable allocator fast paths. Retain both native profiles as counter-enabled diagnostics, not counter-free production profiles. No source optimization follows from their allocator attribution. A separate counter-free harness retains the same loop count, corpus, checksum, producer, and library source. Go CPU profiles do not use these Fern intrinsics.
