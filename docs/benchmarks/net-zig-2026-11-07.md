# The Zig hello servers join the nightly, 2026-11-07

#12887 slice 3. The issue names http.zig and zap as the fastest Zig
HTTP/1.1 servers, from the zig-bd benchmark, and asks for both on the
nightly. `scripts/net-bench` now builds and loads them beside the Fern,
Go, hyper and h2o hello servers. Their rows are `net/httpz/*` and
`net/zap/*`.

## The two servers

`scripts/net-bench.d/httpzhello` is http.zig at commit `9b14af9`, the
head of its `zig-0.16.0` branch. It runs one I/O worker thread and one
handler thread per core. Its connection cap is the 16,384 the Fern hello
sets. The handler sets `res.body = "hello"`.

`scripts/net-bench.d/zaphello` is zap at commit `b12c07d`, the last
commit of its master branch. The tagged release 0.10.6 does not build on
Zig 0.16.0, and master does. It runs one facil.io worker process per
core with one thread each. That is facil.io's reactor per process, the
shape the Fern server forks. The handler calls `r.sendBody("hello")`.

Zap's maintainer archived the repository on 2026-09-06 and points at Baz
as its successor. The nightly keeps zap because it is the server the
field measured. A swap to Baz is a later decision.

Each `build.zig.zon` pins its server to a GitHub archive of the commit,
with the hash Zig computed for that tree. Zig 0.16.0 builds both
`ReleaseFast`. `mise.net-nightly.toml` pins that Zig beside the Rust
toolchain. A missing `zig` fails `scripts/net-bench` as a missing `cargo`
does.

## Measured on this box

A 4-core container, with nothing else running. The Fern hello runs four
workers, and the two Zig servers run as above. oha loads each server
closed-loop for 5 s at each connection count. The helpers of
`scripts/net-lib` start and read the servers as the nightly does. Two
rounds, servers in turn. The load generator shares the cores, so read
the ratios, not the rates.

| round | server | c64 req/s | c64 p99 | c64 user + sys µs per request | c4096 req/s | c4096 p99 | c4096 user + sys µs per request |
|--:|---|--:|--:|--:|--:|--:|--:|
| 1 | fern | 354,453 | 0.4 ms | 1.8 + 2.8 | 255,947 | 28 ms | 2.1 + 3.7 |
| 1 | httpz | 152,641 | 1.7 ms | 2.1 + 12.9 | 100,224 | 90 ms | 3.2 + 18.7 |
| 1 | zap | 180,160 | 1.5 ms | 4.1 + 5.4 | 160,638 | 55 ms | 4.6 + 6.3 |
| 2 | fern | 348,101 | 0.4 ms | 1.8 + 2.8 | 221,588 | 52 ms | 2.2 + 4.4 |
| 2 | httpz | 152,535 | 2.8 ms | 2.5 + 11.5 | 104,650 | 101 ms | 2.9 + 17.8 |
| 2 | zap | 191,549 | 3.4 ms | 4.1 + 5.7 | 174,862 | 43 ms | 4.7 + 5.3 |

On this box Fern answers about 1.9 times what zap does at 64 connections.
At 4,096 connections the ratio is 1.3 to 1.6. Against http.zig the ratio
is about 2.3 at both counts. Zap spends twice Fern's user time for each
request. http.zig spends four times Fern's kernel time, which is where
its throughput goes.

The nightly is the record. Its first rows for the two servers are the
ones to read.

## How to rerun

```
MISE_ENV=net-nightly mise install zig
(cd scripts/net-bench.d/httpzhello && zig build -Doptimize=ReleaseFast --prefix /tmp/httpz)
PORT=8080 /tmp/httpz/bin/httpz-hello &
oha -z 5s -c 64 http://127.0.0.1:8080/
```

`scripts/net-bench` runs the whole set.
