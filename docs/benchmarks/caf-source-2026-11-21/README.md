# CAF source indexing with adjacent packet reads

The [original CAF source profile](../caf-source-2026-11-09/README.md) attributed 295 of 648 CPU samples to the seek and read callbacks. Window construction, buffer fills and callback work also accounted for much of the sampled allocation traffic. The builder requested a separate source window for every packet. On the 100,000-packet fixture, a separate `strace -c -e read,lseek` run counted 100,027 reads and 100,024 seeks in the original Reader benchmark, including its first-packet checksum. Reusing a bounded packet window reduced these counts to 462 and 459.

## Index measurements

The baseline was d28d9261. Both builds used the same x86-64 Linux stage-one compiler (SHA-256 `522a6fa528bb473b457a2203a213ce3271a5e04347df668782b91c9f51978f2e`) and the unchanged index driver. The inputs are the frozen 1,000-, 10,000-, and 100,000-packet fixtures generated by `scripts/bench-caf-source`. Five trials alternated baseline and candidate order, and reversed the order of the three API variants on alternate trials. Each invocation checked packet count, frame count and the first-packet checksum. All 90 measurements are in [index.csv](index.csv).

| 100,000 packets, median | Index time before → after | Allocations before → after | Fresh allocator bytes before → after | Peak RSS before → after |

| Reader | 54.33 → 21.22 ms | 2,100,435 → 1,005,655 | 5,267,976 → 5,302,888 | 5,432 → 5,436 KiB |
| Retained callbacks | 48.73 → 19.20 ms | 1,300,289 → 603,769 | 5,267,896 → 5,302,808 | 5,432 → 5,436 KiB |
| Byte view (control) | 9.28 → 10.64 ms | 59 → 59 | 11,272,048 → 11,272,048 | 12,528 → 12,528 KiB |

The builder still inspects one packet per step and passes only that packet's bytes to the codec. Adjacent packets share bytes already read from the same immutable source. The window respects the configured buffer limit and the end of the CAF data chunk. A packet larger than the preferred chunk size uses a packet-sized window.

## Complete playback

The 7,300,140-byte CAF repeats one 19-frame mono ALAC packet. Each reader opened that file, indexed and decoded the track and wrote all 3,800,000 bytes of signed little-endian PCM to a memory-backed file. Five warm-cache trials alternated Fern and FFmpeg 7.1.5. Median elapsed process times including startup were 229 ms for Fern and 2,199 ms for FFmpeg. All ten outputs had the same SHA-256. The repeated short packets, local host and command-line startup constrain this comparison. [Playback trials and hashes](playback.csv)

To reproduce with a local compiler:

```sh
scripts/bench-caf-source --compiler build/bootstrap/stage1 --output /tmp/caf-bench
/tmp/caf-bench/caf-source render-s16 /tmp/caf-bench/100000.caf /tmp/fern.s16
ffmpeg -nostdin -v error -y -i /tmp/caf-bench/100000.caf -f s16le /tmp/ffmpeg.s16
cmp /tmp/fern.s16 /tmp/ffmpeg.s16
```

The six CAF source suites cover independent PCM and seeks, malformed input, short reads, callback failures, sparse offsets and the one-operation step bound. They passed on x86-64 Linux, ARM64 Linux and Android targets under QEMU Linux user-mode, and WASI under Wasmtime. Native sanitizer runs passed for all six suites.
