# HTTP/3 request allocation ratchet

The current compiler and crypto implementation on main use about 280.19
allocations per HTTP/3 hello request over one connection. Three independent
100,000-request samples agree:

| Sample | Allocations | Allocations per request |
| --- | ---: | ---: |
| CI on the ARM64 helper-fix branch | 28,019,249 | 280.19249 |
| Local integrated release-cleanup branch | 28,019,131 | 280.19131 |
| Local tightened gate with indexed manifest lookup | 28,019,208 | 280.19208 |

These are the counts reported by `TestSelfHostServeAllocsPerRequestH3`.
The gate requires tightening a ceiling when the reading is at least eight
allocations below it. Its former ceiling of 303 therefore fails on the
improved implementation. The ceiling is now 281, preserving less than one
allocation per request of headroom.

The CI sample is from run 39049489821. Local checks use release-cleanup
parent 5daa853c43039c73386c75a7098184179a63a21b; the second local run includes
the indexed manifest lookup and tightened ceiling. This records the
improvement already present in main's implementation.
