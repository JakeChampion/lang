Fern ships with a pure-Fern unit-test runner under
[`std/test`](../../stdlib/test/). Tests are ordinary `.fern` files:
write functions that return `TestOutcome`, list them in `main`,
and the runner prints [TAP-13](https://testanything.org/) to
stdout.

A test file is an ordinary Fern program: run it with `fern -interp`,
or compile it and run the binary. There is nothing else to install.

## Hello, test

A test function returns `Pass` when the assertion holds and
`Fail(message)` when it fails. `import "std/test";` to bring the
runner into scope, then call its functions qualified
(`test.test_new`, `test.assert_eq`, …) with the runner type written
`test.TestRunner`. Receiver methods (`.it`, `.finish`) stay bare.

<FernPlayground
  code={`import "std/test";

function test_addition(): test.TestOutcome {
    return test.assert_eq(2 + 2, 4);
}

function test_strings(): test.TestOutcome {
    return test.assert_eq("foo" + "bar", "foobar");
}

function main(): i32 {
    let r: test.TestRunner = test.test_new("hello");
    r = r.it("addition", test_addition);
    r = r.it("strings", test_strings);
    return r.finish();
}`}
/>

Save as `hello_test.fern` and run it:

```bash
fern -interp hello_test.fern
```

Output:

```
TAP version 13
# Suite: hello
ok 1 - addition
ok 2 - strings
1..2
# tests 2
# pass 2
# fail 0
```

Exit code is `0`. A failing assertion flips it to `1`, prints a
`not ok` line, and embeds the actual and expected values in the
diagnostic block.

## Assertions

Each helper returns `TestOutcome`. The failure message names
the predicate, so a grep across CI logs finds the regression. The
comparison helpers are generic: `assert_eq` works on any type that
implements `cmp.Eq` and `cmp.Display` — integers of every width, floats,
strings, booleans — and `assert_lt` and friends on any `cmp.Ord` type.

| Family       | Helpers                                                                                                              |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| Equality     | `assert_eq`, `assert_neq`                                                                                             |
| Ordering     | `assert_lt`, `assert_le`, `assert_gt`, `assert_ge`                                                                    |
| Boolean      | `assert_true`, `assert_false`                                                                                         |
| Floats       | `assert_eq_f64_near`, `assert_eq_f64_rel`, `assert_eq_f64_exact`, `assert_is_nan_f64`, and the `_f32` forms           |
| Range        | `assert_in_range_i32`, `assert_in_range_i64`, `assert_in_range_f64`, `assert_in_range_f32`                            |
| Strings      | `assert_contains`, `assert_not_contains`, `assert_starts_with`, `assert_ends_with`, the `_ci` (case-insensitive) forms, `assert_empty_string`, `assert_non_empty_string`, `assert_string_count` |
| Multi-substr | `assert_contains_all`, `assert_contains_any`, `assert_contains_in_order`                                              |
| Text diff    | `assert_eq_string_diff` (reports the first differing line), `assert_lines_eq`                                         |
| Arrays       | `assert_eq_array`, `assert_at`, `assert_array_contains`, `assert_sorted_asc`, `assert_unique`, `assert_subset`, `assert_set_eq`, `assert_len_i32`, `assert_len_string` |
| Maps         | `assert_map_len`, `assert_map_has`, `assert_map_lacks`, `assert_eq_map`                                               |
| Option       | `assert_is_some_i32`, `assert_is_none_i32`, `assert_is_some_eq_i32`, and the `_string` forms                          |
| JSON         | `assert_json_eq` (parses both sides; object key order does not matter), `assert_json_has_key`, `assert_json_eq_field_string` |
| HTTP         | `assert_status`, `assert_header`, `assert_no_header`, `assert_body` on an `HttpResponse`                              |
| File state   | `assert_file_exists`, `assert_file_not_exists`, `assert_file_contains`, `assert_file_contents`, `assert_is_file`, `assert_is_dir`, `assert_file_size` |
| Golden files | `assert_matches_golden(path, actual)` (writes a missing file) / `assert_matches_golden_strict(...)` (fails on one)     |
| Process      | `assert_exit`, `assert_exit_zero`, `assert_stdout_eq`, `assert_stderr_eq`, `assert_stdout_contains`, `assert_stderr_contains`, `assert_process` |
| Environment  | `assert_env_set`, `assert_env_unset`, `assert_env_eq`                                                                 |
| Timing       | `assert_elapsed_lt_ms`, `assert_elapsed_lt_us`                                                                        |
| Free-form    | `pass()`, `fail(msg)`                                                                                                 |

The [`std/test` reference](../../stdlib/test/) lists every helper with
its signature.

## Skipping cases

Toolchain-conditional cases (`wasmtime` missing, OS-specific
behaviour, CI-only checks) skip with `(r).skip(name, reason)`. The
TAP output emits `# SKIP` so consumers can tell a skip from a pass;
skipped cases don't affect the exit code.

```fern
import "std/test";
import "std/option";

function main(): i32 {
    let r: test.TestRunner = test.test_new("backends");
    r = r.skip_if(env("WASMTIME_PATH").is_none(),
                  "wasm e2e", "wasmtime not on $PATH",
                  run_wasm_test);
    return r.finish();
}
```

## Nested suites

Group related cases with `r.subsuite(name)` + `r.merge(child)`.
TAP stays flat (one stream, monotonically numbered) but case names
print as `parent / child / case`, so the hierarchy is visible in
the log.

```fern
let arm: test.TestRunner = r.subsuite("arm64");
arm = arm.it("exit code", run_arm64_exit);
arm = arm.it("stdout",    run_arm64_stdout);
r = r.merge(arm);   // fold counts back into parent
```

## Spawning subprocesses

`subprocess(cmd, args, stdin)` runs an external program and
returns a `ProcessResult { stdout, stderr, exit_code }`. The
process assertions above (`assert_exit` / `assert_stdout_eq` /
`assert_process`) operate on that struct. Spawning a process needs a
native target: `wasm32-wasi` does not provide `subprocess`, and a test
that calls it fails to compile there (E066).

```fern
function test_fern_hello(): test.TestOutcome {
    let r: ProcessResult = subprocess("./fern",
        ["-interp", "/tmp/hello.fern"], "");
    return test.assert_process(r, 0, "hello");
}
```

Spawn failures (binary missing, permission denied) surface as
`exit_code = 127` with the OS error in `stderr`, so callers can
assert linearly without an extra `Result` unwrap.

## Tempdirs + cleanup hooks

Tests needing a scratch directory call `temp_dir(prefix)` and
register cleanup at the runner level:

```fern
match (temp_dir("my-fixture")) {
    Ok(dir) => {
        r = r.defer_cleanup(dir);
        // ... write fixtures into `dir`, spawn subprocesses ...
    },
    Err(_) => { r = r.skip("setup", "temp_dir failed"); }
}
```

`test.must_temp_dir(r, prefix)` does both steps in one call and
returns the path with the updated runner as a `(string, test.TestRunner)`
pair.

`finish()` runs `remove_dir_all(dir)` on every registered path
regardless of test outcome. Cleanup errors print as TAP comments
and shift the exit code to `2` (a "tests passed but cleanup leaked"
sentinel) so CI can tell it apart from a real test failure.

Companion filesystem builtins:
`read_dir(path) -> Result[string[], IoError]` lists immediate
children; `remove_file(path)` and `remove_dir_all(path)` return
`Result[(), IoError]` (`Ok(())` on success).

## Fuzzing

`std/fuzz` adds `r.fuzz(...)` to the runner. A fuzz target is a
`(u8[]) => test.TestOutcome` — the same shape as a regular test, called
repeatedly with mutated inputs from a seed corpus. Inputs are bytes, not
strings, because the mutators produce invalid UTF-8; a target that wants
text converts at its own edge.

```fern
import "std/test";
import "std/fuzz";
import "std/string";

function check_to_upper_idempotent(input: u8[]): test.TestOutcome {
    let s: string = string_from_bytes_unchecked(input);
    if (s.to_upper().to_upper() == s.to_upper()) { return test.pass(); }
    return test.fail("to_upper is not idempotent");
}

function main(): i32 {
    let r: test.TestRunner = test.test_new("fuzz");
    r = r.fuzz("to_upper idempotent",
               ["".bytes(), "abc".bytes(), "Hello".bytes()],
               fuzz.fuzz_default_iterations(),
               check_to_upper_idempotent);
    return r.finish();
}
```

The harness picks among eight mutations — byte flip, drop, insert and
duplicate, bit flip, set a byte to `0x00` or `0xFF`, or run the seed
unchanged. Failures stop the loop and report the input with
non-printable bytes escaped to `\xNN`, so the log doubles as a
reproducer. `fuzz.fuzz_run_seeded` fixes the random seed, so a run can be
replayed exactly.

### Shrinking

`r.fuzz_shrink` runs the same loop but, on a failure, minimises the
offending input via halving + single-byte drops before reporting.
The failure message embeds both the raw input (what the mutator
produced) and the shrunk form (the smallest still-failing variant
found):

```
not ok 1 - detect
  ---
  message: seed[0]: forbidden
  raw     (42 bytes): "lots of padding here BAD lots more padding"
  shrunk  (3 bytes): "BAD"
  ---
```

Use the shrink variant when the property's trigger is much smaller
than the input the corpus + mutator produces — typical for parser
fuzz targets where any single malformed byte breaks the property.

## Filtering test cases

For dev-loop iteration, run a single case (or a substring match)
via the runner's `--filter` flag:

```bash
fern -interp my_test.fern -- --filter addition
```

The example file lifts the pattern off `args()`:

```fern
function main(): i32 {
    let f: string = test.parse_filter_from_args(args());
    let r: test.TestRunner = test.test_new_filtered("my suite", f);
    r = r.it("addition basic",    test_a);
    r = r.it("subtraction basic", test_b);
    return r.finish();
}
```

Non-matching cases convert to skips with reason `"filtered out"`,
so the TAP stream stays a faithful record of the test list.
`test.parse_fail_fast_from_args` and `test.parse_quiet_from_args` read
`--fail-fast` (skip everything after the first failure) and `--quiet`
(print only failures and the summary) the same way.

## Golden-file testing

For tests whose expected output is too verbose to inline, compare
against a saved file on disk:

```fern
r = r.it("renderer matches golden",
         () => test.assert_matches_golden("testdata/render.golden",
                                          render(input)));
```

`assert_matches_golden` bootstraps the file when it doesn't exist
(writes `actual` to `path`, passes, prints a comment naming the
bootstrap) — the "approve by running" loop. It does not create
directories, so `testdata/` must already exist. Use
`assert_matches_golden_strict` in CI to catch missing-golden cases
that would silently self-approve.

## Writing your own assertion

A test function can run any logic that returns `TestOutcome` —
the assertions above are conveniences. For a hand-rolled check,
return `test.fail(...)` directly:

```fern
function test_modulo_table(): test.TestOutcome {
    let inputs: i32[] = [0, 1, 5, 10, 11];
    let expected: i32[] = [0, 1, 5, 0, 1];
    let i: i32 = 0;
    while (i < inputs.len()) {
        if (inputs[i] % 10 != expected[i]) {
            return test.fail("table mismatch at " + i.to_string());
        }
        i = i + 1;
    }
    return test.pass();
}
```

## Why explicit registration?

Fern has no reflection, so `main` lists the cases it runs. That
mirrors Zig's `test` blocks and keeps the runner a plain library —
no build-system magic, no framework runtime.

## Failing tests in CI

The process exit code is `0` on a clean run and `1` on any
failure (`2` when every test passed but a cleanup failed). Drop it into
any CI runner — GitHub Actions, GitLab CI,
Buildkite — without further configuration. TAP consumers
(`prove`, `tape`, `tap-junit`) parse the stream directly.

## Coverage

`-cover` builds a binary that counts how often each line and each branch
ran, and writes the table to stderr at exit. `-cover-report` summarises
a saved table, listing the uncovered lines per file; add `-lcov` for an
lcov tracefile that coverage viewers read. It works on the native
x86-64 and arm64 targets.

```bash
fern -target x86-64-linux -cover -o hello_test hello_test.fern
./hello_test 2> cover.txt
fern -cover-report cover.txt            # per-file summary
fern -cover-report -lcov cover.txt > lcov.info
```

The report covers the standard library modules the program imported as
well as its own files.

  every helper on both pass and fail paths)
- `skip_and_subsuites_test.fern` — skip / skip_if / subsuite /
  merge end-to-end
- `process_assertions_test.fern` — `subprocess` + `temp_dir`
  + the process assertion family (echo / cat / sh fixtures)
- `fuzz_example_test.fern` — three benign property fuzzers
  plus a trim-strips-spaces invariant
- `wide_numerics_test.fern` — i64 / u32 / u64 assertions
- `filesystem_ops_test.fern` — read_dir / remove_file /
  remove_dir_all builtins
- `lang_binary_e2e_test.fern` — the canonical migration
  shape: spawn the `fern` binary itself, drive it through
  `-interp` / `-check` against tempdir fixtures, assert on
  `(exit, stdout, stderr)`. Gated on `$LANG_BIN` being set
  so dev laptops without the env var skip cleanly.
- `helpers_test.fern` — multi-substring / string-diff /
  range / file-state / `must_temp_dir` convenience helpers
- `float_test.fern` — f32 / f64 tolerance + exact + NaN +
  f32_bits round-trip coverage
- `fuzz_shrink_test.fern` — `r.fuzz_shrink` walkthrough on
  three benign properties; the failure-path shrinking
  contract is pinned by the Go-side
  `TestRunnerFuzzShrinkSurfacesMinimisedInput` gate
- `batch7_test.fern` — wider-int relational, `f64_bits`
  round-trips, `stat()` + file-state helpers, and
  `assert_json_eq` order-independent JSON equality
- `batch8_test.fern` — argv passthrough, `--filter PATTERN`
  selection, golden-file assertions, Map receiver
  assertions
- `float_math_test.fern` — `(x: f64).sqrt()` / `.pow()` /
  `.log()` etc., the IEEE-754 classification helpers, and
  the round-trip property tests
  (`exp(log(x)) == x`, `sin² + cos² = 1`)
- `timing_test.fern` — `monotonic_ns()` / `now_unix_ms()` /
  `sleep_ms()` builtins + `assert_elapsed_lt_ms` for
  benchmark-style "completes within N ms" assertions
