## Variables

`let` declares a binding, and the binding can be reassigned. Annotate the
type, or let the checker infer it from the initialiser. The same keyword
destructures tuples and structs, and with an `else` block binds a pattern
that can miss — see
[Language features](../../reference/language-features/#refutable-bindings--let--else-and-if-let).

<FernPlayground
  code={`import "std/i32";

function main(): i32 {
    let x: i32 = 7;
    let y = x * 2;       // type inferred as i32
    print(y.to_string());
    return 0;
}`}
/>

A program sees only what it imports, methods included: `import "std/i32";`
is what gives an `i32` its `.to_string()`. Leave it out and the checker
says so (`no method "to_string" on i32 — add import "std/i32"`).

## Numbers have sizes

There's no untyped `int`. The integer types are `i32`, `i64`
(signed) and `u8`, `u32`, `u64` (unsigned), plus `usize` for
native pointer-width counts. Two floats: `f32` and `f64` — `float` is
an alias for `f64`. Mixing widths needs an explicit cast.

```fern
let a: i32 = 7;
let b: i64 = a as i64;   // narrow → wide cast
let c: i32 = b as i32;   // wide → narrow (may truncate)
```

## Control flow

`if` / `else` and `while` behave as you'd expect. For iteration, reach
for `for … in` — over an array, or over a range written `start..end`
(exclusive) or `start..=end` (inclusive):

<FernPlayground
  code={`import "std/i32";
import "std/string";

function main(): i32 {
    let trees: string[] = ["ash", "beech", "elm"];
    for name in trees {
        print(name);
    }

    let sum: i32 = 0;
    for i in 0..10 {
        if (i % 2 == 0) { sum = sum + i; }
    }
    print(sum.to_string());  // 20
    return 0;
}`}
/>

The three-part `for (init; cond; step)` form also exists, for the rare
loop whose stepping isn't a simple walk:

```fern
for (let i: i32 = 1; i < n; i = i * 2) { … }
```

`loop { … }` is an unconditional loop you leave with `break`. Any loop can
be labelled so a nested `break` / `continue` targets it — see
[Language features](../../reference/language-features/) for that, plus
map iteration with `for (k, v) in m`.

`if` is also an expression, for one-line ternaries.

```fern
let max: i32 = if (a > b) { a } else { b };
```

## Functions

```fern
function add(a: i32, b: i32): i32 {
    return a + b;
}
```

Return and parameter types are always required — even `void` for
procedures. There's no inference at the signature boundary.

Functions are values. A lambda is written `(x: i32) => x * 2`, a
function type `(i32) => i32`, and a lambda can read the variables around
it. An `f"…"` string interpolates `{expr}` holes, calling `.to_string()`
on each:

<FernPlayground
  code={`import "std/i32";
import "std/array";

function apply_twice(f: (i32) => i32, x: i32): i32 {
    return f(f(x));
}

function main(): i32 {
    let step: i32 = 3;
    let add_step = (x: i32) => x + step;   // reads step from main
    print(apply_twice(add_step, 10).to_string());  // 16

    let squares: i32[] = [1, 2, 3, 4].map((x: i32) => x * x);
    let name: string = "fern";
    print(f"{name}: {squares.len()} squares, last {squares[3]}");
    return 0;
}`}
/>
