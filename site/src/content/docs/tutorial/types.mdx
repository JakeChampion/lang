## Structs

Plain records. Fields are laid out in declaration order, addressed
by name in source.

<FernPlayground
  code={`import "std/i32";

struct Point { x: i32, y: i32 }

function origin(): Point {
    return Point { x: 0, y: 0 };
}

function main(): i32 {
    let p: Point = origin();
    print(p.x.to_string() + "," + p.y.to_string());
    return 0;
}`}
/>

A struct value cannot change after it is built: `p.x = 9;` is a compile
error (E048). Build an updated copy instead — `Point { ...p, x: 9 }`
copies every field of `p` except the ones you name. The binding `p` can
still be reassigned to the new value.

## Methods

The receiver goes between `function` and the name. Calls dispatch
by receiver type at the call site.

<FernPlayground
  code={`import "std/i32";

struct Point { x: i32, y: i32 }

function (p: Point) magnitude_sq(): i32 {
    return p.x * p.x + p.y * p.y;
}

function main(): i32 {
    let p: Point = Point { x: 3, y: 4 };
    print(p.magnitude_sq().to_string()); // 25
    return 0;
}`}
/>

## Enums

Tagged unions with optional positional payloads. `Option[T]` and
`Result[T, E]` are built into the language — always in scope, so you
never re-declare them.

<FernPlayground
  code={`import "std/i32";

enum Shape {
    Circle(i32),         // radius
    Rectangle(i32, i32), // width, height
}

function area(s: Shape): i32 {
    match (s) {
        Circle(r) => { return 3 * r * r; },
        Rectangle(w, h) => { return w * h; },
    }
}

function main(): i32 {
    print(area(Circle(5)).to_string());        // 75
    print(area(Rectangle(3, 4)).to_string());  // 12
    return 0;
}`}
/>

## Match is exhaustive

The checker fails the build if a `match` misses a variant, unless
a wildcard `_` arm acknowledges the gap.

```fern
function describe(s: Shape): string {
    match (s) {
        Circle(_) => { return "round"; },
    }
}
```

```
error[E030]: match does not cover variant Rectangle of enum Shape — add an
             arm for it, or a `_` arm
```

That's the property that makes adding a variant safe: every `match` that
now has a hole becomes a compile error pointing at the code that needs
updating. Arms can also carry a `when` guard — but a guard can always
fail, so a variant covered only by guarded arms still counts as a hole.

## Option, Result and `?`

Fern has no exceptions and no null. A value that may be absent is an
`Option[T]` (`Some(v)` or `None`); an operation that can fail returns a
`Result[T, E]` (`Ok(v)` or `Err(e)`). Inside a function that itself
returns a `Result`, a trailing `?` unwraps an `Ok` or returns the `Err`
to the caller; on an `Option` it does the same with `Some` and `None`.

<FernPlayground
  code={`import "std/i32";
import "std/string";
import "std/option";

// ? unwraps an Ok, or returns the Err from this function.
function area(w: string, h: string): Result[i32, string] {
    let width: i32 = w.parse_int().ok_or("width is not a number")?;
    let height: i32 = h.parse_int().ok_or("height is not a number")?;
    return Ok(width * height);
}

function main(): i32 {
    match (area("6", "7")) {
        Ok(n) => { print(n.to_string()); },      // 42
        Err(msg) => { print("error: " + msg); },
    }
    match (area("6", "seven")) {
        Ok(n) => { print(n.to_string()); },
        Err(msg) => { print("error: " + msg); }, // error: height is not a number
    }
    return 0;
}`}
/>

`parse_int` answers an `Option[i32]`; `ok_or` turns its `None` into an
`Err` carrying the message. [Error handling](../../reference/error-handling/)
lists the combinators on both types; `let … else` and `defer` /
`errdefer` are in [Language features](../../reference/language-features/).
