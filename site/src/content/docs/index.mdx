**Fern** is a small, statically-typed compiled language with no runtime
and no garbage collector. One source file compiles to a lean native
binary or a self-contained `.wasm` component — the same program, across
arm64 (Linux + macOS), x86-64 (Linux), and WebAssembly.

It's a general-purpose language that's especially at home in two jobs
where startup time and binary size matter: **short-lived CLI tools** and
**edge-function-style HTTP servers**. No JIT warm-up, no interpreter
boot, no megabytes of runtime to ship — your code starts in milliseconds
and exits clean. Reference counting (with a Perceus-style elision pass)
means the same language also handles long-running, allocation-heavy
programs — Fern's own compiler is written in Fern.

## A real CLI tool, end to end

Fern reads `argv`, streams stdin or files, and uses `Result` + `match`
for fallible I/O — so a Unix-style filter is short and total. Here's the
core of a `grep`-like line filter:

<FernPlayground
  code={`import "std/string";
import "std/io";

function main(): i32 {
    var argv: string[] = args();
    if (argv.len() < 2) {
        eprint("usage: grep PATTERN");
        return 2;
    }
    var pattern: string = argv[1];

    match (io.read_input("-")) {       // "-" means stdin
        Ok(text) => {
            var found: boolean = false;
            var lines: string[] = text.lines();
            var i: i32 = 0;
            while (i < lines.len()) {
                if (lines[i].contains(pattern)) {
                    print(lines[i]);
                    found = true;
                }
                i = i + 1;
            }
            return if (found) { 0 } else { 1 };  // grep's exit convention
        },
        Err(_) => {
            eprint("grep: read error");
            return 2;
        }
    }
}`}
  autoRun={false}
/>

## A quick tour

A taste of the type system. Enums are tagged unions, and `match` is
exhaustive — forget a variant and the build fails, not production. Try
adding a `Triangle` to `Shape` below and watch the checker point at the
`area` function.

<FernPlayground
  code={`import "std/i32";

enum Shape {
    Circle(i32),          // radius
    Rectangle(i32, i32),  // width, height
}

function area(s: Shape): i32 {
    match (s) {
        Circle(r)       => { return 3 * r * r; },
        Rectangle(w, h) => { return w * h; },
    }
}

function main(): i32 {
    print(area(Circle(5)).to_string());        // 75
    print(area(Rectangle(3, 4)).to_string());  // 12
    return 0;
}`}
/>

Generics are monomorphised (no runtime cost), and a **trait bound**
constrains a type parameter to types that implement a trait — here, any
orderable, printable value:

```fern
import "core/cmp";

function max[T: cmp.Ord + cmp.Display](a: T, b: T): T {
    if (a.cmp(b) >= 0) { return a; }
    return b;
}

function main(): i32 {
    print(max(3, 9).to_string());   // 9
    print(max("apple", "pear"));    // pear
    return 0;
}
```

Errors are values, not exceptions. `Result` and `Option` are built in,
and the `?` operator threads a failure up without ceremony:

```fern
function double(s: string): Result[i32, ParseError] {
    var n: i32 = parse_int(s)?;   // returns early on Err
    return Ok(n * 2);
}
```

See the [Reference](reference/syntax/) for the full story — or keep
scrolling.

## Why Fern?

- **No surprises at the type boundary.** There's no untyped `int` and no
  implicit numeric coercion — widths are explicit, so an `i32` never
  silently becomes an `i64`. `match` is exhaustive; the compiler fails
  the build when you forget a case.
- **Errors are values, not exceptions.** `Result` and `Option` are
  built into the language. The `?` operator threads failures up without
  ceremony, and there's no hidden control flow to reason about.
- **One language, three backends.** The same source targets native
  arm64/x86-64 and WebAssembly through a shared, target-agnostic IR.
  Prototype with the interpreter, then compile for production.
- **Small by design, general in reach.** Fern began TypeScript-flavoured
  but has grown its own shape, taking cues from Roc, Zig, Rust, and Go:
  tiny, fast, predictable programs. It's tuned hardest for CLI tools and
  edge handlers, but it's a general-purpose language — long-running
  services and its own self-hosted compiler run on it too.
