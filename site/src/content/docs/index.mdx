<div class="fern-lead">

Fern compiles a single source file to a lean native executable or a
self-contained `.wasm` component — the same program, unchanged, across
arm64 (Linux and macOS), x86-64 (Linux), and WebAssembly. It is at its
best where startup time and binary size are the whole story: short-lived
CLI tools and edge-function HTTP handlers. Reference counting instead of
a collector means long-running work is fair game too — Fern's own
compiler is written in Fern.

</div>

<FacetRail>
  <Facet index="01" title="Nothing to warm up">

Statically linked, with no runtime, no interpreter boot and no JIT.
`main` runs the instant the process does, and there is no collector
waiting to pause it.

  </Facet>
  <Facet index="02" title="The toolchain is one binary">

The native backends assemble *and* link in-process with a pure-Go
assembler — producing an executable needs no `gcc`, no `clang`, no `ld`.
Pass `-cc` when you would rather use your own.

  </Facet>
  <Facet index="03" title="WebAssembly without the glue">

`-target wasm` emits a self-contained WASI Preview 2 component.
`wasmtime run` it, or `wasmtime serve` it as an HTTP handler through
`wasi:http/incoming-handler`. No JS shim, no adapter wrangling.

  </Facet>
  <Facet index="04" title="Types that stay put">

Integers carry their width and never coerce silently, so an `i32` can't
drift into an `i64`. Enums are tagged unions and `match` is exhaustive —
miss a variant and the build fails. Generics are monomorphised, so none
of it costs anything at runtime.

  </Facet>
  <Facet index="05" title="Errors are values">

`Option` and `Result` are part of the language, `?` threads a failure up
without ceremony, and `let … else` handles the unhappy path first. No
exceptions, no hidden control flow to reason about.

  </Facet>
  <Facet index="06" title="The tools come with it">

`fern-lsp` gives hover, goto-definition, completion, signature help,
inlay hints, workspace rename and format-on-save to any LSP client, with
a VS Code extension ready to install. A formatter, a test runner and
literate `.fern.md` programs are in the box.

  </Facet>
</FacetRail>

## Read a program before you install one

Fern reads `argv`, streams stdin or files, and returns `Result` from
anything fallible — so a Unix-style filter stays short and total. Here
is the core of a `grep`-like line filter; edit it and press Run.

<FernPlayground
  code={`import "std/string";
import "std/io";

function main(): i32 {
    var argv: string[] = args();
    if (argv.len() < 2) {
        eprint("usage: grep PATTERN");
        return 2;
    }
    var pattern: string = argv[1];

    match (io.read_input("-")) {       // "-" means stdin
        Ok(text) => {
            var found: boolean = false;
            var lines: string[] = text.lines();
            var i: i32 = 0;
            while (i < lines.len()) {
                if (lines[i].contains(pattern)) {
                    print(lines[i]);
                    found = true;
                }
                i = i + 1;
            }
            return if (found) { 0 } else { 1 };  // grep's exit convention
        },
        Err(_) => {
            eprint("grep: read error");
            return 2;
        }
    }
}`}
  autoRun={false}
/>

The [CLI tutorial](tutorial/cli-tool/) grows this into a real tool with
flags and multiple input files.

## Exhaustiveness you can feel

`match` covers every variant or the build stops. Add a `Triangle` to
`Shape` below and watch the checker point straight at `area`:

<FernPlayground
  code={`import "std/i32";

enum Shape {
    Circle(i32),          // radius
    Rectangle(i32, i32),  // width, height
}

function area(s: Shape): i32 {
    match (s) {
        Circle(r)       => { return 3 * r * r; },
        Rectangle(w, h) => { return w * h; },
    }
}

function main(): i32 {
    print(area(Circle(5)).to_string());        // 75
    print(area(Rectangle(3, 4)).to_string());  // 12
    return 0;
}`}
/>

A **trait bound** constrains a type parameter to types that implement a
trait — here, anything orderable and printable. The generic is
monomorphised per instantiation, so the dispatch is direct:

```fern
import "core/cmp";

function max[T: cmp.Ord + cmp.Display](a: T, b: T): T {
    if (a.cmp(b) >= 0) { return a; }
    return b;
}

function main(): i32 {
    print(max(3, 9).to_string());   // 9
    print(max("apple", "pear"));    // pear
    return 0;
}
```

And failure is just a value moving up the call stack:

```fern
import "std/string";

function double(s: string): Option[i32] {
    var n: i32 = s.parse_int()?;   // returns None early if the parse fails
    return Some(n * 2);
}
```

The [Reference](reference/syntax/) has the full grammar, the type
system, and the error-handling rules.

## Where Fern is today

Worth knowing before you pick it up:

- **The nightly *is* the release channel.** There is no tagged stable
  version yet, and syntax occasionally changes under you.
- **The self-hosted compiler is mid-port.** A widening subset of the
  language lowers through its own IR; the rest still routes through the
  older AST emitters. Both produce working programs — the difference is
  visible in the source, not the output.
- **macOS means Apple Silicon.** There is no x86-64 Darwin target, and
  32-bit ARM was retired rather than half-maintained.
- **The wasm target is narrower than native.** C FFI and subprocesses
  are native-only, and say so with a real error rather than failing at
  runtime.
- **The standard library is small on purpose.** Strings, collections,
  iterators, JSON, I/O, HTTP, time, math — it grows when a real program
  needs it to.
