# E072 — a void expression is not a value

A function declared `: void` returns nothing, so a call to it produces no
value to store. E072 is a void call where a value is expected: an enum
payload, or the value of a `let`.

```fern
function log_it(): void { print("saved"); }

function save(): Result[void, IoError] {
    return Ok(log_it());   // E072: no value to put in the payload
}

function main(): i32 {
    let done = log_it();   // E072: no value to bind
    return 0;
}
```

An `if` or a `match` whose branches are all void calls is also a void
expression. A `let` of one is also E072.

## The unit value

When what you want is "success, with nothing to report", that is the
**unit value**, written `()`. Its type is `void`, and `()` is the only
way to write it:

```fern
function save(p: string, body: string): Result[void, IoError] {
    write_file(p, body)?;
    return Ok(());
}
```

## Calling a void function

A void call is a statement. Drop it on its own line:

```fern
log_it();
return Ok(());
```

## Why this is an error rather than a warning

The unit value occupies a slot: an enum payload holding it loads and
stores like any other single-word value. A void *call* never pushed
anything into that slot, so accepting one would leave each backend to
invent a value — which is exactly what used to happen. The interpreter
and the native backends substituted a zero, while the WebAssembly
backend emitted a payload store with nothing on the stack and produced a
module that failed verification at load time. Rejecting the expression
here keeps the four backends agreeing on what a program means.
