# E047 — Integer literal out of range

A numeric literal's value doesn't fit in the target type.
Fern's checker computes the literal's value at compile time
and rejects assignments / annotations that would overflow.

## Example

```
function main(): i32 {
    let x: i32 = 999999999999;   // error[E047]: literal 999999999999 does not fit in i32
    return x;
}

function main2(): i32 {
    let y: u8 = 256;             // error[E047]: literal 256 does not fit in u8
    return y as i32;
}

const LIMIT: i32 = 2147483648;   // error[E047]: literal 2147483648 does not fit in i32
```

Each literal of a `const` initialiser is judged the same way as
a literal of a `let` initialiser. A literal no 64-bit type can
hold (`18446744073709551616`, which is 2^64) is the same error
against whatever type the context asked for.

## A constant expression that leaves its type

A `const` with a declared integer type must stay in that type.
The compiler computes each step of `+`, `-`, `*`, `/`, `<<` and
each negation exactly. A step whose value is outside the type is
this error, and so is a shift by the width of the type or more.

```
const W: u8 = 255 + 1;     // error[E047]: const W: 255 + 1 does not fit in u8
const Y: i32 = 1 << 40;    // error[E047]: const Y: shift count 40 is not less than the 32 bits of i32
```

The same expression in a `let` wraps at run time. To get the
wrapped value in a constant, write the value that you want, or
compute it in a wider type and narrow it at the use with `as`.

## Fix

Use a wider type, or change the literal.

```
function main(): i32 {
    let x: i64 = 999999999999 as i64;
    return (x % 100) as i32;
}

function main2(): i32 {
    let y: u8 = 255;             // max u8
    return y as i32;
}
```

## A local with no annotation

A local that starts from an integer literal and has no annotation
is `i32`, unless a use gives it a different type. An assignment is
not such a use. An assignment does not change the type of its
target, so a literal that is assigned to the local must fit the
type that the local has.

```
function main(): i32 {
    let n = 5;
    n = 5000000000;              // error[E047]: literal 5000000000 does not fit in i32
    let m = 1;
    m += 5000000000;             // error[E047]: literal 5000000000 does not fit in i32
    return n;
}
```

These uses do give the local a different type:

```
function main(): i32 {
    let a = 5;
    let wide: i64 = a;           // `a` is i64
    a = 5000000000;              // fits

    let b = 5;
    let sum = b + 5000000000;    // `b` and `sum` are i64

    let c = 5;
    c = 5000000000 as i64;       // a typed value: `c` is i64
    return 0;
}
```

## Why no silent wrap

C-style silent wraparound (`(uint8_t)256 == 0`) is a
well-known source of bugs. Fern rejects the literal at the
declaration site so the overflow is visible — runtime
arithmetic that might overflow still uses the
implementation-defined wrapping behaviour of the underlying
hardware (overflow on i32 add is well-defined wrap).

## Supported width tags

- Signed: `i32`, `i64`
- Unsigned: `u8`, `u32`, `u64`
- Floats: `f32`, `f64`

## See also

- E002 (type mismatch) — broader category, fires when the
  literal IS in range but the target type doesn't accept
