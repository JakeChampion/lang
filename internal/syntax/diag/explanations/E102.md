# E102 — a `@norc` function that can allocate or change a reference count

A function with the `@norc` or the `@interrupt` attribute allocates nothing and does no
reference-count (RC) operation. Such a function can run before the heap
exists, in the top half of an interrupt handler, or on memory that a device
writes. The checker makes sure of the property with a simple rule:

- Each parameter, the result and each annotated local is a scalar: an integer,
  `usize`, `f32`, `f64`, `boolean` or `char`.
- The body uses literals, operators, casts to a scalar, `if`, `while`, `loop`,
  `break`, `continue`, `return`, assignment to a local, and `unsafe` blocks.
- A call names another `@norc` function or one of the raw memory intrinsics:
  the `__load_*` and `__store_*` floor, the `__mmio_*` accesses, `__fence`,
  the privileged ops (`__wfi`, `__hvc`, `__smc`, `__boot_info`, the system
  register, cache and TLB ops), the port ops, and the bit counts. The register
  name of `__sysreg_read` and `__sysreg_write` is a string literal that the
  instruction encodes, so it is accepted.

A string, an array, a struct, a closure, a method call, a field access, an
index, `for` and `match` are refused. Each of them can hold a heap value.

```
function helper(x: i32): i32 {
    return x + 1;
}

@norc
function tick(n: i32): i32 {
    // error[E102]: `@norc` function "tick" may call only `@norc` functions and the raw memory intrinsics, not "helper"
    return helper(n);
}
```

Fix: mark the callee `@norc` too, if its body obeys the rule, or move the work
out of the `@norc` function. Use `while` in place of `for`. The rule is in
`docs/BARE-METAL-PLAN.md`, section 3.
