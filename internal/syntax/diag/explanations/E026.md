# E026 — Wildcard `_` arm must be last

A `match` had an unguarded `_` (wildcard) arm that was not the
last arm. The wildcard catches everything that the preceding
arms did not, so anything that comes after it is unreachable.
The checker rejects the shape rather than silently producing
dead code. A bare binding name in a match on a non-enum value
(`n => n + 1`) matches every value too, so an unguarded one
must also be last. A guarded `_` or binding arm
(`n when n > 100 => n`) can fail, so it can come before other
arms.

## Example

```
match (s) {
    Ok => { return 1; },
    _ => { return 99; },
    Err => { return 0; },   // error[E026]: wildcard `_` arm must be last in the match
}
```

## Fix

Move the `_` arm to the end, or replace it with the specific
variants you wanted to cover.

```
match (s) {
    Ok => { return 1; },
    Err => { return 0; },
    _ => { return 99; },
}
```

## Why no "after-wildcard" arms

In some languages (Haskell's `case`, Rust's `match`), the
compiler emits a "unreachable pattern" warning instead of an
error. Fern is stricter: unreachable code is almost always a
bug, and elevating to an error means the catch is not
silently masked behind a `-Wno-unreachable` switch.
