# E026 — Wildcard `_` arm must be last

A `match` had a `_` (wildcard) arm that wasn't the last arm.
The wildcard catches everything that the preceding arms
didn't, so anything that comes after it is unreachable —
the checker rejects the shape rather than silently producing
dead code.

## Example

```
match (s) {
    Ok => { return 1; },
    _ => { return 99; },
    Err => { return 0; },   // error[E026]: wildcard `_` arm must be last in the match
}
```

## Fix

Move the `_` arm to the end, or replace it with the specific
variants you wanted to cover.

```
match (s) {
    Ok => { return 1; },
    Err => { return 0; },
    _ => { return 99; },
}
```

## Why no "after-wildcard" arms

In some languages (Haskell's `case`, Rust's `match`), the
compiler emits a "unreachable pattern" warning instead of an
error. Fern is stricter: unreachable code is almost always a
bug, and elevating to an error means the catch isn't
silently masked behind a `-Wno-unreachable` switch.
