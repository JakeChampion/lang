# E040 — Generic type-parameter inference / arity error

Two failure modes when calling a generic function or
constructing a generic struct:

- **Wrong type-arg count.** When the user supplies explicit
  type arguments — at a call site or on a struct literal —
  they must match the generic decl's parameter count.
- **Inference failed.** The arguments or field values did
  not give every type parameter. Both sites can name the type
  arguments themselves: `foo[i32, string](...)` for a call,
  `Box[i32] { … }` for a struct literal. On a method the args
  go after the method name (`h.make[i32]()`). An annotation on
  the binding works as well, and the enclosing return type can
  supply them too.

## Examples

```
function pair[A, B](a: A, b: B): (A, B) { return (a, b); }

function main(): i32 {
    let p = pair(1, "hello");     // OK — inferred as (i32, string)
    return p.0;
}

function empty[T](): T[] { return []; }

function main2(): i32 {
    let xs = empty();             // error[E040]: could not infer type parameter T for empty — supply it explicitly at the call site (e.g. empty[i32](...)) or annotate the binding
    return xs.len();
}

struct Stack[T] { items: T[] }

function main3(): i32 {
    let s = Stack { items: [] };  // error[E040]: could not infer type parameter T for struct Stack — supply it explicitly at the construction site (e.g. Stack[i32] { ... }) or annotate the binding (e.g. let x: Stack[i32] = ...)
    return s.items.len();
}
```

`[]` cannot give `T`, so nothing in the literal decides which
`Stack` the literal builds. A phantom parameter — one no field
mentions at all — can never be inferred:

```
struct Tagged[T] { n: i32 }
```

A generic method is reported as `Type.method`, and its type
arguments attach to the method name:

```
struct Holder { n: i32 }
function (h: Holder) make[T](): T[] { return []; }

function main4(): i32 {
    let h = Holder { n: 1 };
    let xs = h.make();            // error[E040]: could not infer type parameter T for Holder.make — supply it explicitly at the call site (e.g. .make[i32](...)) or annotate the binding
    return xs.len();
}
```

A local with no type takes the type arguments of a generic call
from its first use at a known type:

```
function total(xs: i64[]): i32 { return xs.len(); }

function main6(): i32 {
    let xs = empty();             // OK — total(xs) gives T = i64
    return total(xs);
}
```

The use can be an argument, a `return`, or a method call whose
arguments give the type parameters of the receiver, such as
`m = m.insert(1, 2)`. A use such as `xs.len()` gives no type.
When no use gives the type arguments, the checker reports E040
at the call.

## Fix

Name the type argument where the value is produced:

```
function main2(): i32 {
    let xs = empty[i32]();
    return xs.len();
}

function main3(): i32 {
    let s = Stack[i32] { items: [] };
    return s.items.len();
}

function main4(): i32 {
    let h = Holder { n: 1 };
    let xs = h.make[i32]();
    return xs.len();
}
```

An annotation on the binding does the same job. It is the
only option when you cannot add type arguments where the
value comes from:

```
function main5(): i32 {
    let xs: i32[] = empty();
    let s: Stack[i32] = Stack { items: [] };
    let t: Tagged[i32] = Tagged { n: 1 };
    return t.n + s.items.len() + xs.len();
}
```
