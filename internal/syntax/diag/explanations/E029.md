# E029 — Variant pattern qualifier mismatch

A `match` arm used a qualified variant pattern (`Color.Red`
or `mymod.Color.Red`) where the qualifier doesn't match the
scrutinee's enum. Two forms:

- **Wrong enum name in the qualifier.** Pattern says
  `Status.Ok` but the scrutinee is `Color`.
- **Wrong module in the qualifier.** Pattern says
  `lib.Color.Red` but `Color` actually lives in `main`.

## Example

```
enum Color { Red, Green }
enum Status { Ok, Err }

function f(c: Color): i32 {
    match (c) {
        Status.Ok => { return 1; },   // error[E029]: variant pattern qualifier "Status" does not match scrutinee enum Color
        _ => { return 0; },
    }
}
```

## Fix

Use the correct enum's variants.

```
function f(c: Color): i32 {
    match (c) {
        Red => { return 1; },
        _ => { return 0; },
    }
}
```

## When to qualify

Bare variant names work when the scrutinee's enum is
unambiguous. Qualified names (`EnumName.Variant`) are useful
when:

- Two enums in scope share a variant name and the unqualified
  form is ambiguous.
- You want the reader to see the type without inspecting the
  scrutinee declaration.

Both styles compile to the same dispatch; pick whichever
reads clearer for the local code.
