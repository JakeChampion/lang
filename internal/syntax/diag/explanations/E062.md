# E062 — ambiguous method on a multi-trait object

A method call `value.method(…)` on a multi-trait object (`dyn A + B`) is
ambiguous when more than one of the composed traits declares a method of that
name. The compiler cannot tell which trait's `method` you mean, so the call
has to be disambiguated. See `docs/DYN-TRAITS.md`.

## What is rejected

```
// both `Reader` and `Closer` declare `close`
function shut(x: dyn Reader + Closer): i32 {
    x.close();           // error[E062]: ambiguous `close` (declared by Reader, Closer)
    return 0;
}
```

## Fixing it

Narrow the parameter / value to the single trait whose method you want, so the
object exposes only one `close`:

```
function shut(x: dyn Closer): i32 {
    x.close();           // unambiguous
    return 0;
}
```

If both traits genuinely need to be in the object, rename the colliding method
on one of them so the composed surface is unambiguous.
