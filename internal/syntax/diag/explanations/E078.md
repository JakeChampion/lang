# E078: invalid `@try` enum shape

An enum marked `@try` must have exactly two variants, in this order:

1. A success variant with exactly one payload.
2. A failure variant with zero or one payload.

The `?` operator unwraps the success payload or returns the failure variant
from the surrounding function. The variant names are your choice; their
declaration order determines their roles.

## Example

```fern
@try
enum Outcome[T, E] {
    Success(T),
    Failure(E),
}
```

Adding a third variant, omitting the success payload, or giving either
variant too many payloads produces E078 at the enum declaration.

## Fix

Use the two-variant shape above, or remove `@try` and handle the enum with
`match`. The builtin `Option` and `Result` types already support `?` without
an explicit marker. E042 describes errors at a use of `?`, including an
incompatible surrounding return type.
