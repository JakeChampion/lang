# E009 — Operator requires integer-compatible operands

An arithmetic, bitwise or comparison operator received operands that
it cannot combine. There are two cases:

- **Both sides must be integers.** `+ - * / % | & ^ << >>` refuse a
  non-integer operand. Float arithmetic uses the same operators, but
  both sides must be floats.
- **The two integer types must have a common type.** The checker
  widens an operand only where no value can change.

The common type of two integer types:

- Two widths of one signedness join at the wider type: `i32 + i64` is
  an `i64`.
- A signed and an unsigned operand join at a signed type that holds
  every value of both: `u32 + i32` is an `i64`.
- No signed type holds every `u64`, so `u64` and a signed operand have
  no common type. That is E009.
- `usize` has the width of the target, so it joins only with a type
  that it holds on each target: `usize` itself, or an unsigned type of
  32 bits or less. `usize` with `i32`, `i64` or `u64` is E009. Write a
  pointer offset as `p + off as usize`.

## Example

```
function f(a: u64, b: i32): u64 {
    return a + b;   // error[E009]: operator "+" requires both operands to share an integer type; got u64 and i32
}
```

## Fix

Add an explicit `as` cast. The cast shows where a value can change.

```
function f(a: u64, b: i32): u64 {
    return a + (b as u64);
}
```

## Why the widening stops here

A widening that cannot change a value is invisible and safe. A
conversion that can change a value, such as `-1` as a `u64`, must be a
visible cast. Rust and Zig make the same trade for the lossy case.
