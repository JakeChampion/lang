# E057: `Cell[T]` element type is not allowed

A `Cell[T]` is the one mutable cell in the language. To keep the
immutable-data guarantee that makes reference cycles unconstructible (so
Perceus reference counting needs no cycle collector), cells admit only
supported cycle-free elements: a scalar (integer, float or boolean),
`string`, or an owned array of scalars (`u8[]`, `i32[]`, `boolean[]`, …).
An array of scalars contains no references that could point back to the
cell, and its ownership support preserves snapshots across replacements.
See `docs/CELL-TYPE-PLAN.md`.

Arrays of non-scalars (including `string[]`), borrowed views, structs,
enums, tuples and nested cells remain unsupported. Some such types could form cycles; even cycle-free composites
need explicit ownership support before cells can admit them.

## What is rejected

```
struct Node { next: Cell[Node] }   // E057: unsupported element type Node
let c = cell_new(["a", "b"]);      // E057: unsupported element type string[]
```

## What is allowed

```
let counter = cell_new(0);         // Cell[i32]
let name = cell_new("anon");       // Cell[string]
let bytes = cell_new([0u8, 255u8]); // Cell[u8[]]
let xs = cell_new([1, 2, 3]);       // Cell[i32[]]
```

## Fixing it

Use an array of scalars, such as `Cell[u8[]]`, for shared storage. For unsupported composite values,
store a scalar key, index or handle referring to a value held elsewhere.
