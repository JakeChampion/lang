# E020 — Empty array literal needs a type annotation

An array literal `[]` with no elements can't have its element
type inferred — there's nothing inside to infer FROM. Fern
asks for an explicit annotation on the declaration that owns
the literal.

## Example

```
function main(): i32 {
    let xs = [];   // error[E020]: empty array literal needs a type annotation
    return 0;
}
```

## Fix

Add the type annotation on the variable:

```
function main(): i32 {
    let xs: i32[] = [];
    return 0;
}
```

Non-empty literals don't need the annotation — the element
types fix the array type unambiguously:

```
function main(): i32 {
    let xs = [1, 2, 3];   // inferred as i32[]
    return xs[0];
}
```

## Maps

An empty map, `Map { }` or `map_new(8)`, has no entries to give its key and
value types. The first use of the local that gives them sets them:

- a `return`, an argument, a struct field or an assignment to a local with a
  type;
- a call of `insert` or `get_or`, which gives them from its arguments, as a
  map literal `Map { 1: "one" }` takes them from its entries.

```
function size(m: Map[string, i64]): i32 { return m.len(); }

function main(): i32 {
    let m = Map { };
    m = m.insert(1, 2);   // m is a Map[i32, i32]
    let n = Map { };
    return n.len() + size(n);   // n is a Map[string, i64]
}
```

A call such as `len()` gives no types, so a later use can still give them.
When no use gives them, the checker reports E020 at the `let`:

```
function main(): i32 {
    let m = Map { };      // error[E020]: map "m" needs a type annotation
    return m.len();
}
```

Write the type on the `let`: `let m: Map[i32, i32] = Map { };`.
