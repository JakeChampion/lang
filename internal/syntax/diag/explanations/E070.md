# E070 — a dependency package reaches a capability it was not granted

A dependency entry in `fern.toml` may carry a **capability grant** —
the v1 capabilities (`net`, `fs`, `env`, `subprocess`, `time`,
`random`) the dependency's code is allowed to reach:

```toml
[dependencies]
json_fast = { url = "…", hash = "sha256:…", capabilities = [] }
kv_client = { path = "../kv", capabilities = ["net"] }
```

When the key is present, the checker walks the package's call graph
(the same reachability the `fern -capabilities` report prints — every
declared function is a root, and the walk follows calls through the
stdlib and into deeper packages) and rejects any path from that
package to a capability-tagged runtime builtin outside the grant.
The error carries the chain:

```
error[E070]: package "json_fast" reaches 'net' (tcp_connect) without a
capability grant: json_fast.parse → helper__fetch_cached → tcp_connect;
add "net" to its capabilities in fern.toml or remove the call
```

Rules (docs/PACKAGE-CAPABILITIES-BRIEF.md):

- **The root package is unrestricted** — grants restrict dependencies;
  the program's author is trusting themselves. Stdlib usage counts on
  the row of whichever package calls into the stdlib.
- **A dependency with NO `capabilities` key is not enforced yet**: its
  reaches print as warnings (warn-and-allow), so existing manifests
  keep compiling while the ecosystem migrates. Default-deny is the
  planned follow-up flip.
- **Closures count at their definition package** — a callback the root
  hands to a dependency does not need the dependency to hold the
  callback's capabilities.

Fixes, in order of likelihood:

1. **Grant the capability** — add it to the dependency's
   `capabilities` list in your `fern.toml`, if you trust the package
   with that authority.
2. **Drop the reaching code path** — if the dependency should not need
   the capability, the chain in the message shows exactly which call
   pulls it in.
3. **Pass a capability instead** — hand the dependency a closure your
   own (root) code defines; the closure's capability usage counts as
   yours, which is the object-capability way to delegate narrowly.

An unknown name inside a `capabilities` list is a manifest error at
load time, naming the valid vocabulary.
