# E036 — Variant constructor call error

A variant constructor call (`Some(42)`, `Err("oops")`,
`Color.Red(...)`) had one of several errors:

- **Wrong payload arity.** The variant declares N payloads;
  the call passed a different number.
- **Wrong payload type.** Arity matches but a payload's
  type doesn't fit the declared shape.
- **Variant declared in multiple enums (ambiguous).** A
  variant name like `Ok` shows up on two enums the module
  can name; the call needs to qualify (`MyEnum.Ok(...)`).
  Only enums the referring module declares or imports are
  candidates, so an enum in an unrelated module never makes
  a reference ambiguous. `Option` / `Result` / `IoError` /
  `JsonValue` are built in and count everywhere.
- **Bare variant call used as fn call shape.** `Some` is a
  payload-bearing variant but was called with no parens or
  the wrong shape. The reverse, a bare call of a payloadless
  variant (`Red()`), is E038: write `Red`, or `Color.Red`.
- **No such variant on the qualified enum.** `Status.Foo`
  where `Status` doesn't have a `Foo` variant.

## Examples

```
enum Color { Red, Green, Blue }
enum Shape { Circle(f64), Square }

function main(): i32 {
    let s = Circle();                 // error[E036]: variant Circle expects 1 argument(s), got 0
    let t = Circle(1.0, 2.0);         // error[E036]: variant Circle expects 1 argument(s), got 2
    let bad = Color.Purple;           // error[E036]: enum Color has no variant "Purple"
    return 0;
}
```

## Fix

Match the declared shape:

```
function main(): i32 {
    let s = Circle(1.0);
    let c = Color.Red;
    return 0;
}
```

For ambiguous variant names (when two enums in scope share
the variant), qualify:

```
match (val) {
    MyEnum.Ok => ...,    // disambiguates
}
```
