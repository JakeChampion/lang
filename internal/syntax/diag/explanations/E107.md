# E107 — a generic function has no last instance

The compiler makes one copy of a generic function for each set
of type arguments that the program calls it with. A generic
function that calls itself with a larger type asks for a new
copy each time: `f[i32]` asks for `f[W[i32]]`, which asks for
`f[W[W[i32]]]`, and so on. That chain has no end.

The limit is 64 levels of type arguments in one instance. The
checker reports the generic function when an instance reaches
the limit.

## Examples

```
struct W[T] { v: T }

// error[E107]: generic function "f" has an instance with 64
// levels of type arguments: a call in its body gives it a
// larger type each time
function f[T](x: T, n: i32): i32 {
    if (n == 0) {
        return 0;
    }
    return f(W[T] { v: x }, n - 1);
}

function main(): i32 {
    return f(1, 3);
}
```

The count `n` stops the calls when the program runs, but the
compiler makes the copies before the program runs. It cannot
know that only three are necessary.

## Fix

- Call the function with the same type that it got:
  `f(x, n - 1)`.
- Put the values that grow in an array or in a recursive enum.
  The type of an array or of a list does not change with its
  length.
- Use a `dyn` value when each level has a different type and
  the function reads it through one trait.
