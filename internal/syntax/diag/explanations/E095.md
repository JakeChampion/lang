# E095 — an unsafe obligation escapes its boundary

An `unsafe function` states obligations that its caller must satisfy before
the call. Only an `unsafe` block accepts them. The block marks the place
where the caller established those obligations. The body of an unsafe
function is not such a place. It needs its own block around each raw call.

Three shapes are refused:

- A call to an unsafe function, method, trait method or imported function
  outside an `unsafe` block.
- An unsafe function used as a value. A function value's type carries no
  obligation, so a later call through it reaches the body unchecked.
- An unsafe implementation of a trait method that the trait declares safe.
  Callers of the trait promise nothing.

```
unsafe function danger(x: i32): i32 {
    unsafe {
        return x + 1;
    }
}

function main(): i32 {
    // error[E095]: unsafe function "danger" is called outside an unsafe block
    let a: i32 = danger(1);
    // error[E095]: unsafe function "danger" cannot be used as a value; a function value carries no unsafe obligation
    let f: (i32) => i32 = danger;
    return a + f(2);
}
```

Fixes: put the call in an `unsafe { … }` block at the point where the
obligations hold. Or write a safe wrapper that validates its inputs and calls
the unsafe function inside its own block. A closure with an `unsafe` block in
its body is an ordinary function value. Declare the trait method `unsafe` when
every implementation needs the obligation.

The contract is in `docs/SAFETY-CONTRACT.md`. The block and the modifier
suppress no other check: types, bounds and ownership rules apply inside an
`unsafe` block exactly as outside it.
