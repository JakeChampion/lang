# E101 — an incorrect capability provider

A target that does not grant a capability can get it from a provider. A
provider is a function with the `@provide("capability")` attribute, in a module
that the program imports. A board module for a freestanding target is the
usual place for one. Then a call that needs the capability calls the provider.

Only `log` takes a provider. A `log` provider is a byte sink with this
signature:

```
@provide("log")
pub function uart_write(data: usize, len: i32): void {
    // Write `len` bytes, starting at `data`, to the device.
}
```

`print` and `eprint` give their text to the provider. The provider gets an
address and a length, not a string, so the call changes no reference count.

This error has three causes:

- The attribute names a capability that takes no provider.
- The provider does not have the signature above.
- The program has two providers of one capability.

```
@provide("log")
// error[E101]: the `log` provider "uart_write" must be a function with the signature (data: usize, len: i32): void
function uart_write(text: string): void {}
```

On a target that grants the capability, the target's own implementation is
used. The provider is then an ordinary function. The rule is in
`docs/FREESTANDING-CORE.md`.
