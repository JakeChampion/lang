# E080: a handler reaches a host effect around its `Platform` bag

A function handed a `platform.Platform` takes its host effects from the bag:
the trait's methods are the log sink, the two clocks, the environment,
configuration, secrets, entropy and outbound HTTP. The free functions
(`eprint`, `now_unix_ms`, `env`, …) still resolve inside such a function, so
nothing in the type system stops a bare call — but a handler that makes one
has an effect no caller can substitute. A mock platform in a test records
nothing, `std/sim` cannot script it, and a target whose bag lacks the
capability cannot refuse it at the bag.

The rule follows the call graph: an effect inside a helper the handler calls
is the handler's, and the message gives the chain that reaches it. A handler
is any top-level function with a parameter of type `platform.Platform` or
`platform.Host`, whatever the parameter is called and wherever it sits. The
bag's own methods are the sanctioned route, so the walk stops at them.

## Example

```fern
import "std/http";
import "std/serve";
import "std/platform";

function stamp(): i64 { return now_unix_ms(); }

function handle(req: HttpRequest, plat: platform.Platform): HttpResponse {   // E080
    eprint("hit " + req.path);
    let at: i64 = stamp();
    return http.ok("");
}
```

```
error[E080]: handler `handle` reaches `eprint` (`log`) around its platform `plat`: handle -> eprint; call `plat.log(…)` …
error[E080]: handler `handle` reaches `now_unix_ms` (`now`) around its platform `plat`: handle -> stamp -> now_unix_ms; call `plat.now_ms(…)` …
```

## Fix

Reach the effect through the bag, passing the bag to any helper that needs
it:

```fern
import "std/http";
import "std/serve";
import "std/platform";

function stamp(plat: platform.Platform): i64 { return plat.now_ms(); }

function handle(req: HttpRequest, plat: platform.Platform): HttpResponse {
    plat.log("hit " + req.path);
    let at: i64 = stamp(plat);
    return http.ok("");
}
```

| Ambient call | Through the bag |
|---|---|
| `eprint(msg)` | `plat.log(msg)` |
| `now_unix_ms()` | `plat.now_ms()` |
| `monotonic_ns()` | `plat.elapsed_ns()` |
| `env(name)` | `plat.env(name)` |
| `random_i32()` | `plat.random_i32()` |
| `fetch.send(req)` | `plat.http(req)` |

An effect the bag does not carry (a file read, stdin, a process) has no
route into a handler: the code that needs it belongs outside the handler, or
the bag has to grow the capability first.

The walk follows named calls, methods and function values named in a body.
A call through a value whose target it cannot name (a closure parameter, a
function-typed field) is not charged, and a lambda that takes the platform
is not a handler: only top-level functions are.
