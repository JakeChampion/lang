# E086 — an import does not resolve to a module

An `import` names a module by path. The program is refused, at the import,
when that path leads to no module:

- **Unknown stdlib module.** A `std/…` or `core/…` path that names no module
  of the standard library.
- **No such file.** A relative path (`./util`, `../shared/net`) or a bare one
  with no module file beside the importing file, and no literate
  `.fern.md` either. Under a `fern.toml`, a bare path that names no file must
  name a dependency the manifest declares.
- **An import cycle.** Module `a` imports `b`, which imports `a` again,
  directly or through other modules. The import that leads back to a module
  still being loaded is reported. Modules of the standard library may import
  each other; a program's own modules may not.

## Examples

```
import "std/nosuch";      // error[E086]: unknown stdlib module "std/nosuch"
import "./missing";       // error[E086]: cannot resolve import "./missing": not found

function main(): i32 {
    return 0;
}
```

With `a.fern` holding `import "./b";` and `b.fern` holding `import "./a";`,
the import in `b.fern` is refused:

```
import "./a";             // error[E086]: import "./a" closes an import cycle
```

## Fix

- Check the spelling of a stdlib path against `fern -doc`.
- A relative path resolves against the directory of the file that writes
  it, and `.fern` is added when the path has no extension.
- Declare a package under `[dependencies]` in the `fern.toml` before
  importing it by name.
- Break a cycle by moving what both modules need into a third module that
  each imports.
