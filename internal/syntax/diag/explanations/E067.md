# E067 — a `@must_consume` value was not consumed on every path

A struct or enum declared with the `@must_consume` attribute carries a
compile-time **obligation**: every value of the type must be consumed
at least once on every control-flow path before its binding goes out
of scope. This is how an API encodes "you must respond to this request
exactly once", "this socket must be closed", "this transaction must be
committed or rolled back" — the forgotten-obligation bug class becomes
a compile error instead of a production incident. (Reference-counting
still does all the actual freeing: E067 is an obligation checker, not
a memory-safety checker, and costs nothing at runtime. See
docs/MUST-CONSUME.md.)

**Consuming uses** — any of these discharges the binding:

- passing it as a call **argument** (the obligation transfers to the
  callee; a callee that takes it as an `own` parameter is the declared
  sink — `own`'s at-most-once affine check and E067's at-least-once
  compose to exactly-once across the boundary);
- **returning** it (the caller inherits the obligation);
- **matching** on it (`match (p) { … }` — destructuring resolves it);
- binding it to another local (`let y = x;` — y is then tracked);
- storing it into another `@must_consume` struct/enum (the container
  carries the obligation onward).

**Violations**:

- reaching scope exit (or a `return` / `break` / `continue` that
  leaves the scope) on some path without a consuming use;
- storing the value into an **unmarked** container (array, tuple, or
  an unmarked struct/enum) — the obligation would be laundered out of
  the checked world; mark the container or consume directly;
- **capturing** the value in a closure (obligation flow into closures
  is not yet modelled);
- overwriting a binding that still holds an unconsumed value;
- writing a call whose result is a `@must_consume` value as a
  statement, which drops the value: bind the result and consume it.

An array literal that is an argument of a call is not a store. It
goes to the callee with the obligation of each element, as in
`async.gather([a, b])`. A closure that is a payload of a
`@must_consume` variant carries the values that it captures.

`async.Future` is `@must_consume`. A future that nothing waits for
is a task that does not finish, so each future reaches `block_on`,
`wait`, a combinator, a `return`, or `async.cancel`.

Field reads and method calls on the value are neutral — they neither
consume nor violate.

Slice-1 limits (deliberate; see docs/MUST-CONSUME.md): loop bodies are
opaque — a consuming use inside `while`/`for` does not discharge the
zero-iteration path, so consume after the loop too (or bind inside the
body). A `loop`, and a `while` with the condition `true`, have no
zero-iteration path, so a consuming use on each path of the body does
discharge the binding; `defer x.close();` does not yet count as consuming (a follow-up
models defer's exit edges); the check is intra-procedural and
at-least-once (double consumption of an unmarked-path is not
rejected — `own` parameters add the at-most-once half where it
matters).
