# E105 — a `@secondary` entry of the wrong shape, a second entry, or a target without a secondary entry

A `@secondary` function is the entry of a second core of a kernel. The board
starts the core with PSCI `CPU_ON`, with the address that `__secondary_entry()`
gives and a context id. The secondary entry of the runtime then calls the
function with that context id.

When the function runs, the core has its own stack of 64 KiB and the vector
table. Its translation is the one that was active when `__secondary_entry()`
ran. The core shares the heap of core 0 and runs no RC code, so the function
uses the atomics to talk to core 0.

The rules are:

- The function takes one `usize`, the context id, and returns `void`.
- A program has at most one `@secondary` function.
- Only `-target arm64-kernel` has a secondary entry.

`@secondary` implies `@norc`, so E102 also applies to the body: it allocates
nothing and does no RC operation.

```
@secondary
function count(): void {
    // error[E105]: `@secondary` function "count" must take one usize, the context id, and return void
}
```

## Fix

Give the function one `usize` parameter, and keep one `@secondary` function
for each program.

```
@secondary
function count(context: usize): void {
    unsafe {
        let old = __atomic_fetch_add(context, 1i64);
    }
}
```
