# E042 — `?` operator error

The `?` operator (early-return on `None` / `Err`) has
several wiring requirements:

- **Must be used inside a function.** `?` desugars to a
  `return None;` / `return Err(...);` — needs a surrounding
  function to return from.
- **Operand must be `Option` or `Result`.** `42?` rejects.
- **Surrounding function's return type must match.**
  - `Option?` requires the function to return
    `Option[_]`.
  - `Result?` requires the function to return
    `Result[_, E]` with an error type the operand's converts
    to (below).
- **Malformed Option / Result type.** The operand was a
  shape that looks like `Option` / `Result` but the
  checker couldn't unwrap its inner type. Rare; signals
  a checker bug or a misuse of the type system.

## Example

```
function f(): i32 {
    let x = Some(42)?;        // error[E042]: `?` on Option requires the surrounding function to return Option, got i32
    return x;
}
```

## Fix

Change the function's return type, or unwrap manually with
`match`:

```
function f(): Option[i32] {
    let x = Some(42)?;
    return Some(x);
}
```

Manual unwrap (no `?`):

```
function f(): i32 {
    return match (Some(42)) {
        Some(v) => v,
        None => 0,
    };
}
```

## Error-type compatibility on Result

`?` passes a `Result`'s error on as it is when it is the surrounding
function's error type, and otherwise converts it one of two ways.

Into a `dyn` error type, by boxing it, when the error type implements
every trait of the `dyn` set. `IoError`, `fetch.FetchError` and
`net.NetError` all implement `error.Error`:

```
import "std/error";

function load(path: string): Result[i32, dyn error.Error] {
    let text: string = read_file(path)?;   // boxes the IoError
    return Ok(text.len());
}
```

An error type without the impl is refused with
`` `?` cannot box Oops into dyn error.Error: Oops does not implement error.Error ``.

Into another concrete error type, through that type's `from` constructor
(std/convert's `impl From[IoError] for MyError`). Without one:

```
function calls(): Result[i32, MyError] {
    let text: string = read_file("x")?;   // error[E042]: `?` on Result carrying IoError but the surrounding function carries MyError, and MyError has no `from(IoError)` constructor to convert it (std/convert's `impl From[IoError] for MyError`)
    return Ok(text.len());
}
```
