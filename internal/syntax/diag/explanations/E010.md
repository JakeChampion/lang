# E010 — Reserved built-in name

A user declaration tried to use a name that the compiler
reserves for a built-in type (`Option`, `Result`, `IoError`,
`Body`, `Reader`, `Writer`, `Map`, `MapIter`, `Url`,
`HttpRequest`, `HttpResponse`, `Platform`, `HeaderMap`,
`Instant`, `Date`, `Time`, `DateTime`, `Span`, `Duration`,
`FileStat`, `ProcessResult`).

The runtime helpers and the IR pair-form lower step hard-code
the shapes of these types (variant order, field offsets). If a
user declaration replaces one, the compiler produces wrong code
with no diagnostic. For example, `enum Option { None, Some(T) }`
has the variants in the opposite order, so pair-form and
heap-form returns disagree.

A free function also cannot use the name of an unsafe
intrinsic: a raw builtin that only an `unsafe` block can call,
such as `__load_u8`, `__memcpy` or `__alloc`.
`docs/security/UNSAFE-INVENTORY.md` lists them. A function of
the program can shadow other builtins, such as `print` or
`args`. A name that only starts with the prefix of an intrinsic
family, such as `__port_text`, is not a builtin.

## Example

```
struct HttpRequest { method: string }   // error[E010]: struct "HttpRequest" is a reserved built-in name and cannot be redeclared
function __load_u8(x: i32): i32 { return x; }   // error[E010]: function "__load_u8" is a reserved built-in name and cannot be redeclared
```

## Fix

Pick a different name. A user declaration can refer to a
built-in. It cannot replace one.

```
struct MyRequest { method: string }
```

## Full reserved list

`IsReservedName` in `internal/check/checker/checker.go` holds
the list of reserved types. `UnsafeIntrinsics` in the same file
holds the list of unsafe intrinsics.
