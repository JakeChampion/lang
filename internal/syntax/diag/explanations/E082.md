# E082 — a closure captures a borrowed view

A closure captured a value that holds a **borrowed view**: a `str`, a `[T]`
slice, a `MapIter` cursor, or a struct, enum, tuple, array or map with one
inside it. A view holds no reference count on the storage it reads, so it is
valid only while that storage's owner is alive.

E063 and E065 keep a view from outliving its owner by checking where the
view goes: they can see a `str` or `[T]` in a return type or a field type.
A function value's type cannot show this. `() => i32` says nothing about
what its environment holds, so once a view is captured, a closure can carry
it out of the function, into a record, or past the block its source lives
in, and no rule can see the view go. Fern therefore refuses the capture
itself.

## Example

```
import "std/array";

function count_matches(lines: string[], word: str): i32 {
    // error[E082]: closure captures "word", which holds a borrowed view
    let hits: string[] = lines.filter((l: string): boolean => l == word);
    return hits.len();
}
```

The same applies when the view is inside another value:

```
struct Word { text: str }

function make(s: string): () => i32 {
    let sp: Word = Word { text: slice_unchecked(s, 0, 2) };
    return () => sp.text.len();   // error[E082]: closure captures "sp"
}
```

## Fixing it

Copy the view into an owned value before the closure, and capture the copy:

```
import "std/array";
import "std/string";

function count_matches(lines: string[], word: str): i32 {
    let owned: string = word.to_owned();
    let hits: string[] = lines.filter((l: string): boolean => l == owned);
    return hits.len();
}
```

A record that holds a view gets an owned twin: give it a `string` (or
`T[]`) field instead of a `str` (or `[T]`) one.

A view passed straight to a call, rather than captured, needs no copy:
a parameter borrows its argument for the length of the call.
