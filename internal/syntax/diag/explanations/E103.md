# E103 — an `@interrupt` handler of the wrong shape, or for a target without a vector table

An `@interrupt("slot")` function is an exception handler. The kernel image
puts the handler in its vector table: the `VBAR_EL1` table on arm64, or the
IDT on x86-64. A trampoline calls the handler and returns with `eret` or
`iretq`.

The rules are:

- On `-target arm64-kernel`, the slot is `"sync"`, `"irq"`, `"fiq"` or
  `"serror"`.
- On `-target x86-64-kernel`, the slot is an exception mnemonic from `"de"`
  to `"cp"`, or a number from `"32"` to `"255"`.
- At most one handler takes each slot.
- The handler takes no parameters and returns `void`.
- Only the two kernel targets have a vector table.

`@interrupt` implies `@norc`, so E102 also applies to the body of the handler.

```
@interrupt("reset")
function on_reset(): void {
    // error[E103]: `@interrupt` function "on_reset" names the slot "reset", which is no slot of an arm64 vector table or an x86-64 IDT
}
```

## Fix

Name a slot of the target, and give each slot one handler. A handler can
write data to memory or to a system register. The code that the exception
interrupted can then read it.

```
@interrupt("irq")
function on_irq(): void {
    unsafe {
        __sysreg_write("tpidr_el1", 1i64);
    }
}
```
