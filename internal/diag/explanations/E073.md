# E073: `drop` is a finalizer, not a method to call

`core/mem.Drop` gives a type a **finalizer**. The reference-counting
runtime calls it from the type's generated drop glue, at the moment the
value's last reference goes away and before its fields are reclaimed.
Nothing in your source calls it — that is the point of it.

Calling it by hand runs the body a second time, on a value the runtime is
still going to finalize:

```fern
import "core/mem";

struct FileWriter { handle: File }

impl mem.Drop for FileWriter {
    function drop(self: Self) { self.handle.close(); }
}

function save(w: FileWriter): i32 {
    w.drop();       // E073: the runtime will run this again
    return 0;
}
```

That closes the handle twice, and whatever a finalizer releases — a file
descriptor, a socket, a buffer handed to a C library — it releases twice.
Nothing reports it; the second release just corrupts whatever has since
taken the slot.

## What to write instead

Let the value die. `drop` fires when the last reference goes away, so
ending the value's lifetime is the whole API:

```fern
function save(w: FileWriter): i32 {
    write_all(w);   // w's last use — the finalizer runs after this
    return 0;
}
```

If you want cleanup at a *function's* end rather than a *value's*, that
is `defer`, which fires when the enclosing call returns no matter who
still holds the value:

```fern
function save(path: string): i32 {
    var w: FileWriter = open_writer(path);
    defer flush_index();
    return write_all(w);
}
```

And if what the method does is genuinely useful to callers, it is not a
finalizer — give it its own name (`close`, `release`, `finish`) and call
that. A type may have both: the named method for the explicit path, and
a `Drop` impl that calls it for the path where nobody remembered.

## When this does not fire

Only a `drop` on a type with a `core/mem.Drop` impl is rejected. A method
that happens to be called `drop` on a type with no such impl is an
ordinary method — nothing generates glue for it, so nothing calls it
twice:

```fern
struct Stack { items: i32[] }
function (s: Stack) drop(): Stack { return Stack { items: s.items[1:] }; }

function main(): i32 { var s: Stack = Stack { items: [1, 2] }; return s.drop().items.len(); }
```

## A note on reliability

A `Drop` finalizer runs when the refcount reaches zero, and a value the
reclamation analysis cannot yet prove dead simply never gets there — its
`drop` does not run at all. `Drop` is a cleanup hook, not a guarantee;
do not hang correctness on it firing. That is a further reason not to
reach for a manual `v.drop()` as a workaround: the fix for a finalizer
that did not run is to shorten the value's lifetime, not to run the body
a second time somewhere else.
