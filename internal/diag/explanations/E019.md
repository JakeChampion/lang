# E019 — Generic type-parameter count mismatch

A generic struct or enum reference supplied the wrong number
of type arguments. Fern requires exact arity — every generic
parameter must be filled at every use site.

## Example

```
struct Pair[A, B] { first: A, second: B }

function main(): i32 {
    var p: Pair[i32] = Pair { first: 1, second: 2 };   // error[E019]: struct Pair has 2 type parameter(s), 1 supplied
    return p.first;
}
```

## Fix

Supply every type argument.

```
function main(): i32 {
    var p: Pair[i32, i32] = Pair { first: 1, second: 2 };
    return p.first;
}
```

## Type inference

Fern's checker DOES infer type arguments from struct-literal
field types when the annotation is omitted entirely:

```
function main(): i32 {
    var p = Pair { first: 1, second: 2 };   // inferred as Pair[i32, i32]
    return p.first;
}
```

So if you don't need the explicit annotation, drop it.

## See also

- Same rule applies to enums (`Result[T, E]` needs both).
- E002 (type mismatch) — fires when the count is right but
  the inferred argument doesn't match the constraint.
