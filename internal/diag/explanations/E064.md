# E064 — unknown type

A type annotation names a type that no declaration defines. The name is
not a built-in (`i32`, `i64`, `u32`, `u64`, `f32`, `f64`, `boolean`,
`string`, `void`), not a declared `struct` / `enum` / `trait` / `resource`,
and not a type parameter in scope.

Before this rule the checker silently accepted an undefined name as an
opaque nominal type, so the mistake surfaced only indirectly — as a
confusing assignment mismatch (E003), a return-type mismatch (E002), or
nothing at all for an unused parameter — instead of pointing at the
annotation itself.

## What is rejected

```
function f(a: Wibble): i32 { return 0; }   // unknown parameter type
function g(): Wibble { ... }               // unknown return type
struct S { field: Wibble }                 // unknown field type
function main(): i32 { var x: Wibble = 0; return 0; }  // unknown var type
```

A common cause is reaching for a type name from another language: the
boolean type is spelled `boolean` (not `bool`), and the integer type is
`i32` (not `int`).

## What is allowed

- the built-in scalars and `string` / `void`;
- any `struct` / `enum` / `trait` / `resource` declared in the program or
  an imported module (declarations are visible regardless of source
  order — a type may be used before it is declared);
- a type parameter in scope, e.g. `T` inside `function id[T](x: T): T`.

## Fixing it

Declare the type, import the module that defines it, correct the spelling
(`boolean` / `i32` / `string`), or — inside a generic — add the name to
the function's / type's `[…]` type-parameter list.
