# E066 — target does not provide a required capability

Each compilation target declares the host **capabilities** its runtime
actually wires — filesystem access (`fs`), sockets (`tcp`), blocking
stdin reads (`stdin`), process spawning (`subprocess`), process
supervision (`proc` — `proc_fork`/`proc_waitpid`, native targets
only), … — in its
platform descriptor (`fern -targets` lists them). A program compiled
for a target may only reach runtime builtins whose capability that
target grants; this error means the compiled call graph (after unused
imported functions are tree-shaken away) still contains a call the
target cannot satisfy.

Typical cases:

- `subprocess(...)` compiled with `-target wasm32-wasi`: the CLI wasm world
  has no process-spawning interface wired (wasi:cli/exec-process is a
  standing gap), so the call could only fail at build or run time —
  E066 rejects it up front.
- `read_file(...)` / `tcp_listen(...)` / `read_line()` compiled with
  `-target wasm32-wasi-http`: the proxy world serves one HTTP request per
  invocation and exposes no filesystem, listener sockets, or stdin.

The error message names the missing capability, the builtin that needs
it, and the targets that do provide it. Fixes, in order of likelihood:

1. **Compile for a target that grants the capability** (the message
   lists them — native targets grant everything).
2. **Gate the call by target** — restructure so the capability-needing
   code path isn't reached (and isn't referenced) in the restricted
   build; unused imports are fine, only reachable calls count.
3. **If the capability genuinely should exist on the target**, the
   descriptor lives in `internal/platforms/platforms.go` and the gate
   table in `internal/platforms/enforce.go` — a capability may be
   added once the target's runtime actually wires the builtin family.

Only the call graph that survives tree-shaking is checked: importing a
module whose *other* functions use gated builtins does not trigger
E066. Calls reached through functions of an imported module are
reported without a source caret (the position belongs to the imported
module's source); the message names the function and module instead.
