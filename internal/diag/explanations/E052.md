# E052 — `own` is not yet supported on methods

A method (a receiver method `function (b: Box) m()` or a trait-impl
method `function m(self: Self)`) declared an `own` (owned / consuming)
parameter — on the receiver or another parameter. `own` is currently
supported only on **free functions**.

The reason is implementation, not design: a method *call*'s receiver and
argument ownership transfer isn't wired yet (the move-on-call analysis
and the E051 ownership guard skip method calls), so an `own` method would
type-check and then **double-free at runtime** — the caller drops the
receiver *and* the callee reclaims it. Rejecting it here keeps that
footgun out of reach until method support lands.

## Example

```
struct Box { v: i32 }
trait Consume { function eat(self: Self): i32; }
impl Consume for Box {
    function eat(own self: Box): i32 { return self.v; }   // error[E052]
}
```

## Fix

Write the consuming operation as a **free function** that takes the value
`own`:

```
struct Box { v: i32 }
function eat(own b: Box): i32 { return b.v; }

function main(): i32 {
    return eat(Box { v: 5 });   // a fresh (owned) value transfers fine
}
```

A free function with `own` parameters has the full feature: affine
use-after-move checking (E050), the call-site ownership guard (E051),
ownership transfer, and — for an `own` enum scrutinee — consuming-match
reclamation (the FBIP recursive-traversal win).
