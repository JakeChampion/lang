# E052 — missing return in a value-returning function

A function declares a non-void return type but has a control-flow path
that falls off the end without returning a value. Fern requires every
path through a value-returning function to either `return` a value or
diverge (an infinite `while (true)` loop). Falling off the end would
leave the result undefined — the interpreter yields a void value where a
real one is expected and crashes downstream; a compiled scalar silently
reads 0.

## Example

```
struct Point { x: i32, y: i32 }

function f(b: boolean): Point {
    if (b) {
        return Point { x: 10, y: 20 };
    }
    // error[E052]: when b is false, control falls off the end
}
```

## Fix

Return a value on every path — add a trailing `return`, or an `else`:

```
function f(b: boolean): Point {
    if (b) {
        return Point { x: 10, y: 20 };
    }
    return Point { x: 0, y: 0 };
}
```

A `match` that returns from every arm, or an `if`/`else` where both
branches return, also satisfies the check, as does a function whose body
ends in a non-terminating `while (true)` loop.

## See also

- E012 (`return` without value) — the path reaches a `return` but omits
  the value.
- E002 (return type mismatch) — a value is returned but has the wrong
  type.
