# E040 — Generic type-parameter inference / arity error

Two failure modes when calling a generic function or
constructing a generic struct:

- **Wrong type-arg count.** When the user supplies explicit
  type arguments — at a call site or on a struct literal —
  they must match the generic decl's parameter count.
- **Inference failed.** The arguments or field values didn't
  pin down every type parameter. Both sites can name the type
  arguments themselves: `foo[i32, string](...)` for a call,
  `Box[i32] { … }` for a struct literal. On a method the args
  go after the method name (`h.make[i32]()`). An annotation on
  the binding works as well, and the enclosing return type can
  supply them too.

## Examples

```
function pair[A, B](a: A, b: B): (A, B) { return (a, b); }

function main(): i32 {
    var p = pair(1, "hello");     // OK — inferred as (i32, string)
    return p.0;
}

function empty[T](): T[] { return []; }

function main2(): i32 {
    var xs = empty();             // error[E040]: could not infer type parameter T for empty — supply it explicitly at the call site (e.g. empty[i32](...)) or annotate the binding
    return xs.len();
}

struct Stack[T] { items: T[] }

function main3(): i32 {
    var s = Stack { items: [] };  // error[E040]: could not infer type parameter T for struct Stack — supply it explicitly at the construction site (e.g. Stack[i32] { ... }) or annotate the binding (e.g. var x: Stack[i32] = ...)
    return s.items.len();
}
```

`[]` cannot pin `T`, so nothing in the literal decides which
`Stack` is being built. A phantom parameter — one no field
mentions at all — can never be inferred:

```
struct Tagged[T] { n: i32 }
```

A generic method is reported as `Type.method`, and its type
arguments attach to the method name:

```
struct Holder { n: i32 }
function (h: Holder) make[T](): T[] { return []; }

function main4(): i32 {
    var h = Holder { n: 1 };
    var xs = h.make();            // error[E040]: could not infer type parameter T for Holder.make — supply it explicitly at the call site (e.g. .make[i32](...)) or annotate the binding
    return xs.len();
}
```

## Fix

Name the type argument where the value is produced:

```
function main2(): i32 {
    var xs = empty[i32]();
    return xs.len();
}

function main3(): i32 {
    var s = Stack[i32] { items: [] };
    return s.items.len();
}

function main4(): i32 {
    var h = Holder { n: 1 };
    var xs = h.make[i32]();
    return xs.len();
}
```

An annotation on the binding does the same job, and is the
only option when the value comes from somewhere you cannot
add type arguments to:

```
function main5(): i32 {
    var xs: i32[] = empty();
    var s: Stack[i32] = Stack { items: [] };
    var t: Tagged[i32] = Tagged { n: 1 };
    return t.n + s.items.len() + xs.len();
}
```
