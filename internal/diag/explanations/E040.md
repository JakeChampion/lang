# E040 — Generic type-parameter inference / arity error

Two failure modes when calling a generic function or
constructing a generic struct:

- **Wrong type-arg count at the call site.** When the user
  supplies explicit type arguments, they must match the
  generic decl's parameter count.
- **Inference failed.** The call's argument types didn't pin
  down every type parameter. A call site can name the type
  arguments itself (`foo[i32, string](...)`); a struct literal
  cannot, so there the type has to come from the binding or
  the enclosing return type.

## Examples

```
function pair[A, B](a: A, b: B): (A, B) { return (a, b); }

function main(): i32 {
    var p = pair(1, "hello");     // OK — inferred as (i32, string)
    return p.0;
}

function empty[T](): T[] { return []; }

function main2(): i32 {
    var xs = empty();             // error[E040]: could not infer type parameter T for empty — supply it explicitly at the call site (e.g. empty[i32](...)) or annotate the binding
    return xs.len();
}
```

## Fix

Name the type argument at the call site:

```
function main2(): i32 {
    var xs = empty[i32]();
    return xs.len();
}
```

An annotation on the binding works too, and is the only
option for a generic struct literal — no field value pins
`T` in a phantom parameter:

```
struct Tagged[T] { n: i32 }

function main3(): i32 {
    var xs: i32[] = empty();
    var t: Tagged[i32] = Tagged { n: 1 };
    return t.n + xs.len();
}
```
