# E055 — the result of a collection operation is unused

Collection operations such as `.append`, `.with`, `insert`, `without`, and
`cleared` are **pure**: they return a new (possibly freshly-allocated)
collection rather than mutating the receiver in place. Writing one as a bare
statement therefore does nothing useful — the new value is computed and
immediately discarded, while the original is unchanged. This is the aliasing
footgun the rule closes: code that *looks* like an in-place mutation but
silently has no effect.

## What is rejected

```
var xs: i32[] = [1, 2, 3];
xs.append(4);            // error[E055]: the new array is discarded; xs is unchanged
```

## Fixing it

Assign the result back, since the operation returns the updated collection:

```
xs = xs.append(4);       // xs is now [1, 2, 3, 4]
```

If discarding really is intentional, bind it explicitly so the intent is
visible: `var _ = xs.append(4);`.
