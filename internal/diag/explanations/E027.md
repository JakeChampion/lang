# E027 — Match guard must be boolean

A `match` arm's guard clause (`Pattern if EXPR => …`)
evaluated to a non-boolean type. The guard runs after the
pattern matches; the arm body only executes when the guard
returns `true`, so the guard expression must produce a
boolean.

## Example

```
match (n) {
    x if x => { return 1; },   // error[E027]: match guard must be boolean, got i32
    _ => { return 0; },
}
```

## Fix

Add an explicit comparison:

```
match (n) {
    x if x > 0 => { return 1; },
    _ => { return 0; },
}
```

## Why no implicit truthy-coercion

Same reasoning as E008: Fern doesn't accept "truthy"
integers / strings / option-Some as conditions. Forcing the
explicit boolean makes the guard's intent visible — saves
the reader from having to remember which value shapes count
as truthy.

- E008 (non-boolean condition) — same shape for `if` /
  `while` / `for` conditions.
