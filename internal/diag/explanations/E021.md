# E021 — Invalid method receiver / trait conformance

The method declaration's receiver references a type the
checker can't dispatch on, or a trait obligation isn't
satisfied. Receiver forms:

- **Unknown struct.** The receiver names a struct that
  isn't declared anywhere.
- **Unknown enum.** Same for enums.
- **Wrong receiver kind.** The receiver type isn't a
  struct, enum, or built-in (e.g. naming a type alias or a
  generic parameter as the receiver).

Trait-conformance forms (the same code covers the whole
family):

- **Incomplete or mismatched impl.** An `impl Trait for
  Type` that omits a required method, gets a signature
  wrong, or misses a supertrait impl.
- **Unsatisfied bound.** A call's type argument doesn't
  implement the trait its parameter is bound by
  (`f[T: Ord]` called with a type lacking `Ord`).
- **Object safety.** A `dyn Trait` of a trait whose methods
  can't dispatch through a vtable.
- **Underivable derive.** `@derive(Eq/Ord/Hash)` on a type
  whose field (or enum variant payload) type doesn't itself
  implement the trait — the derived method compares
  field-wise, so every field type needs an impl (or its own
  derive):

  ```
  trait Ord { function cmp(self: Self, other: Self): i32; }
  @derive(Ord)                       // error[E021]: cannot @derive(Ord) for Foo:
  struct Foo { x: i32 }              //   field x of type i32 does not implement Ord
  ```

  Fix: add `impl Ord for i32` (or import a module that
  provides it, e.g. `core/cmp` for the stdlib traits), or
  remove the derive.

## Example

```
pub function (p: Pomt) area(): i32 {   // error[E021]: method receiver type must be a struct, enum, array, slice, or built-in type, got Pomt
    return p.x * p.y;
}
```

## Fix

Spell the type name correctly, or declare it.

```
struct Point { x: i32, y: i32 }

pub function (p: Point) area(): i32 {
    return p.x * p.y;
}
```

## Allowed receiver types

- Concrete structs: `(p: Point)`.
- Concrete enums: `(s: Status)`.
- Built-in types: `(n: i32)`, `(s: string)`, `(r: Reader)`,
  etc. — methods on built-ins live in stdlib modules like
  `std/i32` and `std/string`.
