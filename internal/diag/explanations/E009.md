# E009 — Operator requires integer-compatible operands

An arithmetic / bitwise / comparison operator received operands
that aren't compatible. Two flavours:

- **Both sides must be integers** — `+ - * / % | & ^ << >>`
  reject non-integer types entirely (including floats — float
  arithmetic uses the same operators but the checker tags
  them via `IsFloat`).
- **Both sides must share the same integer type** — mixed
  `i32 + i64` rejects; you must `as`-cast one side first.
  Fern doesn't widen implicitly.

## Example

```
function f(a: i32, b: i64): i64 {
    return a + b;   // error[E009]: operator "+" requires both operands to share an integer type; got i32 and i64
}
```

## Fix

Add an explicit `as` cast:

```
function f(a: i32, b: i64): i64 {
    return (a as i64) + b;
}
```

## Why no implicit widening

Implicit `i32 → i64` widening seems harmless until the same
shape applies to `u32 → i32` (where -1 silently becomes
2^32-1), `f32 → f64` (lossy at the i32 boundary), or
`bool → i32`. Fern requires every type change to be a visible
cast — same trade as Rust and Zig.
