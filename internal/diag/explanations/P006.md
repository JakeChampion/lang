# P006 — `function` in expression position

`function` introduces a **named declaration**. It is not an expression,
so it cannot appear where a value is expected — the right-hand side of a
`var`, a call argument, a returned value.

An anonymous function is written as an **arrow lambda**.

## Example

```
function main(): i32 {
    var f = function (x: i32): i32 { return x + 1; };   // error[P006]
    return f(41);
}
```

## Fix

```
function main(): i32 {
    var f = (x: i32): i32 => x + 1;
    return f(41);
}
```

The parameter list is the same, the return type is optional, and the body
may be an expression or a braced block:

```
(x: i32) => x * 2                      // expression body
(x: i32): i32 => { return x * 2; }     // braced body
(x: i32) => { record(x); }             // statements only — the lambda is void
(x: i32) => { var y: i32 = x; y * 2 }  // a trailing value is returned
```

A braced body is an ordinary function body: `use`, `let … else`, `defer`
and the rest mean there exactly what they mean inside a named function.

The anonymous `function (…) { … }` spelling was retired in #2673 — it and
the arrow form built the same node, and one spelling per construct is the
whole point. `function` now always introduces a name, so the parser knows
which form it is reading at the keyword.
