# E065 — returning a `str` view of a function-local string

A `str` is a **non-owning** view of a UTF-8 string — a `{data_ptr, len}`
pair with no reference-count handle on the backing `string`. It stays
valid only as long as that backing string does. Returning a `str` that
views a string allocated *inside the function* is therefore a
use-after-free: when the function returns, the frame's last owning
reference to the string drops, the reference-counting passes may reclaim
the storage, and the returned `data_ptr` dangles.

This is the `str` half of the same lifetime contract E063 enforces for
`[T]` slices (`docs/LANGUAGE-DIRECTION.md`, "Slice / view lifetime
contract") — the borrowed-view sibling of the owned `string`. The
language otherwise goes to great lengths (E048/E049/E057/E063, the RC
never-over-release invariant) to make memory errors unconstructible.

## What is rejected

Returning a `str` the checker can prove views a function-local string —
an identifier chain that bottoms out at a locally-declared owned
`string` binding (the chase is intraprocedural and cycle-guarded, and
excludes parameters):

```
// error[E065]: the backing string is reclaimed when "greeting" returns
function greeting(): str {
    var s: string = "hello, " + name();
    return s;                 // `str` view of local `s` — dangles
}
```

## What is allowed

- **Viewing a parameter or receiver** — the caller owns the backing
  string, which outlives the call:
  `function first_word(s: string): str { … }`.
- **A string literal** — `'static` / immortal storage, nothing to
  dangle.
- **Returning an owned `string`** — that's a move, not a view.

## Fixing it

Either materialise an owned copy with `.to_owned()` and return the owned
`string`, or take the string as a parameter so the caller's value (which
outlives the call) is the one being viewed:

```
// OK: hand back an owned string (a move).
function greeting(): string {
    var s: string = "hello, " + name();
    return s;
}

// OK: view a parameter — the caller's string outlives the call.
function first_word(s: string): str {
    return s.split(" ")[0];
}
```

Like E063, `return` is the only checked escape position today, and the
chase is intraprocedural — a view laundered through a `str`-returning
callee is not yet chased (the same known hole as the slice rule; both
tighten together later).
