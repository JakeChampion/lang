# E079: `?` inside a `defer` or `errdefer` action

A deferred action runs on the exit edges of the function that registered it —
including the failure edge `?` takes. So `?` directly inside one is circular by
construction: the failure edge replays the deferred actions, one of which is the
action carrying the `?`, whose failure edge replays them again.

It is refused rather than given a meaning. `?` propagates a failure to the
caller, and a deferred action has no caller to propagate to.

## Example

```fern
function g(v: i32): Option[i32] {
    if (v < 100) { return Some(v + 1); }
    return None;
}

function build(out: Cell[i32]): Option[i32] {
    var n: i32 = 0;
    defer n = g(n)?;   // E079
    out.set(n);
    return Some(n);
}
```

The rule follows the exits, not the syntax. A `defer` nested in a lambda body
registers on the LAMBDA's exits, so a `?` in its action is the same refusal one
level down. A `?` inside a lambda that is merely part of the action is a
different thing — it leaves the lambda, not the function whose defer replays the
action — and E079 does not fire there.

That second case is not a way out of this error today: `?` anywhere in a lambda
reads the enclosing function's return type rather than the lambda's and draws
E042 (#9515).

## Fix

Handle the failure inside the action instead of propagating it:

```fern
    defer n = match (g(n)) { Some(v) => v, None => n };
```

Or move the fallible work out of the action, to a point in the function where
`?` has a caller to return to.
