# E071 — a literal outside the Unicode scalar range was cast to `char`

`char` is a **Unicode scalar value**: an integer in `0..0x10FFFF` that is
not one of the UTF-16 surrogates `0xD800..0xDFFF`. That domain is the
type's whole point — it is the guarantee every encoder downstream relies
on — so a *literal* naming something outside it is rejected at compile
time.

```fern
var a: char = 1114112 as char;  // E071: past the maximum, 0x10FFFF
var b: char = 55296 as char;    // E071: 0xD800 is a surrogate
```

Two separate rules are at work, and the message says which one you hit:

- **The range.** `0x10FFFF` is the largest code point Unicode defines, a
  ceiling fixed by what UTF-16 can address. Nothing above it is a
  character.
- **The surrogates.** `0xD800..0xDFFF` are reserved as the two halves of
  a UTF-16 surrogate *pair*. A lone one is not a character — it is half
  of an encoding — so it is excluded even though it sits inside the
  range.

**The fix** depends on where the value comes from. If it is a constant
you got wrong, correct it:

```fern
var ok: char = 0x10FFFF as char;   // the maximum scalar value
var hi: char = 128512 as char;     // U+1F600, an astral emoji — fine
```

If the value is only known at run time, use the checked constructor,
which returns `None` for exactly the cases above:

```fern
import "std/utf8";

match (utf8.char_from_i32(n)) {
    Some(c) => { /* n was a scalar value */ },
    None    => { /* out of range, or a surrogate */ }
}
```

## Why a run-time cast is *not* checked

`n as char` on a non-literal compiles without complaint. That is
deliberate, not an oversight: the cast is the deliberate reinterpret
hatch, and `std/unicode` uses it on values its own tables have already
proven are scalars. Re-validating those on every lookup would be pure
cost with no reachable failure.

The consequence is that an invalid `char` *can* exist at run time if you
cast an unvalidated integer. Encoders are written to cope — `utf8_encode`
substitutes U+FFFD (the REPLACEMENT CHARACTER) rather than emitting
malformed UTF-8 — but you get a replacement character, not your value.
Reach for `as char` when you can prove the value; reach for
`utf8.char_from_i32` when you cannot.
