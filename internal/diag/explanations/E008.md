# E008 — Non-boolean condition

An `if`, `while`, or ternary's condition expression evaluated
to a non-boolean type. Unlike C / Python / JavaScript, Fern
doesn't coerce integers / strings to truthy/falsy — the
condition must be `boolean`.

## Example

```
function main(): i32 {
    var n: i32 = 1;
    if (n) { return 1; }   // error[E008]: if condition must be boolean, got i32
    return 0;
}
```

## Fix

Add an explicit comparison:

```
function main(): i32 {
    var n: i32 = 1;
    if (n != 0) { return 1; }
    return 0;
}
```

## Why no implicit coercion

The Five-Mistakes-Bad-Languages-Make article from
[`docs/STDLIB-DESIGN-RESEARCH.md ▸ Date/time`](../../docs/STDLIB-DESIGN-RESEARCH.md) lists implicit
truthy-coercion as one — JavaScript's `if (x)` accepting
strings, numbers, undefined, etc. is a well-known source of
bugs. Forcing the comparison makes the intent visible.
