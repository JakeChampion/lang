# E045 — Map key / value type error

Three related errors on map literals:

- **Unsupported key type.** Keys must be an integer, a
  `string`, or a struct/enum that implements `Eq` and
  `Hash` — the keyed runtime dispatches through those two
  methods. Floats, tuples, arrays and slices reject.
- **Mixed key types.** Every entry's key must share the
  same type — first entry's type fixes the inferred map's
  key type, subsequent entries must match.
- **Mixed value types.** Same for values — first entry
  fixes the type, subsequent entries must match.

## Examples

```
import "core/map";

function main(): i32 {
    var ok = Map { 1: "a", 2: "b" };               // OK — Map[i32, string]
    var bad_k = Map { 1: "a", "two": "b" };        // error[E045]: map key type string, expected i32
    var bad_v = Map { 1: "a", 2: 42 };             // error[E045]: map value type i32, expected string
    var bad_kt = Map { 1.5: "a" };                 // error[E045]: map key type f64 is not yet supported — use i32, string, or a struct/enum with `@derive(cmp.Eq, cmp.Hash)`, which requires `import "core/cmp";`
    return ok.len();
}
```

## Fix

Align every entry's key and value types. Cast where the
underlying values can be converted.

A struct or enum key needs both derives, and the traits
live in `core/cmp` — there is no prelude, so the names
only resolve qualified and the import has to be there:

```
import "core/map";
import "core/cmp";

@derive(cmp.Eq, cmp.Hash)
struct Key { a: i32, b: string }

function main(): i32 {
    var m = Map { Key { a: 1, b: "x" }: 10 };
    return m.len();
}
```

A bare `@derive(Eq, Hash)` is `error[E021]: unknown trait`.

When the key type comes from ANOTHER module, neither route
is available where you are standing: `@derive` annotates a
declaration you do not own, and a local `impl cmp.Eq for
mod.Key` is an orphan impl. The derives have to be added in
the module that declares the type, and the message names
that module rather than a spelling you cannot write.

## Why floats and composites reject

The Map runtime ([`internal/stdlib/core/map.fern`](../../internal/stdlib/core/map.fern))
hashes and compares a key either natively (integers,
strings) or through the key type's derived `hash` / `eq`.
Tuples, arrays and slices have neither. f32/f64 keys are
unlikely regardless — NaN equality semantics are a
separate correctness landmine.
