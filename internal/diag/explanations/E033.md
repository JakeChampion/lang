# E033 — Unsupported cast

The `EXPR as TYPE` form requested a cast Fern doesn't
support. The supported casts are deliberately narrow:

- **Numeric ↔ numeric**: `i32 as i64`, `u32 as i32`,
  `f64 as f32`, etc. Width changes are explicit; sign
  changes go through the same `as` form.
- **`[u8]` / `u8[]` / `string` ↔ `i32` data-pointer hops**:
  unsafe casts used by FFI shims and the WASM bridge.
  Each side's payload pointer is the i32 value; the cast
  is a no-op at runtime.
- **`i32 → T[]`**: same data-pointer trick for typed array
  recovery.

Anything else — struct-to-struct, enum-to-enum, function-
to-function, struct-to-int — rejects.

## Example

```
struct Point { x: i32, y: i32 }
struct Vec2  { x: i32, y: i32 }

function f(p: Point): Vec2 {
    return p as Vec2;   // error[E033]: cannot cast Point to Vec2 ...
}
```

## Fix

Construct the target type from the source explicitly. Fern
doesn't trust "structurally-compatible" implicit conversions
— two structs with the same field shape are still distinct
types.

```
function f(p: Point): Vec2 {
    return Vec2 { x: p.x, y: p.y };
}
```

## Why no struct-to-struct cast

Two structs with identical field layouts can still mean
different things (a `Position` is not a `Velocity`). Forcing
explicit construction makes the conversion visible at the
call site and prevents accidental aliasing.
