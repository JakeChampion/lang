# E048 — Field is immutable after construction

A program tried to reassign a struct field in place
(`obj.field = value`). Fern is an immutable-data-structures
language: once a value is constructed, its fields can't be
mutated. Designing post-construction mutation out of the
language makes reference cycles unconstructible, so reference
counting stays garbage-free with no cycle collector.

## Example

```
struct Counter { n: i32 }
function main(): i32 {
    var c: Counter = Counter { n: 0 };
    c.n = c.n + 40;   // error[E048]: cannot assign to field "n"
    return c.n;
}
```

## Fix

Use a functional struct-update: copy the value, overriding
just the fields you want to change. The `...old` base copies
every un-named field; the named fields override.

```
struct Counter { n: i32 }
function main(): i32 {
    var c: Counter = Counter { n: 0 };
    c = Counter { ...c, n: c.n + 40 };   // rebuild, then rebind
    return c.n;
}
```

The same shape replaces "mutate through a function call":
instead of a `void` function that mutates its argument, return
the new value and rebind at the call site.

```
struct Counter { n: i32 }
function bump(c: Counter): Counter {
    return Counter { ...c, n: c.n + 1 };
}
function main(): i32 {
    var c: Counter = Counter { n: 0 };
    c = bump(c);   // rebind, don't mutate-through-call
    return c.n;
}
```

## What is still allowed

- **Local variable reassignment** — `var x = 1; x = 2;` is
  fine; `x` is a binding, not a heap field.
- **Array-element assignment** — `arr[i] = v` routes through a
  copy-on-write path and returns a (possibly fresh) handle, so
  it isn't in-place mutation of an already-shared value.
- **Building recursive values bottom-up** — immutable trees /
  ASTs still construct freely; the rule only bans *post-
  construction* mutation, not recursive types.
