# E069 — a 32-bit value was reinterpreted as a pointer-shaped type

Casting a 32-bit-only integer (`i32` / `u32`) to a pointer-shaped type
(`string`, an array `T[]`, or a struct) with `as` is a **pointer
reinterpret**, not a value conversion — the runtime treats the integer's
bits as an address. But a 32-bit value can only hold 32 bits of an
address, so if the value ever *was* a real pointer it was already
truncated when it became `i32`, and reinterpreting it back recovers a
**corrupt pointer**.

```fern
function bad(k: i32): string {
    return k as string;   // E069: k holds at most 32 bits of an address
}
```

This is latent: on a machine whose heap stays below 4 GiB every address
fits in 32 bits, so the truncation is invisible and the reinterpret
"works" by accident. Once the heap crosses 4 GiB — the arm64-darwin
high-heap case that surfaced this (#5042) — the high 32 bits genuinely
vanish and the program probes the wrong bucket / dereferences a bad
pointer, with no diagnostic. E069 turns the accident into a compile
error.

**The fix** is to carry pointer-shaped values in a `usize` (pointer-width)
local or parameter, which survives the round trip on every target:

```fern
function ok(k: usize): string {
    return k as string;   // usize is pointer-width — no truncation
}
```

A `usize → string` / `usize → T[]` / `usize → Struct` reinterpret is
allowed for exactly this reason (it is how the stdlib promotes a freshly
allocated raw block into a typed handle). Only the narrowing `i32` / `u32`
source is rejected.
