# E057: `Cell[T]` element type is not allowed

A `Cell[T]` is the one mutable cell in the language. To keep the
immutable-data guarantee that makes reference cycles unconstructible (so
Perceus reference counting needs no cycle collector), cells admit only
supported cycle-free elements: a scalar (integer, float or boolean),
`string`, or an owned `u8[]`. Byte arrays contain no references that could
point back to the cell. Their ownership support preserves snapshots across
replacements. See `docs/CELL-TYPE-PLAN.md`.

Other arrays, borrowed views, structs, enums, tuples and nested cells remain
unsupported. Some such types could form cycles; even cycle-free composites
need explicit ownership support before cells can admit them.

## What is rejected

```
struct Node { next: Cell[Node] }   // E057: unsupported element type Node
let c = cell_new([1, 2, 3]);       // E057: unsupported element type i32[]
```

## What is allowed

```
let counter = cell_new(0);         // Cell[i32]
let name = cell_new("anon");       // Cell[string]
let bytes = cell_new([0u8, 255u8]); // Cell[u8[]]
```

## Fixing it

Use `Cell[u8[]]` for shared byte storage. For unsupported composite values,
store a scalar key, index or handle referring to a value held elsewhere.
