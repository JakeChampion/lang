# P001 — Unexpected token (parse error)

The parser found a token where it didn't expect one. This
is the catch-all for the most common parse failures:

- Missing semicolons, parentheses, or braces.
- A keyword in a wrong position (`return` at top level).
- An expression where the grammar needs a statement (or
  vice versa).
- A type annotation that can't be parsed.

## Examples

```
function main(): i32 {
    var x: i32 = 1     // missing `;` → error[P001]: expected ";", got "}"
}

function f() {
    return x +;        // error[P001]: unexpected token ";"
}

function g(): broken { return 0; }   // error[P001]: expected type, got "{"
```

## Fix

Re-read the expression at the indicated position. The error
location is where the parser first noticed something was
off — the actual mistake is often a token or two earlier
(a missing comma, a stray `;`, a mismatched paren).

```
function main(): i32 {
    var x: i32 = 1;
    return x;
}
```

## Why so generic

P001 is the "I expected this, you wrote that" catch-all.
Specific shapes (numeric literal errors → P002, assignment
LHS → P003, etc.) get their own codes; P001 covers the
long tail.

## See also

- P002 (numeric literal error) — for malformed numbers or
  unexpected suffixes.
- P003 (assignment LHS not assignable) — `expr = ...` where
  `expr` isn't a valid target.
- E001 (undefined identifier) — fires AFTER parsing
  succeeds; if the parser can't even build the AST, you
  get P001 instead.
