# E049 — Reference-typed captured variable is read-only

A closure tried to assign to a **reference-typed** variable it
captured from an enclosing scope (`cap = value` inside a
`function (...) { … }`, where `cap` is a string / array / struct /
enum / slice / tuple / closure captured from outside).

This is the capture half of immutability enforcement (the field
half is E048). Banning write-back of a *pointer-shaped* capture
closes the last way to build a reference cycle: a closure whose
environment holds a pointer could be made to point back at a value
that points at the closure. With it gone, reference counting stays
garbage-free with no cycle collector.

## Scalar captures are still mutable

A scalar capture (`i32` / `i64` / `f32` / `f64`) can't hold a
reference, so writing it back can't form a cycle. The stateful
"counter closure" stays legal:

```
function makeCounter(): () => i32 {
    var count: i32 = 0;
    function tick(): i32 {
        count = count + 1;   // OK — scalar capture
        return count;
    }
    return tick;
}
```

## Example (rejected)

```
function main(): i32 {
    var name: string = "a";
    var f = function (): i32 {
        name = "b";          // error[E049]: cannot assign to captured string "name"
        return name.len();
    };
    return f();
}
```

## Fix

Thread the new value through the closure's return and rebind in
the enclosing scope, instead of mutating the reference capture:

```
function main(): i32 {
    var name: string = "a";
    var rename = function (s: string): string { return s + "b"; };
    name = rename(name);
    return name.len();
}
```

## What is still allowed

- **Reading any capture** — only writing a reference capture is
  banned.
- **Scalar capture write-back** — counter closures over `i32` /
  `i64` / `f32` / `f64`.
- **Reassigning the closure's own locals / parameters** — those
  are not captures.
