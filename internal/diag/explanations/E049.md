# E049 — A captured reference is read-only, on both sides

A capture is shared BY REFERENCE: the variable becomes a heap cell
both the closure and the enclosing scope write. E049 guards that
cell from both sides.

**Inside the closure**, assigning a **reference-typed** capture is
rejected outright (`cap = value` inside a `(...) => { … }`, where
`cap` is a string / array / struct / enum / slice / tuple / closure
captured from outside).

**In the enclosing scope**, a store into a captured variable is
rejected when the stored value's type can reach a **function** —
directly, or through an array element, a struct field, an enum
payload, a `Map` value, a tuple element, or opaquely behind `dyn`
or a type parameter. Such a store points the cell at a value that
reaches the closure whose environment holds that same cell, which
is a reference cycle.

This is the capture half of immutability enforcement (the field
half is E048, the element half E056, the `Cell[T]` half E057).
Between them the capture cell is the only mutable heap slot in the
language, so closing it is what makes a reference cycle
unconstructible — which is what lets reference counting stay
garbage-free with no cycle collector.

## Scalar captures are still mutable

A scalar capture (`i32` / `i64` / `f32` / `f64`) can't hold a
reference, so writing it back can't form a cycle. The stateful
"counter closure" stays legal:

```
function makeCounter(): () => i32 {
    var count: i32 = 0;
    function tick(): i32 {
        count = count + 1;   // OK — scalar capture
        return count;
    }
    return tick;
}
```

## Examples (rejected)

```
function main(): i32 {
    var name: string = "a";
    var f = (): i32 => {
        name = "b";          // error[E049]: cannot assign to captured string "name"
        return name.len();
    };
    return f();
}
```

```
function main(): i32 {
    var g: () => i32 = (): i32 => { return 1; };
    var f: () => i32 = (): i32 => { return g(); };   // f's cell for g
    g = f;                   // error[E049]: would close a reference cycle
    return 0;
}
```

## Fix

Thread the new value through the closure's return and rebind in
the enclosing scope, instead of mutating the reference capture:

```
function main(): i32 {
    var name: string = "a";
    var rename = (s: string): string => { return s + "b"; };
    name = rename(name);
    return name.len();
}
```

For the enclosing-scope form, keep the closure in a variable no
closure captures — the cell only closes a cycle when the value
stored into it can reach the closure that holds the cell.

## What is still allowed

- **Reading any capture** — only writing a reference capture is
  banned.
- **Scalar capture write-back** — counter closures over `i32` /
  `i64` / `f32` / `f64`.
- **Reassigning the closure's own locals / parameters** — those
  are not captures.
- **Rebinding a captured variable from the enclosing scope with a
  value that cannot reach a function** — `s = "b"` on a captured
  string, `arr = arr.append(3)` on a captured `i32[]`. That is the
  by-reference capture working as designed; only a value that can
  reach a closure closes a cycle.
- **Rebinding a closure-typed variable no closure captures** — with
  no shared cell there is nothing to close.
- **Storing a fresh closure literal that captures neither the
  variable nor anything holding a closure** — a callback swapped on
  a flag. A closure's only outward edges are its captures, so such a
  literal cannot lead back to the cell.
